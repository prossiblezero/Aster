# Worker 适用范围与剩余边界

更新于 2026-09-28，对应 `src/aster/core/workers.py`。9 月 18 日只读工具并行实验始终关闭 Worker，其读取重叠不能作为多 Agent 收益。历史实验见 [交付修复](../evaluations/worker-handoff-20260925/REPORT.md)、[调查委派迭代](../evaluations/worker-value-20260925/REPORT.md)与[重设计前代码任务基线](../evaluations/worker-code-20260928/REPORT.md)；下述能力需要通过新旧对照实验评价，不能把历史结果算作本次重设计收益。

## 已有能力

Worker 使用独立 Runtime 与历史；`max_workers` 限制同时活跃数，默认关闭。Explore 强制只读，不因任务中的“修复、测试”等关键词产生无法履行的编辑门槛。写 Worker 必须声明非空范围，且同一时间只允许一个写 Worker；父任务在此期间也不能写入或启动进程，可继续只读调查。子任务不能继续派生。

父子共享根 `TaskSpec.max_steps` / `max_turns` 总额度，以及可选的 `max_tokens` 上限。子任务按剩余额度分配，最多 24 个工具步骤、12 次模型调用；为父任务保留总步骤与调用额度的约 20%（至少各 2 次），token 上限也保留约 20%。请求发出前预留估算输入与最大输出，返回后按供应商报告结算；缺失 usage 时保留估算记账。计数持久化在 `RunState.team_usage`，失败、取消及在途请求不会被视为免费；这是请求预算控制，不是供应商美元账单的精确上限。

首轮能力提示说明分工与交付；任务需传递完整问题、目标路径、输出形式和测试责任。局部预算耗尽时会尝试一次无工具交付轮；团队额度不足、服务错误或取消时保存包含已读路径、实际改动、验证状态与停止原因的确定性部分结果。`handoff.json` 的 `delivery` 区分 `complete` / `partial`，不会将额度耗尽标成完成。

已结束子任务的交付在父任务下一次模型请求前自动送达一次。`worker_status` 仍可等待单个 ID 或最多四个 ID，共享 0–300 秒期限；返回工具结果后，不再重复自动通知。界面轮询不算模型已收到结果。外层 `finished` 仅表示选中的子任务都已终止，必须检查每项结果；超时和取消查询均不取消孩子。父检查点保存待交付编号，恢复后补发已落盘结果；没有交付文件时报告中断，不会重启子协程。

已结束子任务可用 `worker_message(..., resume=True)` 在原上下文中补问一次，新增额度最多 8 步/4 轮，仍从团队余额扣除。父权限变化、并发名额用尽或预算不足会拒绝续跑。父任务结束仍清理未完成孩子，没有隐式等待所有交付。

父任务具有严格测试要求时，子任务按实现交付、父任务验证最终工作区。调查结论应保留来源和未核查项；父任务针对具体缺口查证、通过真实接口检查可执行结论。提示不是事实担保：引用路径不等于自动验证了来源，`completed` 不等于独立验收通过。

## 仍未提供的能力

- **独立文件工作区与自动合并**：父子共享真实工作区，写入范围检查不隔离用户编辑器或另一个 Aster 进程。执行依赖按 Runner 隔离，不共享可写依赖根。
- **恢复后台执行与任意往返消息**：进程恢复只补发交付；不复活子任务，补问仅支持当前进程内保存的子 Runtime，且最多一次。
- **自动保证结论正确或交付完整**：无工具收尾和确定性 fallback 保住已有证据，但不会修正模型遗漏、错误引用或未完成的实现。父任务仍须看终态与证据并补救。

会话内模型切换仍要求所有 Worker 空闲。后训练首版继续关闭 Worker；子轨迹信用分配未实现，不宣称支持完整多 Agent GRPO。

保持轻量实现：优先用于能独立调查、交付短结论的任务；单文件小修改可能付出更多交接成本。收益必须结合具体场景、独立正确性与全部父子消耗解释，不把主上下文下降等同总成本下降。
