## 已有能力

2026-10-01 的[18 次证据交付对照](../evaluations/subagent-evidence-20261001/REPORT.md)中，旧并行/新 Solo/新并行严格通过为 3/6、4/6、4/6；新并行比旧并行 token 少 16.3%、耗时少 37.0%，但父方重读仍是 31 次，新并行相对新 Solo 仍需 2.80 倍 token。引用定位搜索减少，格式及行为值错误仍在；完整行为通过未优于旧并行。它支持保留小范围工程修复，尚不支持默认开启自主委派。

Worker 使用独立 Runtime 与历史；`max_workers` 限制同时活跃数，模型自主委派默认关闭；用户可从 TUI「子任务」面板显式派发最多两个只读调查/审查任务，无需更改配置。Explore 强制只读，不因任务中的“修复、测试”等关键词产生无法履行的编辑门槛。写 Worker 必须声明非空范围，且同一时间只允许一个写 Worker；父任务在此期间也不能写入或启动进程，可继续只读调查。子任务不能继续派生。

父子共享根 `TaskSpec.max_steps` / `max_turns` 总额度，以及可选的 `max_tokens` 上限。子任务按扣除父方保留量后的余额与并发上限分配局部额度；为父任务保留总步骤与调用额度的约 20%（至少各 2 次），token 至少保留约 20%，父任务已有请求估计时取它与两次父请求估计的较大值。余额连该保留量加一次最大输出都无法容纳时，不再启动子任务。直接 API 尚未构造父请求时退回 20%；切换运行清除旧估计。请求发出前预留估算输入与最大输出，返回后按供应商报告结算；缺失 usage 时保留估算记账。计数持久化在 `RunState.team_usage`，失败、取消及在途请求不会被视为免费；这是请求预算控制，不是供应商美元账单的精确上限。

首轮能力提示说明分工与交付；子任务自动收到初始 `TaskSpec.prompt` 及当前分支最近的用户请求（最新要求优先），父任务补充局部目标、已知事实、输出形式和测试责任，并用可选 `parent_work` 声明自己负责的独立工作。双方收到分工，记录随父检查点保存；这仍是协调提示，不是无重复工作的保证。局部预算耗尽时会尝试一次无工具交付轮；团队额度不足、服务错误或取消时保存包含已读路径、实际改动、验证状态与停止原因的确定性部分结果。`handoff.json` 的 `delivery` 区分 `complete` / `partial`，不会将额度耗尽标成完成。

分工提示要求父方先完成 `parent_work`，除非具体依赖阻塞自己的工作，否则不在孩子交付前重做委派包；交付后按证据中的缺口或矛盾复核。加载目录只列尚未暴露的可用工具，空目录时隐藏 `tool_load`。这不限制父方必要的来源核验，也不改变直接工具调用的权限检查。

当本职仅剩独立取证请求且返回后即可整合时，提示允许将带等待的 `worker_status` 放在同批请求末尾；依赖先前输出的操作仍分轮。混合批次按现有顺序执行，不扩权限，也不保证期限内完成；仍须检查返回状态。精确行为值应在权限和依赖允许时通过已检查实现执行请求表达式，保留初始状态和输出表示；执行不可用时报告静态结论与缺口。

当前分支已有子会话时，`worker_status` 直接出现在父方工具定义中，无须先用 `tool_load` 加载；恢复子会话引用后同样可用。`max_workers>0` 时，`worker_start` 也直接可见；其余管理工具继续按需加载。已结束子任务的交付在父任务下一次模型请求前自动送达一次。`worker_status` 可等待单个 ID 或最多四个 ID，共享 0–300 秒期限；默认 `wait_for="any"` 在任一新结果可用时返回全部选中任务的快照，未消费交付立即返回，已消费结果不再结束后续等待。父方只剩最终整合时可显式用 `wait_for="all"` 等所有选中任务终止或到达共同期限；已有未消费结果不会提前结束这种等待。还有独立工作时先继续做，首份交付能解锁后续工作时保留 any。`wait_seconds=0` 在两种模式下均立即返回；单个 ID 两种模式相同。界面轮询不算模型已收到结果。外层 `finished` 仅表示选中的子任务都已终止，必须检查每项结果；超时和取消查询均不取消孩子。父检查点保存待交付编号，恢复后补发已落盘结果；通过工具读过的保存结果也不会重复通知，没有交付文件时报告中断，不会重启子协程。

模型收到的通知和状态工具正文以 `read_paths` 代替完整的 `read_evidence` 哈希表；答案、所选源码和版本、过期路径、错误及验证状态保留。界面、原始工具返回和持久化证据仍保存完整结构，精简仅发生在模型输入边界。

子任务首轮可见专用 `worker_finish(answer, sources)`，同一调用交付答案与最多四段支撑结论的源码，正文总计不超过 8,000 字符。每段选择 `evidence_id/start/end/claim`，其中 `evidence_id` 可复制子任务 `read_file` 输出的 12 位 `source_ref` 或完整 ID。短引用只在当前子分支授权的读取中唯一匹配，再还原完整 ID；歧义时须使用完整 ID，不会模糊纠正写错的长 ID。原文由运行时从既有读取事件提取，可以选同一文件的多个行段及较早的读取。来源必须属于该子分支、范围已经读过且当前文件哈希和内容一致。反馈分别说明未知或歧义引用、可用行段、过期来源，以及超过 8,000 字符时的总量和各段大小。正常完成仍通过原有 Final 检查，每次交付消耗一个正常工具额度，无须再请求模型重述答案。JSON 对象答案由程序序列化，这不验证内容正确，也不替代父方的输出契约。

原始交付的 `source_excerpts` 携带结论标识、实际行段、完整证据 ID、文件哈希与截断标记。父模型的展示副本省略摘录的 ID 和哈希，并在正文逐行标出真实行号；磁盘交付、快照、界面及直接状态 API 保留原文和完整元数据。父模型收到与当前文件匹配的摘录后满足观察门槛；它不获得文件编辑凭证或父方正式测试通过状态。仅摘要、仅哈希、过期或缺失摘录不能获得这项观察认定。读取授权和选中正文随子快照保存，旧分支不能通过复用工具调用 ID 引用未来轨迹。继续新任务时清除旧的交付选择，历史读取仅在当前内容匹配时可再次选择。旧版或没有选择来源的文本交付继续回退原工作记忆的最多四个 500 字符摘录；预算耗尽仍使用既有无工具的部分交付。read_file 的模型输出显示真实行号，原始文件工具正文保持不变。

已结束子任务可用 `worker_message(..., resume=True)` 在原上下文中继续交流，局部额度重新分配，仍从团队余额扣除。父检查点通过不可变 `entry_id` 保存当前分支的子会话历史；旧父分支只见当时的消息与观察。重启后可查看，显式补问才从对应快照恢复子历史并创建新的执行记录，未确认的工具效果会阻止恢复。快照缺失时明确报告不可用，不回退到最新子状态；冷恢复面板只展示已保存的结果与读取证据，不读取持续增长的最近工具轨迹。父权限变化、并发名额用尽或预算不足会拒绝续跑，token 不足的续问不会改写旧子快照。所有活跃子任务均让过早的 Final 返回等待反馈；请求期间新到的交付也要先进入后续观察。显式取消和总预算耗尽仍会清理全部孩子，不会隐式无限等待。

父任务具有严格测试要求时，子任务按实现交付、父任务验证最终工作区。调查结论应保留来源和未核查项；父任务针对具体缺口查证、通过真实接口检查可执行结论。提示不是事实担保：引用路径不等于自动验证了来源，`completed` 不等于独立验收通过。

多个独立结果的请求可用现有 `todo_add.acceptance` 记录验收条件，Solo 也支持。`worker_start.todo_id` 绑定其中一项，启动后记录子运行与负责人；启动被拒绝不改变待办。完整或部分交付都会把事项返回父任务待验收，只有父任务 `todo_update` 附上 `resolution` 才能关闭。绑定运行期间不能直接关闭或抢占这项待办；需要先等待或停止子任务。旧版不带这些可选字段的工具调用仍兼容。

带验收条件的未处理事项阻止严格完成；本次请求取消的事项会出现在最终答复中，最多标为 `completed_with_warning`，不能成为独立的通过证据。同一任务恢复继续保留该警告，新用户请求不继承历史取消警告。状态、交付关联和验收说明随原检查点保存，旧交付不能覆盖后一次重新分派；续聊将无法复活的运行归属退回待处理。`resolution` 和 `done` 仍是父模型的判断，运行时不能保证其语义正确，也不能发现模型从未列出的需求，必须结合独立评分。

## 仍未提供的能力

- **独立文件工作区与自动合并**：父子共享真实工作区，写入范围检查不隔离用户编辑器或另一个 Aster 进程。执行依赖按 Runner 隔离，不共享可写依赖根。
- **自动恢复后台执行**：进程恢复只查看与补发交付；只有明确补问才加载子会话。不会重放效果不确定的工具，也不提供无限额度的后台守护任务。
- **自动保证结论正确或交付完整**：无工具收尾和确定性 fallback 保住已有证据，但不会修正模型遗漏、错误引用或未完成的实现。父任务仍须看终态与证据并补救。

会话内模型切换仍要求所有 Worker 空闲。后训练首版继续关闭 Worker；子轨迹信用分配未实现，不宣称支持完整多 Agent GRPO。
