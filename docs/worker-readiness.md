# Worker 适用范围与剩余边界

更新于 2026-09-25，对应 `src/aster/core/workers.py`。9 月 18 日只读工具并行实验始终关闭 Worker，其读取重叠不能作为多 Agent 收益；后续独立实验见 [交付修复](../evaluations/worker-handoff-20260925/REPORT.md)与[调查委派迭代](../evaluations/worker-value-20260925/REPORT.md)。

## 已有能力

Worker 使用独立 Runtime、历史与 12 步/12 轮预算；`max_workers` 限制同时活跃数，默认关闭。Explore 强制只读，不因任务中的“修复、测试”等关键词产生无法履行的编辑门槛。写 Worker 必须声明范围，活动写 Worker 范围不可重叠；子任务不能继续派生。

首轮能力提示说明分工与交付；任务需传递完整问题、目标路径、输出形式和测试责任。`worker_status` 兼容单个 ID，也能一次等待最多四个 ID，共享 0–300 秒期限。外层 `finished` 仅表示选中的子任务都已终止，必须检查每项结果；超时和取消查询均不取消孩子。父任务结束仍清理未完成孩子，没有隐式等待所有交付。

父任务具有严格测试要求时，子任务按实现交付、父任务验证最终工作区。调查结论应保留来源和未核查项；父任务针对具体缺口查证、通过真实接口检查可执行结论。提示不是事实担保：引用路径不等于自动验证了来源，`completed` 不等于独立验收通过。

## 仍未提供的能力

- **产品级全团队总预算**：每个运行仍有独立预算；已完成 Worker 释放名额，不能把并发上限当累计调用或金额上限。本轮评测额外使用全树请求/动作/已报告 token/墙钟账本，包含失败与取消，并核对 usage 覆盖率；它不是已集成的生产预算器。已报告 token 限额也不对并发在途请求作精确预留。
- **独立文件工作区与自动合并**：父子共享真实工作区，写入范围检查不隔离用户编辑器或另一个 Aster 进程。执行依赖按 Runner 隔离，不共享可写依赖根。
- **自动保证交付完整性**：子任务可能耗尽额度、遗漏字段、引用错误或遇到服务故障。父任务须看终态与证据并补救，整组等待不会自动修正答案。

会话内模型切换仍要求所有 Worker 空闲。后训练首版继续关闭 Worker；共享预算与子轨迹信用分配未完成，不宣称支持完整多 Agent GRPO。

保持轻量实现：优先用于能独立调查、交付短结论的任务；单文件小修改可能付出更多交接成本。收益必须结合具体场景、独立正确性与全部父子消耗解释，不把主上下文下降等同总成本下降。
