# Worker 扩展评估

2026-09-18，依据 `src/aster/workers.py` 与 Runtime 生命周期审查。本轮只读工具并行的真实对照始终关闭 Worker；读取重叠及端到端结果不能作为多 Agent 收益。

当前 Worker 保留独立 Runtime、历史与 12 步/12 轮预算；`max_workers` 限制同时存活数。explore 只读，写 Worker 必须声明范围且活动 Worker 范围不能重叠；不允许递归创建 Worker。它们共用真实工作区，父任务结束会取消未完成 Worker，没有自动等待全部子任务交付的承诺。

暂不扩展并发数量。先补以下接口后才值得做独立收益对照：

1. 根任务持有共享的动作、模型输入/输出 token 和墙钟预算。创建及请求前预留，失败、重试、取消均结算；不能靠不断新建已完成 Worker 绕过总额。
2. 父子用量按 run ID 汇总并保留缺失覆盖率，根汇总不重复计入子汇总；来源记录关联委派请求、子回复和候选变化。
3. 明确 join/取消/失败策略及用户可见状态。父任务声明完成之前等待已授权必需子任务或明确取消，取消后不发布迟到写入。
4. 在新任务上冻结单 Agent 与 Worker 配置，固定模型、预算、Memory/Skills/流式/读并行，比较独立验收、总用量、墙钟和冲突。各自正常路径及人工介入分开记录。

会话内模型切换仍要求所有 Worker 空闲。新增执行依赖复用按 Runner 隔离，不让多个 Worker 共用可写依赖根；跨 Worker 依赖共享、独立 worktree 与合并属于后续设计，不由本次读工具线程并行隐含提供。

后训练首版继续关闭 Worker。共享预算和子轨迹信用分配未完成前，不采集委派训练数据，也不宣称支持完整多 Agent GRPO。
