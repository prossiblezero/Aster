# Aster：轻量级 Coding Agent

**核心技术：** Python、Agent Harness、Tool Calling、MCP、Context Management、Checkpoint / Resume、Layered Memory、Memory Consolidation、Run Trace。

**项目描述：** 面向代码仓库中的功能开发与问题修复，针对多轮任务中上下文膨胀、重复读取文件、中断后状态丢失，以及项目约定和修复经验难以跨会话保留的问题，开发轻量级本地 Coding Agent Harness。以统一 Runtime 串联模型接入、工具执行、上下文管理、分层记忆和任务恢复，结合权限控制与结果验证，支持 Agent 在本地完成代码修改和测试，并保留可追溯的执行记录；通过后台知识整理与使用反馈，让任务经验持续用于后续开发。

**核心贡献：**

1. **Agent Harness 架构与编排。** 设计统一 Runtime，将模型接入、上下文构建、工具调度、会话状态和完成校验串联为可恢复的运行循环，CLI/TUI 共用同一执行内核。适配 OpenAI Responses、Chat Completions 和 Anthropic Messages，统一处理权限检查、预算限制及限流、过载等临时故障，保存 Checkpoint、执行轨迹和验证结果，支持任务续跑与问题复盘。通过 MCP 接入 GitHub 和自研文件管理服务，支持工具动态发现、按需加载，并沿用 Runtime 的权限校验与执行记录。基于 SWE-bench Verified、Terminal-Bench 和 Aider Polyglot 构建 **20 题开发评测子集**，覆盖仓库修复、终端编码与小型实现；历史迭代版本固定模型及运行预算，每题一次完整复测，独立验收通过率达 **75%（15/20）**。
2. **记忆与自进化。** 让 Agent 从对话、代码和测试结果中自动提炼项目约定与修复经验，以本地 JSON 保存知识、出处和适用条件。通过 asyncio 在后台整理，支持用户纠正、过期停用，并根据使用反馈调整召回顺序；保存成功后向用户展示学习结果。在前期知识版本的 **10 道跨会话任务对照**中，后续任务完成率由 **40% 提升至 70%**。
3. **上下文管理。** 按预算裁剪历史消息和工具输出，保持工具调用与结果配对，将移出的内容归档并支持按需读回。在 12 道预置长历史的代码题中，首次输入长度按本地 token 估算平均减少 **57.8%**，选定预算后 **36 次运行全部完成任务**。
4. **运行成本优化。** 让临时测试随工具调用执行，减少测试准备中的工具往返；跳过内容未变的重复记忆材料，并在任务收尾保留工具定义，减少不必要的请求前缀变化。在 **10 道跨会话任务、48 个会话**的内部新旧版本对照中，相对 Aster 优化前版本，后续任务的已报告 token 减少 **45.9%**；计入学习和后台整理后，总量减少 **39.9%**。
5. **会话管理与任务恢复。** 用 SQLite 保存会话树与恢复位置，支持随时追问、会话分支、断点续跑和多会话后台执行，恢复前检查文件变化，检测重复调用和失败循环。为 MCP 调用增加持久化幂等记录、端点熔断和备用切换，阻止结果不确定的写操作重放。在六类固定会话工作流的离线对照中，操作数由 **69 降至 36，减少 47.8%**。
6. **执行隔离与结果验证。** 使用 Linux 沙箱和路径权限限制工具操作，持续保留结构化测试报告中的失败，避免测试受阻或局部通过后遗漏回归；只有对应失败重新测试通过，才解除交付限制。在全跳过、伪造输出、提前退出等 **25 个异常或无效验证场景中，均未误判为通过**。

## 面试时解释数字（备查，不放简历正文）

MCP 的实现见 [接入与可靠性说明](mcp.md)，实测见 [2026-10-13 指标报告](../evaluations/mcp-metrics-20261013/REPORT.md)：GitHub 与文件服务共 14 项工具，按需加载的首轮 Schema 估算 token 减少 69.3%，但 32 次真实模型运行中，两组任务成功率均为 13/16，按需加载的整任务已报告 token 增加 18.9%、平均耗时增加 38.0%，不能将 Schema 缩减写成整体降本。10 次独立文件写入的同会话及恢复后重放共 20/20 返回已有结果，10/10 次参数冲突被阻止，未观察到重复文件副作用；不代表分布式 exactly-once。备用切换与熔断有本地服务测试覆盖，本次未测真实备用服务。

当前生产源码已于 2026-10-12 回退至 `c6b651d`，对应最早包含五题故障补测的 15/20。下文单次完整复测的 15/20 是后续迭代版本的历史成绩，不应与回退版本混称；本轮未证明降本收益。[最终修复与回退记录](../evaluations/final-repair-20261012/REPORT.md)。

最新完整复测见 [2026-10-11—12 上下文成本优化](../evaluations/general-coding-cost-20261011/REPORT.md)：固定原二十题、`gpt-5.6-luna` / medium、每题 900 秒，每题一次全新尝试，独立通过及正常交付且通过均为 **15/20（75%）**；仓库 **7/12**、终端 **6/6**、小型实现 **2/2**。解释器新增通过，Requests 2931 新增回归；内部完成 19 题中有 4 题独立失败，另有一次超时。相对上一版，请求 **405→349（−13.8%）**、未缓存输入 **−8.4%**，但总 token **8,369,416→9,148,018（+9.3%）**、累计耗时 **+27.4%**。六组费用权重估算仅下降 **0.7%–4.7%**，共同通过 14 题的费用权重均上升，且本轮有 6 次缺失回执，不能宣传为普遍降本或真实账单下降。pi/Codex 沿用历史 **15/20、14/20**，本轮未超过 pi，消耗仍高于两者。三题两版 pilot 与完整复测共 26 次尝试、13,395,171 已报告 tokens，单列而不择优拼分。正文第四条仍引用独立的十题跨会话新旧版本实验，不表示 Aster 的通用 benchmark 成本低于其他 Agent。

此前两版完整复测见 [2026-10-11 优化结果](../evaluations/general-coding-optimized-v2-20261011/REPORT.md)：基于 `c6b651d` 加冻结补丁，沿用三来源 20 题、`gpt-5.6-luna` / medium、每题 900 秒，各题一次全新尝试。第一版为 **14/20（70%）**，第二版为 **15/20（75%）**，没有挑选旧轮最好结果；第二版正常交付且独立通过也是 **15/20**，仓库 **8/12**、终端 **5/6**、小型实现 **2/2**。pi、Codex 固定历史成绩为 **15/20、14/20**，本轮未超过 pi。第二版内部完成 18 题中仍有 3 题独立失败，另有 1 次超时和 1 次停滞退出；第一版与第二版共 40 次正式尝试，已报告 16,746,634 tokens、18 次请求缺失用量，另有一次健康探测 4,395 tokens。生产修正临时目录隔离和重试退避、加强通用验收指引，同时保留解释器、源码导入、原始跟踪夹具和容器权限/服务生命周期适配。完整工程测试 1231 通过、4 跳过。题目已用于诊断和优化，简历明确写开发子集；上述数字不能解释为未见测试集、完整榜单、稳定排名或单项优化的因果收益。

此前故障补测合并成绩见[纳入补测后的对比](../evaluations/general-coding-retry-20261010/combined/REPORT.md)：当时冻结 `c6b651d`，20 题＝12 道 SWE-bench Verified 仓库修复＋6 道 Terminal-Bench 归档终端编码＋2 道 Aider Polyglot Python 实现；三者同模型 `gpt-5.6-luna`，每次尝试 900 秒。原始 60 次单次运行中 Aster 为 **12/20（60%）**；将其五题重跑结果全部替换后为 **15/20（75%）**，pi、Codex 沿用原始 **15/20（75%）**、**14/20（70%）**。Aster 实际尝试 25 次，另外两者各 20 次。新增通过 C++、COBOL、gRPC；gRPC 使用持久进程环境适配，pytest 也适配了导入环境，不能将 75% 写成严格同条件单次通过率。仓库部分均为 **8/12**；合并后 17 道本项目新增题上分别为 13/17、12/17、13/17，历史题分别为 2/3、3/3、1/3。没有按子 Agent 可拆分性选题，也没有强行保留旧 26 题。终端和 Aider 使用本地适配环境，不能写成原 benchmark 完整榜单成绩。

原始单次运行保留了全部超时和供应商故障，Codex gRPC 还受到登录 shell 重置 PATH 的影响，不能据小样本宣称稳定排名。原始 Aster 内部完成 17/20，其中 5 题独立评分失败；合并记录中内部仍完成 17/20，其中 3 题独立失败。C++ 补测虽独立通过，但内部验收未完成，因此合并后“正常交付且独立通过”为 **14/20**。原始 7 次运行触发过验收返修，不等于证明优化提高了得分。Aster 原始已报告总 token 8,350,325，加补测 1,715,963 后累计 **10,066,288**；pi 为 6,527,449，Codex 为 6,528,266。累计缺失用量分别为 19、7、9 次请求。没有改动前同条件对照，不将合并成绩变化写成验收优化收益。

另用 SWE-bench Verified 的十题固定开发子集（简单／中等／困难＝3／5／2）做了官方 Docker 评分：[2026-10-09 试验版](../evaluations/swebench-review-20261009/REPORT.md)为 **2/10**，与上一版持平；pi、Codex 的历史结果各为 3/10，本轮未重跑。自动追加补丁复核没有显示足够收益，最终移除；随后补齐的断流重试只做本地回归。这里验证了评分链路并暴露了修复范围遗漏，不能写成榜单排名、能力提升或最终交付版本的新成绩。

正文第四条的跨会话降耗数字来自 [2026-10-07 十题对照](../evaluations/memory-cost-20261007/REPORT.md)：两版各 24 个会话，所有成功、失败与未完成尝试都计入已报告用量，模型仍自动学习。正常完成且通过均为 9/10，但功能断言 30/30 → 27/30；CSV 约定遗漏修正后只做单题补查，3/3 通过，不拼成十题 10/10。供应商单价未知，基线 2 次、新版 3 次尝试缺少用量，因此写 token 降幅，不写账单降幅或“质量全面不下降”。源码、实验范围和原始失败都在报告中。

记忆部分的 40% → 70% 来自 2026-10-05 的前期知识提炼对照，该批次的后续任务 token 减少 11.7%。2026-10-06 新增自动学习后，另一组实验的已报告总 token 曾增加 12.6%、后续增加 20.0%，没有把这次增加隐去；这正是后续降耗的起点，见[自动学习实验](../evaluations/memory-sleep-20261005/REPORT.md)。三个批次不能混算。

前期知识对照的统计说明：十题是已用于开发的内部任务，每题每版本运行一次。“完成”要求后续任务正常交付并通过全部验收检查；学习和后续任务均完成时为 **4/10 → 6/10**。11.7% 与 10.2% 统计全部后续任务的尝试（含失败），不含首次学习和提取，也不等于实际费用的降幅。

前期两组都启用记忆、自进化与 Dream。主对照使用核心知识改造版；错误经验记录另作案例补查，最后的来源检查修正与默认开启调整只做相关回归，没有重新测量前期指标。实验仍有口头承诺记住却未保存的失败；支付案例中原代码也可读，不能单凭该例断言成功由记忆造成。这些前期结果不代表稳定的自主学习能力、总成本下降或公开 benchmark 成绩。参见[完整结果与证据](../evaluations/memory-knowledge-20261005/REPORT.md)。

v4 批次的唯一失败是关闭长期记忆的 `memory_steps`：模型未读文件，猜测 16，正确值为 17。另有两次命令缺少结尾引号被拒、六次编辑前缺少最新读取被拒，后续均完成任务。这些结果保留，不用最好看的批次覆盖失败。工具次数包含定位、读取、修改、测试和差异检查，不等于回答同一问题的重试次数。

v4 的 58 次真实尝试中，205 次上下文构建均未触发历史裁剪，输入预算为 21,952；因此这批成绩不能证明紧预算下的任务能力。v5 已另做三档预算对照和真实模型恢复对照，结果按批次独立保留，不把不同开关和不同预算合并成重复采样成绩。

模型接入通过 HTTPX 适配 OpenAI Responses / Chat Completions 与 Anthropic Messages API，未依赖两家的官方 Python SDK。真实连接只评测了 Responses；Chat、Anthropic 通过协议契约测试。asyncio 是 Python 标准库，用于异步模型请求与后台记忆整理；Pydantic 是第三方数据校验库，用于工具参数、运行状态和记忆候选的数据约束。终端交互界面使用 Textual（Python 的 TUI 框架），简历核心技术行突出 Harness 编排、上下文、记忆和恢复机制。Memory Consolidation 对应知识提炼与后台整理，Run Trace 对应执行轨迹记录。内建测试验证支持 Python 与 Node.js，其他测试框架需要对应验证器。隐藏评分与候选同 Python 解释器，不宣称完全抗恶意候选篡改。
