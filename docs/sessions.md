# 会话、对话与分支

一个会话可以包含多次用户请求；一次用户请求及其处理、回答称为一次对话。持久化以有父指针的类型化记录树表示，对话只是记录的分组。`RunState.turn` 为兼容训练及现有调用者，仍表示模型迭代次数；记录中的 `turn_id` / checkpoint 的 `dialogue_id` 才表示用户对话。无新用户输入的续跑沿用对话编号。

## 使用

无需记忆命令也能管理会话：

- 顶部「新建」打开目录输入框，默认使用当前目录，可填写另一个目录或已有 worktree。「会话」打开可筛选的列表，点击条目即可切换。「取消」只取消当前会话。
- 每次对话的稳定位置后显示「从此分支」「带入摘录」。点击较早对话的入口，会恢复该位置；继续输入会产生新路径，已有后续内容仍可在「历史」里找到。当前会话工作时须先等它完成或取消，才能切换该会话的分支。
- 「历史」展示可恢复位置，包括过程中的完整工具批次边界。输入关键词筛选，点击条目，或选中后点击「选择」「带入摘录」；可用「返回」关闭。清屏或旧内容超过终端滚动上限时，仍能通过这里搜索历史位置。
- 宽度至少 110 列时左侧常驻已打开会话列表，支持点击切换；更窄时保留顶部状态汇总与「会话」按钮。列表区分「就绪」「工作中」「等待确认／回答」「已完成」「已取消」「已停止」「失败」「待输入」。工作状态由当前进程的真实任务决定；未加载的历史运行即使存档为 running，也只显示「待恢复」。
- 后台完成会更新侧栏和已打开的会话弹窗，刷新时保留筛选与选中条目。重启后打开历史会话，会沿选中路径重建原始对话和分支入口；界面展示原记录，不改变压缩后的模型上下文。
- `Ctrl+O` / `Ctrl+T` 分别打开会话／历史，按钮可用 Tab 聚焦、Enter 激活；命令入口仍保留。

- `/sessions [关键词]` 打开会话选择器，搜索后 Enter 选择；`/rename 名称` 给当前会话命名。
- `/tree [关键词]` 打开当前会话的可恢复位置。◇ 是完整工具批次后的稳定位置，● 是当前点；搜索后 Enter 选择，Ctrl+S 选择并带入离开分支的摘录。原有后续历史保留，发送新请求会形成另一条路径。
- `/branch 位置ID [--summary] [--adopt-workspace]` 是相同操作的命令入口。编号支持无歧义前缀。`/entry 记录ID` 可查看记录和来源。
- `/new [目录]` 打开独立会话，`/switch 序号或会话ID` 切换。不同工作目录或已有 worktree 的会话可同时运行，取消只针对前台任务；退出会取消所有打开的任务并保存已完成的步骤。
- `/history`、`/resume`、`/continue` 保留原有行为。`/resume` 会立即续跑；树导航只选择历史位置，不调用模型。

树导航恢复历史、模型配置及计划等状态，**不回滚工作区文件**。文件有变化时默认拒绝；点击操作会显示确认框，只有选择「保留文件并继续」，或在命令中明确加 `--adopt-workspace`，才采用当前文件，并清除旧文件读取授权与测试证明。需要比较代码版本时，请自行选择对应 worktree / 工作目录。相同目录内的独立会话不能同时执行任务，底层文件锁也约束另一个 Aster 进程；显式 Worker 仍使用原来的父任务作用域规则。

带入分支摘录是用户显式操作。当前采用确定性摘录，保留来源位置，最多 12,000 字符，单条最多 2,000 字符，界面上下文标明截短。它没有模型概括能力，不是长期记忆，也不会给目标分支授权读取来源分支的全部工具归档。已有长期记忆仍遵循成功文件摘录的准入要求；同一目录的独立会话执行前会在工作区锁内刷新持久记忆，防止闲置实例覆盖后来保存的内容；不同目录的记忆不会自动共享。

## 持久化与兼容

`.aster/sessions.sqlite3` 使用 SQLite 事务保存不可变记录及恢复点。记录类型包括 `turn_start`、`message`、`model_change`、`compaction`、`context_transform`、`branch`、`branch_summary`、`checkpoint`、`legacy_import`。父指针决定有效路径；压缩记录提供替换历史，旧记录不删除。恢复点保存运行状态、配置、文件指纹和该时刻可访问的观察归档清单；用户不能选择半个工具批次。

JSON checkpoint 仍按版本 2 导出，并兼容版本 1。SQLite 先提交，JSON 后导出；若导出失败，树中已提交的位置仍可恢复。旧版、或仅复制 JSON checkpoint 的用户，可用 `/resume` 恢复，后续执行会导入会话树；导入不能找回旧版本已经覆盖或丢弃的历史。已有数据库时，原生协议中的受保护推理元数据按现有脱敏规则保存。

模型恢复从当前配置的具名 profile 解析端点和凭证，不相信历史文件中的地址或密钥。同一 Runtime 可恢复其启动默认模型；跨进程找不到历史 profile 或权限配置变化时会拒绝。需要主动改变模型的旧 checkpoint 使用原有 `/resume --allow-model-change`。

记录头更新采用乐观并发检查，过期写入不会覆盖另一个使用者的新历史。工具执行中的不确定副作用继续沿用 `inflight.json` 拒绝恢复规则，不会因为选择树位置而重放。

回退代码时可继续使用导出的 JSON checkpoint；旧代码忽略新增字段。保留 SQLite 数据库，旧代码无法维护新树，回退期间产生的记录需要再次通过旧 checkpoint 导入，不能宣称无损双向同步。

## 验证与评测

`tests/test_session_tree.py` 验证隔离、压缩、模型恢复、归档授权、故障和旧数据；`tests/test_session_navigation_ui.py` 验证交互选择、后台运行、取消和草稿；`tests/test_session_click_ui.py` 用真实鼠标事件验证旧对话分支、显式摘录、重启后入口、文件采用确认、后台状态更新、点击取消和小终端布局。评测会区分脚本操作路径、本地延迟和真人使用体验，不用自动化耗时替代人工定位时间。已有操作评测是命令流程的历史结果，不作为鼠标交互的人效结论。

设计参考 pi 的类型化记录树和显式分支摘要（调研版本 `19451accdeec671c1f4da9eafac8fc270f510ef4`），以及 Codex 的对话生命周期与执行配置记录（`5c5308fc9a9ee789049d646ef11e5400384b9c6f`）。Aster 保留自身 checkpoint、执行证据和训练契约，不复制其他项目的存储格式。


历史实验的设计取舍与证据边界见[优化历程](optimization-history.md)；已公开的报告与原始数据见[指标证据](evaluation-results.md)。
