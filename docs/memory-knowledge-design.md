# Aster：从摘录记忆到有出处的知识

历史阶段记录：2026-10-05。该阶段已完成，下面保留当时实现与冻结实验；2026-10-06 的自动提炼和异步整理见[后续设计与交付](agent-next-optimization.md)。

目标是让轻量 Agent 跨会话记住约定、吸收纠正、复用方法，在两天范围内完成改进和十题对比。来源的选择依据具体机制与 Aster 的缺口；以下包含既有研究、新近修订和产品实现参考，不把重新阅读旧材料当作研究创新，也不声称完成了所有 2026 memory 论文的综述。

交付后的默认策略调整：按用户对开箱即用的要求，`memory_enabled`、`memory_evolution`、`auto_dream` 均改为默认开启。普通用户直接启动即可使用；已有明确的关闭配置仍生效。下述冻结对照本就显式开启这三个选项，实验数据与归档不因默认值调整而改写。

## 与已有实现的差异

| 已有能力（本轮前） | 本轮新增或修正 |
|---|---|
| 文件原文摘录、出处与整文件哈希 | 保留摘录；加入事实与方法的知识提炼，允许真实用户请求和执行结果作为来源 |
| `memory_store/update/discard` 工具 | 扩展其准入规则和适用条件，纠正可以直接替换旧知识 |
| 正文与标签的词面检索 | 同时匹配适用条件，展示条目 ID 以便明确反馈 |
| 使用结果排序、Dream 失效停用 | 仅反馈给实际应用并检验的记忆，避免所有召回条目连带奖惩 |
| 主 Agent 可主动调用记忆工具 | 执行失败后测试通过时，提供一次有界的修复经验提炼机会，可判断跳过 |
| 工作记忆、本地 JSON、快照与回滚 | 继续复用；本轮没有重新实现这些能力 |

| [VERSE](https://arxiv.org/abs/2610.02616)，2026-10 arXiv 预印本；已读全文 | 在可验证任务上演化 agent harness，分开优化与评估；验证预算本身也有成本 | 使用执行断言而非自我宣称成功，不引入自动改写 Aster 源码的优化循环 |
| [SEARL](https://aclanthology.org/2026.acl-long.1125/)，ACL 2026；核对官方条目与摘要 | 结合工具图记忆和策略优化 | 作为更重路线的参照；本轮不实现工具图策略训练，也不据摘要声称复现细节 |

PlugMem 的信息密度指标很有启发，但其定义涉及决策效用与注入记忆量，不能直接替代所有模型请求的计费 token。本轮选择能从 trace、代码结果和供应商 usage 直接复算的指标。

## 设计取舍

推荐先打通“有来源的知识提炼 + 适用范围 + 用户纠正 + 使用反馈”这一条主线，复用 Aster 的本地记忆、事件记录、检索和 Dream。当前只允许原文摘录，限制了用户口头约定与执行经验的保存；优先解决这个已确认的缺口。

最小选项是仅修复反馈归属，继续保存原文摘录，工作量最小，但仍无法直接承接用户纠正与方法归纳。另一条可选路线是在本地 JSON 中引入概念关系与轻量知识图；图结构本身不必依赖新数据库，但需要额外定义关系提取、更新和检索逻辑。现有少量记忆尚无证据显示多跳检索是主要瓶颈，因此本轮优先选择知识条目；若后续任务显示主要失败来自概念关联缺失，再考虑图关系。

最脆弱的假设是主 Agent 能提炼出值得保存、范围正确的知识。早期实验中，模型把“本轮不实现 report.py”混入长期条目。因此按需加载的写入说明要求只提取长期规则，并补充中英文暂态检查及可修正的拒绝反馈。这仍不是通用语义判定器，来源认证无法替代内容质量判断。

对 WorkBuddy 体验的判断是选择性纳入：有复用价值的是项目特有的原因、修复与适用条件，逐条保存手误或给每次回复追加复盘会制造噪声。旧版支付修复案例已经能保存修复后的代码原文；本轮应补的是知识提炼和合适时机，而不是另建一套学习系统。因此只在真实执行失败后测试通过时提示一次，由主 Agent 判断是否保存，允许无操作，不作为完成硬门槛、不自动生成 skills。额外成本限于该次提示及模型选择的写入工具调用，仍须计入端到端成本。

十题运行中也观察到“最终声称已记住，但没有实际调用记忆工具”的缺陷，因此最后的提示修正明确用户知识的调用方式和真实保存要求。这是行为引导，不是对自然语言作出持久化保证的解析器。

支付题进一步表明：用 `fact` / `procedure` 分类决定能否引用执行证据，会把合理的规则归纳拒之门外，消耗重试预算。最终实现让两者共享派生知识的来源准入，类型用于组织内容；保留适用条件、全部文件哈希和真实事件认证。错误反馈也直接提示重新读取已变更文件、去除摘录行号或选择派生知识，减少无指引的重试。该末轮修正只做相关契约回归，未追加第三轮模型比较。

交付范围限定为下列五个生产源码文件中的知识准入、调用接口、提示与反馈连接，以及必要的测试、文档和十题结果；不需要新增服务、依赖、密钥或配置项。效果以一次固定任务对比为准，不能保证所有指标都会改善。

## 实现

涉及 `knowledge/memory.py`、`tools/schemas.py`、`tools/workflow.py`、`core/runtime.py`、`context/prompt.py` 五个生产源码文件。

长期记忆增加 `kind` 与 `when`，保留一个存储、一组工具和现有开关：

- `excerpt` 继续要求逐字出处；`fact` 与 `procedure` 可归纳文件、真实用户信息及实际执行的测试和 Shell 结果。后两者必须说明适用范围，类型不影响来源准入。
- 来源由 Runtime 从本次运行的事件核对，支持多个观察。`user` 是最近真实用户请求的别名，落盘时替换为事件哈希；模型生成的内部反馈不能冒充用户消息。
- 文件来源继续校验全部哈希，多个引用不能用一次新读取覆盖旧证据的失效。认证通过说明观察确实存在，不说明模型推断已被证明。
- 自动召回展示条目 ID、类型和适用条件。检索匹配范围包括适用条件，仍使用词面检索，最多注入三条。
- `run_tests.memory_ids` 声明实际应用且正在验证的已召回条目。省略即不计分，环境错误保持中性；避免测试结果连带奖惩所有被召回条目。
- 修复经验提示仅在同时开启记忆与自进化、主 Agent 出现真实非零执行失败且随后测试通过时触发。一次运行最多提示一次，最多建议提炼一条，跳过偶发与已覆盖的内容；以事件记录去重，恢复运行也不会重复提示。提供失败及通过引用，提醒不要把不相关的通过当作修复证明。保存时告知实际结果，不强制每次回复附加复盘。
- `memory_update` 在新条目准入成功后停用旧条目。Dream 继续按固定规则处理来源过期、反证和重复失败，并保留快照/回滚能力。

这构成“提炼 → 召回 → 应用 → 反馈 → 更新/停用”的外部记忆演化。没有新增依赖、配置开关、向量数据库或独立反思模型，仍用最多 64 条的项目 JSON 记忆。旧摘录记录可直接读取。关闭记忆时，测试工具不额外携带记忆反馈参数，保持小上下文预算。

知识写入仍有工具调用和模型决策成本，不能宣称免费。显式列出应用条目可以改善反馈归属，但仍依赖模型判断，也不等于精确的因果归因。现阶段没有自动发现所有语义冲突、跨项目共享或长期自主改写策略的能力。

## 十题验证

[任务定义](../evaluations/memory-knowledge-20261005/cases.py)覆盖口头项目约定、用户纠正、多文档知识、来源变更、修复经验、测试命令、适用范围和无关记忆反馈。每题有三项预先固定的行为断言，先学习，再通过全新 Runtime 会话使用；第 4 题额外有一次纠正，共每版本 21 个会话。

学习阶段明确要求记住，因此测量的是定向学习后的跨会话使用，不是无人提示下的自发积累。所有记忆均由真实模型自行写入；原始文档、学习阶段代码及模型自行创建的笔记均继续可读。

主比较保留冻结源码；末轮提示与修复经验改动单独归档，只补查第 2、7 题。第 7 题补查去掉“记住”要求，但要求先运行测试，以形成真实失败机会。这两次补查用于确认具体缺陷与触发行为，不能替代原比较结果，也不能声称测得自然任务流的自动学习成功率。

主要指标是任务成功率、30 项行为约束通过率，以及学习/使用/合计的供应商报告 token。辅助指标包括成功且召回了学习记忆的任务数、重复读取与测试失败、过期条目排除和无关条目反馈。成功且召回不等于记忆导致成功；整套比较是内部针对性实验，不替代公开 benchmark 或统计显著性结论。

执行脚本、冻结源码与实际结果放在[评测目录](../evaluations/memory-knowledge-20261005/)。仅做一次旧/新对比；遇到具体缺陷再补相应检查，不开展参数搜索或多轮挑分。

对照已完成，见[结果报告](../evaluations/memory-knowledge-20261005/REPORT.md)：严格复用成功 4/10 → 7/10，约束通过 17/30 → 25/30，总 token 增加 1.7%；全流程均完成为 4/10 → 6/10。两个针对性补查保留一成一败，末轮准入修正只做相关回归，版本和成本单独列明。
