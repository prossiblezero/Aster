# Aster v0.2 轻量 Coding Agent 收尾计划

2026-09-18。依据提交`6d0d0c8`附近的源码及[真实产品复测](../evaluations/benefit-20260918/REPORT.md)。这是下一轮实施建议；本次只补计划，没有实施下列源码修改或启动新模型实验。用户当前选择：先把可日常使用的轻量agent工程收尾，再开展后训练方案设计。已有训练接口保留，不在此轮扩展或采集训练数据。

## 目标与范围

建议将v0.2定义为Linux/Python 3.12上的单Agent：从CLI/TUI接收明确或需要少量澄清的需求，在授权范围查资料、安装项目依赖、编辑代码、执行验证、处理失败、取消与继续，交付有README和样例的可运行项目。继续使用现有Runtime、三种协议适配、九个核心工具、沙箱、证据及恢复机制。

合格不等于任意项目一次成功，也不要求Memory、Skills、缓存每项都有正收益。门槛是：默认路径可用；工具/权限/失败语义准确；必要的恢复可靠；产品能由独立验收确认；用户无需使用实验驱动设置隐藏参数或由操作员补代码。

最小方案是修已证实的契约与执行缺口、保留已有架构。整体重写、压成pi同样工具数量、引入插件平台或新的多Agent调度会扩大风险，本轮不采用。预计涉及现有源码、测试和文档超过8个文件，按依赖顺序分五批审查合入，每批落地后系统仍可使用；第五批验收依赖前面的行为修复，第四批为非阻塞整理。不增加常驻服务或生产必装依赖。网页浏览器验证另作为可选执行能力，不能悄悄变成核心安装负担。

## 第一批：模型响应可靠性和可诊断性

修改`provider.py`、`streaming.py`、`schema.py`、`runtime.py`及对应测试，统一响应成功、空输出、不支持的输出、截断、明确拒绝和结构错误的分类。完整响应和工具参数通过校验后才能提交历史或执行；不执行流式半截参数，不把拒绝误判为空回复重试。

复用现有事件系统，在流式和非流式共同记录：请求与响应model、protocol、response ID、白名单request-id、实际发送payload摘要、attempt、耗时、终态/输出块结构及长度、原始数值usage和归一计数/覆盖率。不得保存凭证、连接地址、推理正文或任意未过滤的响应对象；raw usage只保留有界的计数和归因字段。标签变化、计数矛盾明确标记，不据标签声称知道实际底层模型。

重试仍发生在生成侧：保留现有单逻辑请求最多3次传输尝试，把明确空回复的最多1次重试纳入同一尝试上限；不叠加外层重试，不自动轮换模型/网关/协议/流式模式。鉴权、内容过滤、未知输出和坏参数不盲重试。每次尝试消耗实际任务时间，已有usage也必须记账；没有usage保留未知。额度用完即保留checkpoint并给恢复入口。

恢复复用现有调用ID、checkpoint和工具结果记录；检查进程中断时是否存在已执行但未完成归集的调用，对结果不明的Shell副作用停止并提示检查，不自动重放。可按现有执行事件补最小的在途标记，不建立事务数据库，不承诺任意外部命令exactly-once。

验收：空响应、仅推理/未知块、拒绝、截断参数、503/断流、取消、标签变化、usage缺失/矛盾、日志脱敏；执行一次写入后模型失败，恢复不会重复写入。服务端仍不稳定时允许明确失败，不能通过隐藏失败或无限切路由制造“稳定”。

## 第二批：公开CLI/TUI和执行环境闭环

修改`cli.py`、`tui.py`、`config.py`、`tools.py`以及确有需要的`safety/runner.py`，沿用现有配置字段和命令，优先不增加顶层工具。

- CLI订阅已有流式事件，使`--stream`真正提供进度；最终答案仍完整输出，重试片段明确分隔，避免与最终结果混淆。TUI沿用现有增量组件。
- `--max-steps`、`--max-turns`允许用于TUI，将同一预算送入初次任务和续聊。默认仍有界；未知模型回退额度继续明示，不猜测远端规格。公开profile示例说明总上下文和输出预留，不再依赖`run_project.py`硬编码配置。
- 停止时展示run ID、可理解原因、已修改/已验证状态、CLI `--resume`或TUI `/continue`、`/resume`用法。空闲`/model`继续复用已有预检；不支持的跨协议历史明确拒绝，失败切换保留原会话。无需同时接通所有品牌真实账号。
- 在模型可见的固定能力说明中给出实际执行环境：可用Python/Node、沙箱/联网状态、依赖是否复用、临时目录规则、命令生命周期。不要每轮扫描全系统，使用运行环境的有限探测结果。
- `run_shell`说明单次命令结束后不能假定后台服务器仍存在，使用工作区临时目录而非任意`/tmp`；exit 0只表示命令退出成功。保留stderr，不能凭关键词把所有带“error”的成功程序重新判成失败。
- `run_tests`明确支持的运行器、保留的reporter参数，以及与普通构建/语法检查的区别；被拒时返回可执行的纠正提示。浏览器ES module检查方式写进Web使用说明，不能要求模型从失败猜环境。
- 真实验证一次授权文档读取与必要依赖安装、下一命令使用、重启后按README重建。继续通过现有`network`、`reuse_environment`和审批控制；不写base环境、不默认放开网络。

Web验证须如实分层：本轮是操作员调用Playwright做独立验收，尚未证明Aster能在当前沙箱内自己跑浏览器。v0.2核心先提供上述可发现的环境契约；浏览器自测采用可选Playwright工作流，服务器、浏览器及清理在同一次有界执行中完成，禁止用跨工具后台进程拼接。它需要浏览器安装与明确网络/进程权限，不作为核心依赖，不继承宿主登录资料。若当前沙箱不能安全执行，就明确保留“浏览器自测未支持”的边界，独立浏览器验收仍保留；不要为这个扩展关闭沙箱、编造自测证据或拖住核心版本。承诺“Web全自动浏览器验证”前必须单独打通它。

验收：真实公开入口的流式显示、提问、取消、恢复、预算、切换；安装依赖跨命令可用且宿主不污染；禁网仍生效；测试、构建、浏览器检查分别报告，不把Shell成功当产品验收。

## 第三批：默认功能收敛，修正Memory/Skills契约

当前源码默认`memory_enabled=true`、`memory_evolution=true`、`auto_dream=true`、`max_workers=2`。建议v0.2新会话默认改为四项关闭/0，保留已有显式配置覆盖；`tool_profile=core`和`read_parallelism=1`保持不变。这是产品默认范围的选择，不是删除实现或宣称Memory无用。旧checkpoint仍按原安全/配置身份校验，文档提供旧显式值；不能为了兼容而悄悄放宽身份检查。

默认迁移必须验证：旧checkpoint不重写，提供旧显式配置时能恢复原行为，配置不匹配时列出具体差异与恢复方法；不能因为更新默认值而静默关闭旧会话功能。新增该恢复回归。新增checkpoint字段保持旧状态可读；如新状态不能被旧版本恢复，明确最低兼容版本并保留原checkpoint，不能承诺所有版本直接回退。

九个核心工具保持：`list_files`、`read_file`、`search`、`write_file`、`patch_file`、`run_shell`、`run_tests`、`git_diff`、`tool_load`。可选工具继续按需展开。`run_tests`的结构化证据与`git_diff`的任务基线语义不能用普通Shell等同替换。

在`context.py`和`runtime.py`中，把宿主编写的Memory保存、Skill选择和工具能力指引移到简短稳定的策略段；Memory摘录、技能目录描述、正文和资源继续作为不可信资料。不能把技能内容整体提升为系统指令，也不为缓存重排已确认历史。

Memory工具和文档准确描述为“本次运行成功读取、有来源和失效检查的项目原文摘录”。继续限制原文、来源摘要及敏感内容；本轮不增加自由总结、用户偏好或Shell纠错经验来源。利用已有事件报告可见/加载/尝试/准入/拒绝/召回，Dream报告skipped及实际失活数量，不能将维护调用叫成反思学习。显式开启时验证保存→新会话召回→来源改变失效；自然保存率单列，不强制每任务保存。

Skills保留目录发现、正文快照、资源分页、显式刷新。指引说明匹配任务时按需加载，模型已读等价资料时不要求为计数再读一次。继续区分提供技能、工具入口加载、正文/资源读取和实际完成；不把所有任务都用了Skill、或比满分基线更高分作为门槛。

验收：关闭可选功能不影响编码；开启Memory和安装Skill的机制演示可复现；恶意资料不能改变权限；Dream无事可做时如实跳过。不做新向量库、大型Skill库、Memory自动总结器和Worker共同调度。

## 第四批：再拆两个职责，随后冻结Runtime边界

上轮已拆会话准备与正式测试执行。接下来仅提取：

1. `observation_read`的同会话归档来源合并、查询和分页，复用`session.py`/`evidence.py`，显式传入允许来源。
2. `memory_store/update`的成功读取证据认证与入库，归入`memory.py`，显式传入当前run和读取证据。

Runtime保留预算预留、审批前后版本检查、调用执行顺序、取消等待、状态提交、验证失效及生命周期；CLI/TUI与RL继续共用它。禁止通过持有整个Runtime的万能对象、mixin或大量一行转发来压缩文件长度。不设800行或500行的硬目标；依赖无环、职责可定位、行为不变即停止。第一批中如已经触及相关调用，可顺路提取，不重复重构。

验收：祖先归档合法访问、跨会话拒绝、分页回读；伪造/过期/非读取Memory证据拒绝；失败不改状态；相关回归通过后跑完整现有测试。保留调用/事件和checkpoint兼容边界。本批纯职责提取可通过回退源码提交撤销；其他批次按各自记录/配置兼容条件回退，不迁移或删除现有用户记忆和实验档案。

## 第五批：一次有限的工程发布验收

先冻结配置、需求与评分器，再执行下面三个场景。不复跑本轮题目追求漂亮收益，不增加大benchmark；这是工程发布门槛，不是统计能力排名。所有启动、澄清、恢复、切换使用公开CLI/TUI，记录真实模型身份和所有失败；实现、测试及README由Aster编写。

| 场景 | 预先约定范围 | 关键验收 | 工具步/模型轮/墙钟上限 |
|---|---|---|---|
| 新产品：期末复习安排器 | 从简短模糊需求做本地网页；课程、考试日期、剩余复习量、每日可用时数；不足时明确提示 | 最多两轮需求澄清；排程不超每日上限、不排到考试后；修改重排、刷新持久化、手机操作；Aster自测与独立浏览器评分分别记录 | 70/40/20分钟 |
| 新产品：实验数据整理器 | CSV读取、空值与非法数值报告、描述统计、原始/汇总/异常三个Excel工作表；提供交互式CLI、虚构样例和README | 使用确有用途的openpyxl依赖；授权读取官方用法文档、安装、跨命令使用；原始文件不覆盖；非法输入明确报错；干净目录按README重建 | 80/45/25分钟 |
| 现有产品维护：课业清单撤销删除 | 为已有产品加最近一次删除撤销，保留备份与日历；明确刷新后无需保留撤销记录 | 在一次写入完成、下一次模型生成期间取消，退出后恢复；空闲时切换已配置模型继续；功能与原26项浏览器回归通过，无重复已完成工具动作 | 50/30/15分钟 |

预算值通过公开CLI参数和已有profile指定；墙钟由验收控制器计时，恢复分配剩余额度，不以续聊重置总账。建议沿用已验证128000总上下文/32768输出预留作为该服务的显式测试配置，不宣称所有模型都支持此额度。正常审批和需求澄清不算返修；提交成果后获得缺陷反馈算返修。

每场景首次结果完整保留。明确产品缺陷最多一次有针对性的修复后重跑；同条件服务故障最多一次人工恢复，两者都消耗预定总预算，不跨模型补抽直到成功。仍失败则明确未通过，定位并修工程缺陷后另开新版本验收，不能覆盖原版失败。两个新产品只在可运行交付后进入`exam_project/`；协议、驱动、评分器、截图、轨迹归`evaluations/v0.2-release/`，教学站仍在`learn_web/`。

评分器先用正负用例校验，并接受语义等价的合法界面；出现评分器误判时保留原结果及版本化更正。独立检查不能使用候选自己写的断言充当唯一奖励。验收网页时操作员只使用浏览器评分器，不人工修补代码；如可选浏览器执行能力未交付，报告明确区分“独立浏览器验收通过”和“Aster自主浏览器验证”。

## 停止线：满足这些就转入后训练设计

- 三条公开入口任务链完成，交付能按README运行，独立验收通过，无操作员代写实现；首次成功、返修与服务故障分别统计。
- 确定性测试覆盖错误分类、有界重试、取消、恢复、权限、工具配对、配置切换、Memory/Skills开关和来源边界；最新源码完整回归通过。
- 至少一套真实模型profile稳定完成主流程；协议适配声明区分离线验证与真实服务验证。不为未提供的账号、模型或服务写“已验证”。响应标签/usage异常保留，不能作为后训练可信教师或策略身份。
- 默认路径仅单Agent与核心工具；可选能力行为可解释；已知平台和浏览器限制写清楚；Runtime不再因文件长度继续机械拆分。
- README、配置、工具契约、修改计划、安装入口同步，Git工作区干净；保存v0.2候选提交，发布/推送另外依用户明确要求执行。

完成后停止增加工程功能，开始数据集、SFT、GRPO方案设计。当前已完成的训练契约维持原状；本轮工程题与调试过的评分器只作开发材料，新训练/开发/未见测试按任务家族另划分。核心可用性不依赖Memory净收益、Dream产出或缓存达到某个固定百分比。

最脆弱的假设是至少有一条可用、身份足够清楚的模型服务路线。若相同请求仍随机换标签或返回空终态，Aster可以把失败分类、限制重试并保全状态，却不能从客户端保证后端修复。此时更换用户已配置且授权的稳定服务配置，保留不可用服务的原记录；不要继续堆兼容层或拿不可信轨迹开始训练采集。

## 验证与交接

全过程使用aster环境，逐批修改与提交。没有新增强制账号或密钥；真实模型仍使用本地已有配置，凭证不写入计划或Git。联网/下载依赖走明确的现有权限，浏览器是可选安装成本。此计划未发新模型请求、未验证新的服务端点。

每批运行受影响模块的专项检查；最后一次完整检查：

```bash
conda activate aster
python -m pytest -q
python -m ruff check src tests
git diff --check
aster --help
```

不新增重复实现镜像测试；优先扩展现有`test_provider_events`、`test_streaming`、`test_session_ui`、`test_session_continuation`、`test_tool_contracts`、`test_dependency_environment`、`test_context_archives`及Memory/Skills边界测试。既有代码若有无关格式问题不为过检查顺手全仓格式化。上轮851项核心回归与31项实验离线检查只是基线，不能代替修改后的检查。
