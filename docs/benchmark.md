# Aster 评测：任务正确性与机制收益分开看

评测包含 **193 条任务、42 个机制场景和 12 组上下文配置**。任务题库里有 164 道 HumanEval 函数题，不能据此声称模型解决了 164 道题。各条内容、初始文件、参考动作、预期行为都在 [datasets](../datasets/README.md)。

当前报告：[确定性回放](../artifacts/benchmark-v3-scripted/report.md)、[机制消融](../artifacts/benchmark-v3-mechanisms/report.md)、[真实模型](../artifacts/benchmark-v3-real/report.md)、[修复前后比较](../artifacts/benchmark-v3-comparison/report.md)。修复前的 v2 报告保留，不用新结果覆盖失败记录。

## 复现命令

```bash
conda activate aster
python -m pytest -q
python scripts/benchmark.py --task debug-and-fix --output artifacts/benchmark-v3-single
python scripts/benchmark.py --concurrency 4 --output artifacts/benchmark-v3-scripted
python scripts/benchmark_mechanisms.py
python scripts/benchmark.py --real --selection real_subset.json --repeats 1 --concurrency 4 --output artifacts/benchmark-v3-real
```

第一条代码题命令先确认初始版本的目标测试失败、已有行为测试通过，再通过 Runtime 回放参考修复，最后在独立副本执行验证器。全量回放包含 193 条任务；12 条记忆题各跑两个条件，因此是 **205 次执行**，另外检查 169 条代码题的初始版本和 12 组上下文压力配置。

机制脚本执行 **42 个独立场景、70 次条件尝试**，不调用模型。真实模型脚本使用固定的 **29 条题目、每题两个条件，共 58 次尝试**：5 条仓库修改、12 条跨运行问答、HumanEval/0–11。真实连接从 `.env` 加载，模型为 GPT-5.6 Luna，使用网关默认采样参数。

`--task` 可以重复指定；`--suite` 按题型选择；`--selection` 使用 datasets 中的固定名单。`--repeats 3` 是所有题、所有条件各跑三次，不是只重跑失败题。出现失败仍写报告，退出码为 1。

## 四层证据

| 层次 | 观察什么 | 怎样判断 |
|---|---|---|
| 任务完成 | 候选代码、外部测试、回答字段、结束状态 | 同时满足任务正确性和运行完成要求；两者也单独保留 |
| 效率 | 工具调用、重复读取、token、耗时 | 同题同初始文件进行开关对照；仓库、函数、记忆分别统计 |
| 鲁棒性 | 无效参数、停滞、恢复、状态漂移、网络错误 | 看中间拒绝、后续动作和最终结果，不能只看最后一句话 |
| 安全 | 路径、权限、沙箱、记忆准入、奖励来源 | 检查危险动作是否被拦截；代码题的高分不能抵消安全失败 |

## 对照具体改变了什么

**工具集合。** `core` 默认暴露 9 个工具，其余通过 `tool_load` 加载；`all` 一开始暴露全部工具。同题使用同一模型、初始文件、预算和验证器。失败尝试也计入成本。每题每组一次只能提供小样本观察，不能据此宣称统计显著或所有任务都更省时。

**跨运行记忆。** 两组先通过相同的 `read_file → memory_store` 获取事实，每组均两次工具调用，然后新建 Runtime 回答相同问题；历史和 working memory 为空，源文件仍可读。只改变长期记忆开关。学习阶段是固定工具动作，Luna 独立完成后续问答。报告把学习成本与后续问答分开，这测的是已有事实召回收益。

**记忆演化。** 24 个场景分别覆盖 12 条准入、4 条来源变化、6 条使用反馈和 2 条回滚。演化关闭时仍有准入和来源检查，只关闭反馈排序与 Dream 淘汰。6 条反馈场景中，按共同目标检查召回结果，关闭组 2/6、开启组 6/6，其中包含 2 条不应误删正常经验的控制场景。反馈由数据集预先标注，不能写成“真实 Agent 自进化成功率提升 66.7 个百分点”。

**恢复与 Hooks。** 恢复两题在相同重复/振荡动作后尝试改变方法，只有开启一次恢复机会的组继续完成；Hooks 两题分别检验重复调用 ID 与前置回调异常。关闭组保持其他权限与沙箱。共同目标均为 0/2 → 2/2；这是小规模机制消融，不能外推为业务失败率降低 100%。另外有 4 个恢复控制、3 个 resume、3 个停止生命周期、4 个 RL 环境场景。

“契约通过”与“目标达成”不同：关闭恢复的组按照定义停止，契约通过，但没有完成后续任务。70/70 指所有条件表现符合事先定义，不是 70 次 Agent 自主完成任务。

## 上下文预算

12 组配置交叉组合 12/24/48/96 条历史观察与代码、日志、中文三类文本。输入上限为 `4096 - 512 = 3584`，512 留给输出。计量复用 Provider 的 `request_payload`，覆盖最终消息、工具定义和请求参数，同时检查当前任务与指定验证证据没有丢失。

修复后平均输入 **18,138 → 3,412 个本地估算 token**，12/12 满足预算，当前请求与验证证据各保留 12/12；修复前预算检查为 0/12。这里用 cl100k_base 对 JSON 统一计数，并非各供应商的计费 tokenizer。

普通观察压力矩阵和原生工具历史配对是两类检查。后者由协议回归覆盖并行工具、推理元数据、裁剪、直接 step 后接续和 checkpoint；没有因此宣称任意长任务都不会丢信息。不可进一步压缩的请求会明确停止。

## 独立验证器与后训练边界

模型看到任务和初始工作区，拿不到参考动作、预期答案或评分条件。结束后再复制候选、加入隐藏测试与固定 pytest 配置，使用 Python 隔离启动以防候选的同名模块冒充 pytest，在禁止网络的沙箱中运行；测试失败、收集失败、超时和空测试都不通过。HumanEval 使用官方断言；第 33 题用官方参考函数固定预期值，避免被测函数与自己比较。

Agent 自己执行仓库测试，只产生“做过验证”的过程证据。它不能直接变成训练成功奖励。`AsterEnv` 每次 reset 复制初始仓库，Final 前停止子任务，再调用宿主提供的 `verifier(root, state)`；只有该验证器确认成功才给 +1，没有独立验证器时不会给正的成功奖励。工具调用本身没有正奖励，终态后不能继续 step。

Python 进程内测试仍不是对任意恶意代码的完全防作弊证明。当前检查防止公开测试被删除、配置/conftest 影响评分、pytest 模块冒充、空测试与生命周期骗分；后续具体训练任务仍需设计独立奖励验证器，并针对该任务补骗分样本。当前没有实现 SFT 或 GRPO。

所有题目和轨迹均属 evaluation split，不得直接混入后续训练集。小型仓库题借鉴 SWE-bench 的初始版本/修复版本验证方式，未运行 SWE-bench 官方实例；12 道模型函数题的结果不是完整 HumanEval 分数。

## 指标和工件

`steps` 是工具调用次数，`turns` 是模型决策轮次；`passed` 要求该题的全部判定成立。真实 token 优先使用服务端 total_tokens，缺失才使用输入加输出。请求失败或重试若没有返回 usage，账面无法覆盖远端可能产生的全部费用。

报告列出所有尝试和共同成功题的成本；后者只是控制正确性差异的补充，不能取代全量通过率。Pass@k 使用 `1 - C(n-c,k)/C(n,k)`；每题只有一次时不报告 Pass@3，不把工具开关当作两次重试。v2 与 v3 的网关负载和并发不同，耗时只作观测，不归因于某一代码改动。

`report.json` 保存逐题结果、模型配置、Git 版本和源码/数据指纹；`attempts.jsonl` 保存逐次结果；`runs/` 保留独立批次的 trace、checkpoint、候选文件、diff 和评分输出。完整工件在本机保留并忽略 Git，汇总报告提交 Git。修复前错误以及此前评分器纠正记录保留在 v2 目录。

本轮先在 `d405773` 上完成了一批 58 次真实模型尝试，结果为 58/58；随后补充工具目录发现、子任务后的观察刷新与评分启动隔离，在 `62fedb1` 上重新执行完整名单。第一次报告保存在各 v3 目录的 `first-pass-report.*`，最终正文与比较使用 `report.*`。两次是不同源码版本的完整评测，不把它们合并成同一版本的 Pass@2。

## 最终版本实测（2026-09-14）

最终版本的 138 项单元/集成测试与 Ruff 通过；参考动作回放 205/205，169 条代码题的初始目标测试均失败且原有行为通过，参考解均通过；机制场景 70/70，预算配置 12/12。真实模型最终为 **57/58**，逐次候选文件与 checkpoint、trace 哈希链均核验一致。

| 任务类型 | 条件 | 修复前完成 | 最终完成 | 最终平均工具调用 | 最终平均记录 token |
|---|---|---:|---:|---:|---:|
| 函数实现 | 全部工具 | 12/12 | 12/12 | 5.92 | 27,783 |
| 函数实现 | 核心工具 | 12/12 | 12/12 | 6.67 | 25,781 |
| 仓库修改 | 全部工具 | 2/5 | 5/5 | 15.80 | 47,963 |
| 仓库修改 | 核心工具 | 2/5 | 5/5 | 18.20 | 45,706 |
| 跨运行问答 | 关闭长期记忆 | 11/12 | 11/12 | 3.08 | 13,671 |
| 跨运行问答 | 开启长期记忆 | 11/12 | 12/12 | 0.00 | 5,159 |

最终批次的唯一失败是 `memory_steps / memory_off`：模型未调用工具，直接回答 16，正确值为 17。Runtime 的结束条件满足不等于答案正确，外部答案验证已将该次判错。没有更改题目或重采样覆盖失败。

同批次对照：核心工具相对全部工具，函数题记录 token 减少 7.2%、仓库题减少 4.7%，同时工具次数增加。记忆两组共同成功的 11 条，工具调用 37→0、token 158,822→56,770，减少 64.3%。两组全量成功率仍分别是 11/12 和 12/12。

跨版本记录 token 显著增加，完整比较也包括这个退步；仅凭现有 usage 不能将差异归因于某个组件或网关行为。不能用更高完成率掩盖成本增加，也不把跨批次耗时下降写成确定的系统加速。详见 [逐题与开关比较](../artifacts/benchmark-v3-comparison/report.md) 和 [工件核验](../artifacts/benchmark-v3-comparison/validation.json)。
