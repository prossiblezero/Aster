# Aster：轻量代码智能体 Harness

**核心技术：** Python、asyncio、HTTPX、Pydantic、OpenAI / Anthropic API、Tool Calling、Context Management、Layered Memory、Checkpoint / Resume、Hooks、Sandbox、pytest。

**项目描述：** 开发面向本地代码仓库的智能体运行系统，统一模型调用、代码修改、权限控制、任务恢复与结果验证。通过真实代码任务对照和模块消融，评估上下文裁剪、工具加载、记忆召回与停滞恢复的效果和边界。

**核心贡献：**

1. **统一执行流程与工具管理。** 让命令行与交互界面共用一套运行逻辑，串联参数检查、审批、执行和记录；组织 27 种工具，默认展示 9 种核心工具；归档回读等其他能力通过工具目录按需加载。在 v4 的 12 道函数题对照中，相比一次展示全部工具，采用“核心工具＋按需加载”后，任务完成率均为 **100%**，平均 token 消耗降低 **11.4%**。
2. **设计上下文预算与归档。** 根据接入模型的窗口自动分配容量，将工具结果归档，超限时压缩正文并支持按需回读；工具调用与结果成组裁剪。在 12 道含长历史的代码题上，选定 8,192 输入预算后各重新运行 3 次，平均首次输入从 **18,435 压至 7,779 个本地估算 token，压缩 57.80%**；**36/36 完成，Pass@1、Pass@3 均为 100%**。
3. **设计分层记忆与反馈维护。** 会话内保存文件、搜索与测试摘要，文件变化后及时失效；跨运行保存有来源证据的项目事实，通过反馈排序、过期停用和快照回滚维护质量。在 v4 的 12 条真实模型问答中，关闭/开启长期记忆分别完成 **11/12、12/12**；双方均答对的 11 条，后续工具调用从 **35 次降至 0 次**，token 减少 **65.3%**。另用 6 个固定反馈场景验证记忆维护，目标召回从 **2/6 提升至 6/6**。
4. **保障任务恢复与有界纠偏。** 保存任务状态、完整交互及工作区指纹，恢复时检查文件、权限和配置漂移；运行时检测重复与振荡，注入纠偏提示并限制恢复次数，取消时等待子任务退出。覆盖重复、振荡、恢复额度和续跑一致性等 **25 个场景，机制回归通过率 100%（37/37 次条件检查）**。
5. **集中管理工具安全与 Hooks。** 统一路径、写入范围、审批和进程隔离，设置执行前、成功后、失败后和停止回调；工具目录同步过滤不可用能力。前置检查异常时拒绝动作，重复调用编号由协议入口强制拦截；**27 个测试工具场景**覆盖真实执行、全跳过、假输出、提前退出及环境错误，防止假通过与记忆误扣分。
6. **建立分层评测与运行审计。** 围绕任务完成、效率、鲁棒性和安全，组织 **193 条基础主任务、12 道新增上下文代码题和 81 个 Harness 机制场景**；使用隐藏测试独立检查代码，分开记录功能正确、运行完成及成本，并保留执行记录、检查点与代码差异。基础主任务 **205/205 次参考动作回放通过**，最新机制检查 **119/119 次符合预期**；真实模型成绩与脚本回放分开报告。

v4 批次的唯一失败是关闭长期记忆的 `memory_steps`：模型未读文件，猜测 16，正确值为 17。另有两次命令缺少结尾引号被拒、六次编辑前缺少最新读取被拒，后续均完成任务。这些结果保留，不用最好看的批次覆盖失败。工具次数包含定位、读取、修改、测试和差异检查，不等于回答同一问题的重试次数。

v4 的 58 次真实尝试中，205 次上下文构建均未触发历史裁剪，输入预算为 21,952；因此这批成绩不能证明紧预算下的任务能力。v5 已另做三档预算对照和真实模型恢复对照，结果按批次独立保留，不把不同开关和不同预算合并成重复采样成绩。

模型接入通过 HTTPX 适配 OpenAI Responses / Chat Completions 与 Anthropic Messages API，未依赖两家的官方 Python SDK。真实连接只评测了 Responses；Chat、Anthropic 通过协议契约测试。内建测试验证面向 Python，其他语言需要对应验证器。隐藏评分与候选同 Python 解释器，不宣称完全抗恶意候选篡改。
