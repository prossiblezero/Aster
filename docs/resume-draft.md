# Aster：轻量代码智能体 Harness

**核心技术：** Python、asyncio、HTTPX、Pydantic、OpenAI / Anthropic API、Tool Calling、Context Management、Layered Memory、Checkpoint / Resume、Hooks、Sandbox、pytest。

**项目描述：** 开发面向本地代码仓库的智能体运行系统，统一模型调用、代码修改、权限控制、任务恢复与结果验证。通过真实代码任务对照和模块消融，评估上下文裁剪、工具加载、记忆召回与停滞恢复的效果和边界。

**核心贡献：**

1. **统一执行流程与按需工具加载。** 针对工具描述占用上下文、不同交互入口执行逻辑分散的问题，统一 CLI/TUI 的模型调用、参数校验、审批与执行流程，采用核心工具常驻、扩展工具按需加载。在真实模型对照中，12 道函数题的平均 token 消耗降低 **11.4%**，5 道仓库维护题降低 **12.4%**。
2. **实现上下文预算与工具结果归档。** 针对长任务中历史对话和工具输出不断挤占模型窗口的问题，设计分层预算、调用与结果成组裁剪及归档回读机制，保留当前请求与必要协议字段。在 12 道预置长历史的代码题中，选定预算后每题运行 3 次，平均首次输入由 **18,435 降至 7,779 个本地估算 token，压缩 57.8%**，任务完成 **36/36**。
3. **设计会话树与多会话交互。** 针对回到历史位置探索新方案时需要查找恢复点、手动交接上下文的问题，实现类型化会话树、分支历史隔离、可选摘录交接及独立会话后台执行。在六类固定工作流的离线对照中，操作数由 **69 降至 36，减少 47.8%**；在历史分支专项中，准备操作由 **4 步降至 2 步**，且真实模型回答不受影响。
4. **实现分层记忆与来源维护。** 针对新会话重复查阅项目事实、旧知识随文件修改而失效的问题，结合会话内工作摘要与跨会话证据摘录，通过来源校验、反馈排序和过期停用维护记忆。在 12 道项目事实问答对照中，开启记忆后任务通过率达到 **100%**，且 token 减少 **65.3%**；在两个项目的六轮编码维护对照中，开启记忆后文档读取减少 **18.5%**。
5. **保障中断续跑与有界故障恢复。** 针对任务中断后需要重新执行、重复调用和失败循环消耗预算的问题，保存运行状态、交互历史与工作区指纹，恢复前检查环境漂移，并通过停滞检测、有限恢复额度和子任务清理控制执行生命周期。在 12 个故障注入场景、每场景 3 次真实模型续跑中，任务完成不受影响。
6. **建立执行安全与可信验证闭环。** 针对越界修改，以及“打印通过但未实际执行测试”造成错误完成判定的问题，统一路径权限、写入范围、沙箱与 Hooks，依据结构化测试报告核对执行结果；将独立评分与公开自测分离，保留训练环境接口和执行证据。在全跳过、伪造输出、提前退出等 **25 个异常或无效验证场景中，误判率为 0%**。

v4 批次的唯一失败是关闭长期记忆的 `memory_steps`：模型未读文件，猜测 16，正确值为 17。另有两次命令缺少结尾引号被拒、六次编辑前缺少最新读取被拒，后续均完成任务。这些结果保留，不用最好看的批次覆盖失败。工具次数包含定位、读取、修改、测试和差异检查，不等于回答同一问题的重试次数。

v4 的 58 次真实尝试中，205 次上下文构建均未触发历史裁剪，输入预算为 21,952；因此这批成绩不能证明紧预算下的任务能力。v5 已另做三档预算对照和真实模型恢复对照，结果按批次独立保留，不把不同开关和不同预算合并成重复采样成绩。

模型接入通过 HTTPX 适配 OpenAI Responses / Chat Completions 与 Anthropic Messages API，未依赖两家的官方 Python SDK。真实连接只评测了 Responses；Chat、Anthropic 通过协议契约测试。内建测试验证面向 Python，其他语言需要对应验证器。隐藏评分与候选同 Python 解释器，不宣称完全抗恶意候选篡改。
