# Aster：本地代码智能体 Harness

**技术栈：** Python、GPT-5.6 Luna、结构化工具调用、Linux 文件与进程隔离、上下文压缩、分层记忆、任务恢复、自动验证、Agent-RL

**项目描述：**

从零实现一个运行在本地代码仓库中的 coding agent。模型负责决定下一步做什么，Aster 负责限制它能访问哪些文件、能执行哪些命令、如何保存过程、如何恢复中断任务，以及如何确认任务真的完成。项目重点解决长任务中的上下文变长、重复读文件、工具失败后空转、验证结果过期和“模型说完成但实际没完成”等问题。

**核心工作与结果：**

1. **搭建统一执行流程。** 把模型请求、工具参数校验、权限判断、隔离执行、结果记录和最终验证串成一条流程；生产运行和 Agent-RL 的 `reset/step` 使用同一套执行边界，避免训练环境和实际运行环境不一致。当前支持三种模型接口和 25 个结构化工具。

2. **控制上下文长度。** 为任务、历史消息、记忆和技能内容设置 token（模型处理文本的基本单位）预算，优先删除普通旧观察，保留当前请求、失败信息、修改记录和最新验证证据。在 12 组压力配置中，输入平均从 **703.9 降到 576.9 tokens**，平均减少 **11.28%**，最高减少 **59.38%**；当前请求和重要验证证据保留率均为 **100%**。

3. **把记忆做成可验证的三层结构。** 当前任务使用 working memory 保存文件事实和过程摘要，跨任务经验进入 durable lessons；每条经验都挂在 `run_id + evidence_id` 上，由 evolution ledger 记录支持、矛盾、使用成功/失败和版本变化，支持去重、淘汰与快照回滚。与关闭记忆的对照相比，12 个 follow-up 任务的重复读文件次数从 **12 次降到 0 次（减少 100%）**；在 12 个固定事实任务中，Recall@3、MRR 和 Top-3 precision 均为 **100%**。这组结果验证的是证据约束下的记忆流程，不外推为开放域语义检索能力。

4. **让恢复有条件、有边界。** checkpoint 保存任务状态、工作区指纹和运行配置；恢复前重新核对这些信息，正常状态继续执行，工作区漂移或配置不匹配则拒绝恢复。10 个恢复场景中，正常恢复、漂移拒绝和身份不匹配拒绝均为 **100%**。运行中另外检测重复调用、ABAB 反复和相同输出循环，三类模式 **3/3 检出**；一次恢复仍无进展后停止，避免无限重试。

5. **用完成合同拦截“口头完成”。** 任务只有在“确实修改了目标、修改后重新验证、验证器通过”时才算完成；没有编辑或验证过期都会被拒绝。9 个正反场景的合同执行率为 **100%**。同一套工具边界还覆盖路径逃逸、`.git/.aster/.env/.pem` 敏感路径、提示注入、参数错误和命令超时，确定性安全与故障集 **9/9 通过**。

6. **用对照实验评测 Harness 收益。** 对能够单独归因的模块设置关闭能力或大预算基线，并使用独立测试仓库和自动验证器：上下文压缩把平均输入从 **703.9 降到 576.9 tokens（减少 11.28%）**，同时保留当前请求和验证证据 **100%**；开启记忆后重复读文件 **12→0**；恢复与完成合同分别在漂移/停滞和正反场景中保持 **100%**。再用 GPT-5.6 Luna 对简单、中等、困难共 **5 类任务**各运行 3 次（15 次），得到 **Pass@1 80.00%、Pass@3 100.00%、验证通过率 93.33%**：简单任务 6/6 通过，中等任务 5/6，困难任务 3/3。成功运行按难度分别记录工具调用、token 和耗时，避免把不同难度混成一个效率平均值；所有 attempt 的 trace 和失败原因均保留，其中 1 次为远程网关连接错误。

**项目边界：**

当前已实现 Agent-RL 环境接口，但尚未实现 SFT、GRPO；上下文策略没有自进化；Memory 使用轻量关键词召回，尚未宣称开放域语义检索或完整陈旧记忆治理。确定性测试结果与真实模型结果分开统计。
