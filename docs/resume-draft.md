# Aster：轻量代码智能体 Harness

**核心技术：** Python、异步编程、工具调用、上下文治理、分层记忆、沙箱隔离、自动化评测。

**项目描述：** 开发面向本地代码仓库的智能体运行系统，统一模型调用、代码修改、权限控制、任务恢复与结果验证。通过固定任务、模块开关和修复前后对照，验证系统可靠性与使用成本，并为后续后训练提供可隔离、可评分的运行环境。

**核心贡献：**

1. **统一执行流程与工具管理。** 让命令行、交互界面和训练环境共用一套运行逻辑，串联参数检查、审批、工具执行和结果记录；将 26 个工具组织为 9 个核心工具与按需加载能力。在 12 道函数题上，两种配置均完成 12/12，核心集合将平均 token 从 27,783 降至 25,781，减少 7.2%。
2. **控制长任务输入规模。** 将工具定义、对话和协议消息统一纳入预算，按完整调用与结果组裁剪历史。在 12 组长上下文配置中，平均输入从 18,138 压至 3,412 个本地估算 token，预算满足率从修复前 0/12 提升至 12/12，当前请求和指定验证证据均完整保留。
3. **减少重复工作并维护记忆质量。** 会话内保存文件与测试摘要，跨运行保存可追溯的文件事实，通过使用反馈、过期停用和快照回滚维护经验。在 12 条真实模型记忆任务中，关闭/开启记忆分别完成 11/12、12/12；双方都答对的 11 条任务，后续工具调用从 37 次降至 0 次，token 从 158,822 降至 56,770，减少 64.3%。
4. **提高长链路任务可靠性。** 实现状态检查点、文件与配置漂移检查、有界循环恢复，修复有效修改被误判为停滞以及旧摘要继续使用的问题。同一组 5 个仓库修改任务，在两种工具配置下均从修复前 2/5 完成提升至 5/5；固定恢复消融中，开启恢复后两种循环场景均能继续完成任务。
5. **收紧安全与生命周期边界。** 将路径、只读范围、人工审批和进程隔离集中执行，设计工具前置、成功、失败与停止 Hooks。在重复调用、前置检查异常两类控制场景中，开启 Hooks 后均拦截不应执行的动作；持久记忆须关联真实文件观察，并拒绝敏感、临时及无支持内容。
6. **建立可复现评测与后训练接口。** 将 193 条主任务和 42 个机制场景集中组织为数据集，完成 205/205 次参考动作回放、70/70 次机制契约检查；真实模型完成 57/58 次固定条件尝试，保留唯一的猜测错误及完整轨迹。训练环境逐次复制初始仓库，只由独立验证器发放任务成功奖励，避免状态串场和重复调用刷分。

唯一失败是关闭长期记忆的 `memory_steps`：模型未读文件，猜测值为 16，实际为 17。这个案例保留为后续证据获取训练的评测案例，不直接混进训练集。此前修复版本的 58/58 也保留，但简历采用最终版本的 57/58，没有挑更好看的批次。

跨版本的网关 token 记录明显增加，原因尚不能单独归因于模型、网关或 Harness；完整表格如实展示增加值。简历的 token 节省数字仅使用最终同一批次的开关对照，不宣称此次修复让整体 token 成本下降。

项目已有 Agent-RL 环境接口，尚未实施 SFT、GRPO，也未验证后训练收益。真实模型测试使用 Responses；Chat、Anthropic 通过协议契约测试，不能写成三家真实模型均已跑通。
