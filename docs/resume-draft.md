# Aster：轻量代码智能体 Harness

**核心技术：** Python、asyncio、HTTPX、Pydantic、OpenAI / Anthropic API、Tool Calling、Context Management、Layered Memory、Checkpoint / Resume、Hooks、Sandbox、pytest。

**项目描述：** 开发面向本地代码仓库的智能体运行系统，统一模型调用、代码修改、权限控制、任务恢复与结果验证。通过压力测试检查上下文预算，通过同题对照和模块消融评估工具、记忆与运行治理。

**核心贡献：**

1. **统一执行流程与工具管理。** 让命令行与交互界面共用一套运行逻辑，串联参数检查、审批、执行和记录；组织 26 种工具，默认最多展示 9 种核心工具，其余按需加载。在相同的 12 道函数题上，相比一次展示全部工具，采用“核心工具＋按需加载”后，任务完成率均为 **100%**，平均 token 消耗降低 **11.4%**。
2. **控制长任务的上下文规模。** 将对话、工具定义及协议包装统一纳入预算，按完整调用与结果组裁剪历史，保留当前请求、计划与待办；长正文支持继续分页读取。在 **12 组人工构造的历史压力输入**中，平均输入由 **18,207 降至 3,352** 个本地估算 token，预算与指定信息保留检查全部通过；该测试尚未验证裁剪后的真实任务完成率。
3. **设计分层记忆与反馈维护。** 会话内保存文件、搜索与测试摘要，文件变化后及时失效；跨运行保存有来源证据的项目事实，通过反馈排序、过期停用和快照回滚维护质量。在 12 条真实模型问答中，关闭/开启长期记忆分别完成 **11/12、12/12**；双方均答对的 11 条，后续工具调用从 **35 次降至 0 次**，token 减少 **65.3%**。另用 6 个固定反馈场景验证记忆维护，目标召回从 **2/6 提升至 6/6**。
4. **保障任务恢复与有界纠偏。** 保存任务状态、完整交互及工作区指纹，恢复时检查文件内容、权限和配置漂移；运行时检测重复与振荡，向模型注入纠偏反馈并限制恢复次数，取消时等待子任务退出。通过 **2 个停滞恢复、4 个恢复控制及 3 个续跑场景**，检查预设动作能否继续执行、正常进展是否被误拦，以及恢复次数在新任务与续跑中的处理。
5. **集中管理工具安全与 Hooks。** 统一路径、写入范围、审批和进程隔离，设置执行前、成功后、失败后和停止回调；工具目录同步过滤不可用能力。在重复调用和前置检查异常两类消融中，开启 Hooks 后均阻止了不应执行的动作；**27 个测试工具场景**覆盖真实执行、全跳过、假输出、提前退出及环境错误，防止假通过与记忆误扣分。
6. **建立分层评测与运行审计。** 围绕任务完成、效率、鲁棒性和安全，组织 **193 条主任务、65 个 Harness 机制场景**；代码修改任务用隐藏测试独立评分，对工具集合、记忆和恢复分别设置开关对照，保留每次执行记录、检查点、代码差异和失败原因。**205/205 次参考动作回放通过，93/93 次机制行为检查符合预期**。

最终批次的唯一失败是关闭长期记忆的 `memory_steps`：模型未读文件，猜测 16，正确值为 17。另有两次命令缺少结尾引号被拒、六次编辑前缺少最新读取被拒，后续均完成任务。这些结果保留，不用最好看的批次覆盖失败。工具次数包含定位、读取、修改、测试和差异检查，不等于回答同一问题的重试次数。

现有真实模型批次的 58 次尝试中，205 次上下文构建均未触发历史裁剪，输入预算为 21,952。因此，57/58 的任务成绩不能证明上述紧预算压力配置仍能保持任务完成率。

模型接入通过 HTTPX 适配 OpenAI Responses / Chat Completions 与 Anthropic Messages API，未依赖两家的官方 Python SDK。真实连接只评测了 Responses；Chat、Anthropic 通过协议契约测试。内建测试验证面向 Python，其他语言需要对应验证器。隐藏评分与候选同 Python 解释器，不宣称完全抗恶意候选篡改。
