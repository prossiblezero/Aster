# 阶段 16：把长历史变成可查回的证据

## 问题：压缩后，关键日志只剩一个开头怎么办？

假设 Agent 运行了一次不能随便重复的迁移检查，关键信息藏在几千行日志中间。保留前后几段能减小输入，却不能保证那条信息仍在。Aster 先把已采集、已脱敏的工具正文保存在当前运行的观察归档，再让模型看短正文与引用；以后通过 `observation_read` 查回。这不调用额外总结模型，也不生成新的语义结论。

观察归档像本次任务的原始附件，`working_memory` 像桌面的便签，跨运行记忆像经过证据核实后留下的项目笔记。三者职责不同；这次没有新增第二套工作记忆，也没有让上下文策略自行训练或进化。

## 从一次真实请求往回读代码

先看 [Runtime.prepare_request](../../src/aster/runtime.py)。它刷新文件和测试证据，取得工作记忆与已加载技能，再调用 [ContextBuilder.build](../../src/aster/context.py)。正常模型轮次和 `AsterEnv` 都调用它。`context_built` 事件记录策略版本 `deterministic-v4`、实际请求估算量、预算、归档记录哈希与请求工件地址；请求工件按原有规则脱敏，记录的请求哈希也对应脱敏版本；文件名含该哈希，避免同一轮多次构建覆盖先前证据。

构建器还从现有 `RunState` 渲染一份短状态：未完成待办、实际修改路径、测试状态与命令、验证时的工作区哈希、剩余步骤与轮次。测试通过后再修改文件，验证状态会失效。模型无需从几千行旧日志里猜测试是否通过，但公开测试通过仍不等于外部隐藏验收通过。

请求依次经过这些处理：

1. 按完整交互组校验历史，归档尚未外置的工具正文；旧格式导入的工具观察也归档，但不伪造历史工具调用。
2. 保留完整工具正文、真实状态与调用编号。此时只归档，不因为单条结果超过某个固定 token 数就截断。
3. 把系统规则、当前任务、工具定义、结构化状态与全部历史一起转为实际供应商请求并计量。
4. 超预算时先移出可删除的旧普通消息（工具观察已归档），再缩短旧交互正文、移出旧完整组；最后才缩短最近批次。正文真的缩短时附带归档引用，完整结果不携带额外长编号；每份正文按实际缺口让出空间。
5. 必要时让可重建的记忆召回、技能正文等让出空间，缩短可分页重读的计划文字。用户要求、调用参数与必需协议元数据不做任意截断。
6. 整份请求满足预算后才更新活动历史。必需内容仍装不下就明确停止；归档写入或校验失败也不先删除唯一原文。

v4 移除了 `tool_output_tokens`。同一份 6,000 tokens 的结果，整份请求放得下就完整发送，放不下才按缺口压缩；分页正文只保留连续前缀并重算游标，不能用首尾拼接伪装成连续一页。技能正文也在全局超预算后才取摘要。

生产默认按具体模型的输入上限和总窗口计算，再留输出与 5% 计量余量；Luna 当前默认输入额度为 875,900，详见[配置说明](../configuration.md)。`context_tokens` 显式值仍包含输出预留，`effective_context_tokens` 是解析后的有效总额。压测使用几千 tokens 是主动制造长历史放不下的条件，不是推荐把真实模型窗口限制到几千。每轮由 Runtime 自动检查，用户无需手动触发压缩。

## 调用和结果为什么不能拆开？

`call_id` 标识一次具体调用。例如两次 `read_file` 的编号分别为 A、B，结果必须分别关联 A、B，不能只凭工具名配对。缩正文不会改变调用参数、编号或真实状态；移出旧历史则移出整个交互组，包括并行调用与协议要求关联的推理元数据。

[provider.history_groups](../../src/aster/provider.py) 在内部历史和供应商请求转换后检查空编号、重复编号、孤立结果、缺失结果及回合顺序。Runtime 也在保存和恢复检查点时验证完整组。取消时记录真实的中断状态；是否已经产生副作用不确定，就提示检查工作区，不能补造成功结果。

检查点与审计副本还要区别处理。`encrypted_content` 是 Responses 的加密推理数据；Anthropic 的 `signature` 和 `redacted_thinking.data` 也是必须原样回传的协议字段。它们可能偶然包含类似密钥的随机字符，不能直接套用普通日志正则再拿去恢复。`EvidenceStore.save(..., preserve_native_history=True)` 只在 checkpoint 的原生字段位置保留原值，工具数据里的同名字段没有豁免；请求审计和 trace 继续脱敏。含真实已知凭据、已有 `[REDACTED]` 标记，或签名绑定的思考文字需要脱敏时，明确拒绝保存/恢复，而不把坏记录当成合法状态。

```bash
conda activate aster
python -m pytest -q tests/test_protocol_pairing.py tests/test_context_archives.py
```

重点阅读 `test_latest_parallel_batch_fits_one_budget_with_all_results` 对应的参数化用例：四份大结果共用紧预算，但所有调用与结果仍成对。其他用例检查正文中部的一次性证据如何在裁剪和恢复后找回，以及归档损坏为何必须在下一次模型调用前停止。

## 怎样使用唯一新增的工具？

先读 [ObservationRead](../../src/aster/tools.py)，再读 [EvidenceStore](../../src/aster/evidence.py) 的三个观察方法。

| 字段 | 含义 |
|---|---|
| `observation_id` | 归档编号；有编号时读取该观察，没有编号时列出或检索本次运行的观察 |
| `query` | 可选的字面文本检索，不是正则，也不调用向量模型 |
| `offset` | 带编号时按字符定位；不带编号时按匹配记录定位，从 0 开始 |
| `limit` | 带编号时最多返回的字符数，默认 512、最大 1000；不带编号时最多 10 条记录 |
| `next_offset` | 下一页位置，`null` 表示结束；按它续读，不自行加上请求的 limit |

例如先调用 `observation_read(query="timeout")` 查引用，再用返回的 `id` 与 `match_offset` 读取附近原文。正文因预算缩短时，字符页和记录页的游标随可见内容调整，避免跳过尚未展示的内容。分页所需的最小结构也装不下时停止，不输出损坏 JSON。

存在工具观察后，这个工具会出现在 `tool_load` 的可加载目录中；模型加载后才展示其完整参数定义，默认仍只展示 9 个核心工具。它没有 `run_id` 或文件路径参数，不能读其他运行、密钥、检查点或任意 `.aster` 文件；归档内容仍是不可信观察。查回旧文件内容不能替代编辑前的 `read_file`，因为文件可能已经变化。

## 正常执行与训练环境如何保持一致？

[AsterEnv._observation](../../src/aster/rl.py) 的 `model_input` 是经过上述构建的消息，配套 `tools` 是同一份工具定义。其余状态字段供调用方调试；后续训练适配器不能把全部诊断字段重新拼给模型，否则又绕过了压缩。`context_policy` 是规则版本，`context_tokens` 是此次输入估算量。

```bash
python -m pytest -q tests/test_context_policy_input.py
```

第一个测试让外部策略读取文件，再切换到捕获请求的模型，逐项比较两条路径的输入和工具定义。第二个测试删除归档，确认环境返回失败及对应奖励，而不是抛出异常后丢失一次转移。这里没有实现 SFT 或 GRPO。

## 如何判断重构有效？

先看[中档回归与预算选择](../../datasets/context_budget_protocol.md)和[实测结果](../context-results.md)：12 道主任务，先在原中档各跑 3 次，再对三个固定候选各试 1 次，选中后用新 3 次确认；一次性历史证据题另报。历史三档结果仍保留。本轮题目与隐藏评分器不改，取消单条工具上限的收益由同预算比较回答，放宽预算的效果另报。观察 Pass@1、Pass@3、预算停止和隐藏测试结果，再看共同成功尝试的 token 与工具成本，不能只比较压缩率。

这批原题已经用于诊断，属于开发回归，不能当作未见任务泛化成绩。原始报告与每次失败继续保存；历史前后批次也不能完全排除模型服务随时间变化。归档仅包含执行器实际采集到的内容，无法恢复它采集前已经丢弃的输出。不可压缩的用户要求或最新调用参数超过窗口时，仍需要拆分任务或使用更大的已知安全窗口。
