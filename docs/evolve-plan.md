# Aster 自我进化循环：设计与有效性证明方案

日期：2026-11-01。本文只做设计，不含实现；代码由 Codex 按阶段完成。阶段只写顺序，不写工期。

## 1. 目标与诚实的命名

目标：让 Aster 自己读取自己的采样轨迹，修改自己的框架文本层（系统提示、工具说明、提示文本），并用评测闭环决定保留还是回退；然后用经得起追问的证据证明“迭代确实有效”。

命名要和证据对齐，分两级：

| 级别 | 做了什么 | 文献里的对应 | 能写的名称 |
| --- | --- | --- | --- |
| 第一级 | 提议者读历史轨迹与分数，只改文本层，评测后择优保留 | Meta-Harness、Self-Harness、以自身为优化器的单模型框架 | 自应用的框架自动优化循环 |
| 第二级 | 改进过程本身也被改进：提议者的指引与经验库随任务积累，并被证明有用 | Harness²（第二层循环）、DGM（修改自身的改进能力） | 递归自我改进 |

第一级是必做的最小版本。第二级只有在第一级出现正向结果后才做，并且必须有“有无第二级”的对照；没有这个对照，就不能写“递归”。

对本方案影响最大的三条：

1. **多数论文的有效性证据偏弱**：缺划分、缺重复、缺置信区间。我们已有成对自助法置信区间、冻结留出集、同时段对照，这套协议比表中多数论文严格，这是面试时的差异点，但也意味着可能得到负结果。
2. **分数提升可能来自择优偏差**：从多个带噪声的候选里挑最好的，即使每个候选都等价，开发集分数也会上升。Meta-Harness 的“只看分数”消融中位数仅 34.6，对比完整轨迹访问的 50.0，说明提议者读轨迹是关键信息来源，也说明需要专门的对照来排除噪声。
3. **收益常常集中在一处**：“Where Does Harness-Optimization Value Live?”说明整体不显著时，局部可能有真收益；反过来，整体显著也可能只由一个组件或一道离群题（write-compressor 就是前例）撑起。

## 3. 设计

### 3.1 可改动范围

只允许改框架文本层，不碰权限、沙箱、判分、校验逻辑：

- 系统提示（`src/aster/context/prompt.py` 的策略文本）。
- 工具说明（`src/aster/tools/schemas.py` 中的描述字段）。
- 完成门禁等处向模型显示的提示文本。

文本现在散落在多个 Python 文件的字符串里。阶段 0 要把它抽成一个单文件“框架配置”（类似 Meta-Harness 的单文件框架），提议者只能改这个文件，渲染结果与 v15-final 逐字节一致。

### 3.2 提议者

提议者就是 Aster 自己（以自身为优化器），在副本里运行：

- 可读：所有历史候选的配置、开发集分数、完整采样轨迹（以文件形式）。
- 不可读：留出集题目与结果、判分器、`docs/`、`evaluations/`、git 历史、项目记忆。其中 `docs/harness-v12.md` 等文件直接写着人工优化的结论，不隔离会把“自动发现”变成“抄答案”。
- 可写：只有框架配置文件。

### 3.3 种子与目标

主实验用**历史种子**：v15 的代码不变，文本层回退到人工优化之前的版本（提交 `8128866` 系统提示精简、`3e51777` 工具说明精简之前，另含 v14.2 的提示措辞改动）。这样有一个现成的已知答案——人工最终版 v15-final，循环的效果可以用“恢复了人工优化收益的多少”来标定，余地也比在 v15 上继续优化大。

阶段 0 要先验证这个回退可行（预算测试与缓存稳定性测试通过）；不可行则改用“最小通用提示”作种子，并在报告里注明。

最终版同样要与 v15-final 直接比较：持平写“追平人工”，显著更好才写“超过人工”。

### 3.4 优化目标与选择规则

通过率已接近饱和、开发集同配置波动约 ±2 题，所以不用通过率当主目标。规则在跑任何候选之前固定：

- 约束：成对比较下通过题数不低于种子减 1，同时“正常交付且通过”、`completed_with_warning` 占比不恶化（防止靠提前放弃降成本）。
- 目标：加权成本最小化。成本口径沿用历史：`(非缓存输入 × 1.25 + 缓存输入 × 0.125 + 输出 × 10) / 1e6`，美元等价估算，不是账单。
- 噪声门槛：种子在开发集重复跑 4 次，得到“同一份代码两次运行之差”的经验分布；候选的成对成本下降必须超过该分布的 90 分位数才算有效改动。
- 分级筛选：每个候选先在约 10 题的小集合上快速筛，达到成本下降且通过数不退才升级到完整开发集，并重复 2 次。
- 供应商异常：沿用既有协议，任一臂以 `provider_error` 结束的题，所有臂一起剔除并列明。

### 3.5 搜索规模

4 代，每代 2 个候选，共 8 个候选；每代只保留当前最优为下一代起点，所有候选（含被拒绝的）都归档，供提议者读取与事后审计。

## 4. 如何证明“迭代真的有效”

评审会问的问题，和我们分别用什么证据、什么对照来回答：

| 追问 | 证据与对照 | 阶段 |
| --- | --- | --- |
| 是不是只在开发集上过拟合 | 留出集在循环开始前冻结，提议者从未接触；留出集只在最后看一次，之后不再改动。清单先提交，再运行 | 1、5 |
| 是不是噪声或择优偏差 | 种子重复 4 次得到零假设分布，作为接受门槛；用同一份重复数据离线估计“8 个等价候选里挑最好”会虚增多少，对比开发集提升与留出集提升的落差 | 2、6 |
| 提升会不会只来自一道离群题 | 报告去掉成本占比最大一题后的结果，以及逐题的中位数效应 | 6 |
| 是不是靠提前放弃省钱 | 通过数、正常交付数、`completed_with_warning` 占比与种子同台报告 | 5 |
| 改进是否随代数单调 | 记录每一代在开发集上的曲线；留出集只测种子、终版、人工版三点，不逐代偷看 | 4、5 |
| 与人工优化相比如何 | 留出集上种子、进化终版、v15-final 同时段按题配对，各重复 2 次，成对自助法置信区间 | 5 |
| 是否依赖特定模型 | 第二个模型家族（官方 DeepSeek）上跑种子与终版各一次，不重新进化 | 5 |
| 提议者是否作弊或污染 | 配置文件之外的任何文件哈希必须不变；正则审计题目名、仓库名、测试名；提议者看不到留出集、判分器与 `docs/`；人工逐条审阅被接受的改动，特别检查是否削弱校验或权限相关措辞 | 3、6 |
| 搜索本身花了多少，何时回本 | 总成本包含提议者的 token；报告每题节省与回本所需任务数 | 6 |
| 哪个改动真正有用 | 被接受的改动不多（预期不超过 4 个），在留出集上逐个去掉做对比；只在整体效果为正时才做 | 6（可选） |

可选扩展，只有主结果为正才做，每个都要先报告成本再执行：

- **轨迹访问消融**：只给分数的提议者对完整轨迹提议者，同样规模的循环。回答“读轨迹是否必要”。
- **第二级对照**：给提议者一份可演化的指引与经验库（可复用 Aster 现有的记忆提炼与反馈机制），对比有无经验库时的接受率与每美元收益。这是能否称“递归”的唯一证据。

## 5. 阶段、检查点与回退

阶段顺序固定，上一阶段的门槛不过，不进下一阶段。所有操作在副本里执行，不直接在工作区运行评测。

分支 `exp/evolve-20261101`，基线标签 `evolve-base` 打在当前 `docs/sync-20261020` 的 HEAD。每个阶段一次提交加一个标签，不推送。

| 阶段 | 内容 | 门槛 | 标签 | 回退到上一阶段 |
| --- | --- | --- | --- | --- |
| 0 | 抽出单文件框架配置；渲染结果与 v15-final 逐字节一致；确认历史种子可行 | 全部既有测试、预算测试、缓存稳定性测试通过；渲染一致 | `evolve-s0` | `git reset --hard evolve-base` |
| 1 | 冻结评测：新抽留出集（与 old20、new30、fresh30、fresh30b 全部不重合）、开发集和约 10 题筛选子集；预检；写入协议与分析脚本（成对自助法、零假设分布、离群剔除） | 清单与协议先提交；预检通过；留出集题数足够 | `evolve-s1` | `git reset --hard evolve-s0` |
| 2 | 种子在开发集重复 4 次，固定零假设分布与接受门槛；估计最小可检出效应 | 若最小可检出成本变化大于 15%，先增加重复或换较弱模型，再继续 | `evolve-s2` | `git reset --hard evolve-s1` |
| 3 | 提议者与护栏：只写配置文件、哈希与泄漏检查、隔离目录、预算上限；一次不计分的冒烟测试，确认提议能产生合法补丁并测出提议者的 token 成本 | 冒烟测试通过；护栏对故意违规的补丁全部拒绝 | `evolve-s3` | `git reset --hard evolve-s2` |
| 4 | 运行进化循环，4 代；每个被接受的候选一个标签 `evolve-g1` 起；保存全部候选与轨迹 | 无新增代码改动；按预先写好的规则接受或拒绝 | `evolve-s4` | `git reset --hard evolve-s3` |
| 5 | 留出集最终比较：种子、终版、v15-final 各 2 次；第二模型各 1 次；运行后不再改任何东西 | 清单先于运行；其余同阶段 1 | `evolve-s5` | `git reset --hard evolve-s4` |
| 6 | 审计与报告：改动审阅、泄漏审计、离群分析、回本分析；可选扩展的决策 | 负结果也原样报告 | `evolve-s6` | `git reset --hard evolve-s5` |

## 6. 规模与成本

按用户“评测要精简”的要求，这是能回答问题的最小设计：一个模型做主实验、一份开发集、一份留出集，扩展项全部可选。

成本是推算，不是实测：

- 单位成本取自完成门禁消融（`evaluations/acceptance-ablation-20261020/REPORT.md`）：60 次题目执行折算约 3.43 美元等价，约 37 分钟墙钟，也就是 30 题一轮约 1.4 至 2.2 美元等价。
- 留出集：主模型 3 个臂各 2 轮，加第二模型 2 轮，共 8 轮。
- 开发集：种子 4 轮，候选最多 8 个、每个完整评测 2 轮，外加筛选，最坏约 23 轮。
- 提议者读取轨迹的 token 成本尚未测量，阶段 3 的冒烟测试才能给出数字，因此总预算要等阶段 3 之后才能确定，现在只能给量级。
- 供应商过载会造成重跑，上面没有计入。

## 7. 能得出与不能得出的结论

能得出：在冻结的留出集上，进化终版相对种子与人工版的配对差异及置信区间；进化改动的内容与来源；搜索成本与回本。

不能得出：对其他模型、其他任务分布的普遍收益（只有一次第二模型迁移检验）；“递归自我改进”（需要第二级对照）；改动的因果机制（需要可选的逐个去除）。

负结果的处理：若留出集上没有显著改进，如实写“自动循环在 N 代内未能超过种子”，这与完成门禁消融的做法一致，也是可以回答追问的结论。
