# Worker 交付与预算改造（2026-09-28）

本次在 `pre-worker-redesign-20260928`（`6998e08`）保存旧版。目标是让局部子任务产生可使用的交付，验证是否减少重复调查；不增加团队框架、训练流程、模型路由、服务或依赖。

## 实现范围

- 保留一个主 Runtime 和按需启动的子 Runtime。子任务不继承完整父历史，不再派生下级，长期记忆仍由父任务维护。
- 工具步达到上限后不直接丢弃交付机会；最后一次模型请求关闭工具，只交接已有发现。模型失败、取消等路径仍保存 `handoff.json`，明确标注部分结果，保留实际读取、修改和测试状态。
- 结果在父任务下一次模型请求前自动送达；显式 `worker_status` 已消费的结果不重复投递。待投递 ID 写入检查点；恢复可以消费已保存的交接，不恢复后台协程。
- `worker_message(resume=true)` 最多进行一次有界补问，沿用子任务上下文。检查父任务权限是否变化、剩余团队额度及并发名额。
- 所有父子请求、工具动作共用根任务的 `max_turns` / `max_steps`。子任务从剩余额度分配，单次最多 24 工具步和 12 模型调用，并为父任务保留约 20% 额度（调用/工具至少 2 次）。这是固定工程策略，不是学习出的最优分配器。
- `TaskSpec.max_tokens` 可选限制整队 token。请求前预留估算输入与最大输出，返回后用实际 usage 校正；缺失 usage 保留估算收费。运行中的预留也参与后续准入。它不是服务商账单的精确硬上限。
- 一个时刻只允许一个写入者。写 Worker 必须有范围；它运行时，父任务和其他子任务暂停写文件及进程工具，直到写入者交付或取消。静态读取仍可并行。没有独立 worktree 或自动合并。

`completed` 只表示子 Runtime 通过自己的完成门槛；`delivery=partial` 表示未完整交付。二者都不能代替父任务整合后的测试或独立评分。引用路径、摘要和模型结论依然是不可信观察。

子任务的观察档案留在自己的会话中，不放宽跨会话读取权限。父任务可按路径和符号核查当前文件，必要时补问子任务；不能把旧文件哈希当作当前工作区的读取凭证。

## 对照边界

三个条件均包含大文件编辑、Go 正式测试、工作区内 PYTHONPATH 命令的共同修复。它们的收益不归因于委派设计。

1. Solo：关闭 Worker。
2. Handoff only：保留旧 12 步 / 12 轮配置，只修无工具收尾和部分交接。
3. Redesigned：加入共享额度、自动投递、有限续问和单写入者。

同一模型、同一外部全队预算、同一独立评分器。原 20 题作为回归，另固定 6 道新题，数据保存在 `datasets`。全部结果包含失败，分别报告通过率、全队用量、耗时、交接与实际利用情况。详见 [评测协议](../evaluations/worker-redesign-20260928/PROTOCOL.md)。不把“报告非空”或主任务 token 减少当作协作收益。
