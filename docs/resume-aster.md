# Aster 简历条目（2026-10-20）

写法对齐作者另外两个项目条目：`项目简介` 一段讲清需求与问题，随后每条一个命名模块，先说设计再给量化结果，结果一律带对照基线。所有数字的出处见文末对照表，不写无法追溯的数字。

## 条目

**项目简介**：面向真实仓库的代码修改与验证需求，针对 Agent 耗时与成本不透明、执行环境不可控、评测结论容易过拟合的问题，独立设计并开发支持多协议接入、副本沙箱执行、检查点恢复与强化学习采样的 Coding Agent Harness。

**性能与成本**：分阶段计时定位到 63% 的任务耗时花在 harness 自身，根因是容器 overlayfs 上单次 fsync 88–225 ms、每步全仓重哈希与 O(n²) 日志追加；实现仿 git index 的增量快照、按内容寻址的任务基线与检查点组提交，单步开销降低 6.7–13 倍，模型之外的耗时下降 81%，加权成本较优化前降低 57%。

**上下文工程**：将内部证据记录与模型可见视图分离，完整结构化记录只用于审计、恢复与训练导出，模型只读渲染后的纯文本与必要游标，并精简工具定义与系统提示词（1,975→1,638、359→248 token）；在 GPT 与 DeepSeek 两个模型家族、两套题上按题配对，每请求输入下降 9.8%（置信区间 [−14.2%, −5.1%]），通过率不变。

**执行环境与验证语义**：命令在工作区副本中执行、校验后发布，用 Landlock/seccomp 限定可写路径与网络，并在每条命令前后守护 Landlock 不拦截的 chmod；既有失败改由运行时在原始代码上复跑测试、比对失败签名来判定，而不采信模型声明，追逐既有失败的轮次减少 47%。

**评测方法**：搭建隔离判分网络修正判分环境漂移（24 份历史补丁复判 24/24 一致），每次改动前先冻结新抽的留出集，同时段与 pi、Codex 按题配对并给出置信区间；最新留出集上通过 20/23（pi 21、Codex 20），每请求输入与成本均低于 Codex，成本已与 pi 相当（1.29 对 1.20）。完成门禁消融给出负结论：严格、默认、关闭三组同题通过数相同、补做仅 3/4/0 次，据此没有把它写成质量收益。

### 版面够的话可以加一条

**训练接口**：为 Qwen3.5 的 SFT/RL 实现 token 级采样轨迹：用策略自带 chat template 渲染 prompt 并以 token id 送入 vLLM，解析 hermes JSON 与 XML 两种工具调用，逐回合记录 token id、logprob 与 loss mask，prompt 不是上一轮的严格延长时自动切段，基础设施失败不计入梯度。（接口与离线测试已完成，尚未在 GPU 上实测，面试时要主动说明。）

## 写的时候回避了什么

- **不跨题集乘除**。「成本较优化前降低 57%」来自 new30，「成本与 pi 相当（1.29 对 1.20）」来自 fresh30b，两者不相乘推出「比优化前便宜 N 倍」。
- **不报 23/30**。早期 v12 在 new30 上是 23/30、与 pi 持平，但那之后 new30 已被用于开发，不再是留出集；条目只报最新一次冻结留出集上的同时段配对结果。
- **不把完成门禁写成收益**。消融没有测出质量提升，写成负结论反而经得起追问；它的用武之地是弱模型，这一点尚未验证。
- **成本口径要主动说明**：加权成本 =（未缓存输入 × 1.25 + 缓存输入 × 0.125 + 输出 × 10）/ 1e6，按公开价折算的美元等价估算，只用于相对比较，不是账单。15.2 节 GPT 那次有部分请求缺用量，表中按已知请求均值补齐；不补齐时 Aster 为 1.22。
