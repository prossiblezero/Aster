# 上下文预算：压缩效果、任务完成率与默认配置

2026-09-16。本轮选定的**压力评测输入预算为 8,192**：12 道主任务各用全新尝试运行 3 次，**36/36 完成，Pass@1 / Pass@3 均为 100%**。平均初始输入由 **18,434.83 压到 7,779.25 个本地估算 tokens，平均压缩 57.80%**。这组数可以用于简历，但限定为这 12 道开发题上的选参后确认，不表示通用任务都能无损压缩。

真实模型批次冻结在 `01638a7`，策略 `deterministic-v4`。随后审计发现并在 `4bb221b` 单独修复 checkpoint 对加密推理字段的误脱敏；它改变持久化和恢复校验，不改变本轮持续运行的上下文算法。下文真实成绩仍明确归属 `01638a7`，工程回归归属 `4bb221b`。

## 日常使用按模型窗口，评测主动制造压力

当前不再默认把 Luna 限制在几千或两万 tokens。按 [OpenAI 官方 Luna 规格](https://developers.openai.com/api/docs/models/gpt-5.6-luna)，总窗口为 1,050,000、最大输入 922,000、最大输出 128,000。自动输入额度是 `floor(min(最大输入, 总窗口 - 输出预留) × 0.95)`，默认 **875,900 输入 + 2,048 输出预留**；5% 是本地计量余量。达到上限前由 Runtime 每轮自动检查，不需要用户手工触发压缩，也不会为了填满容量而添加内容。

精确模型名称已登记才使用对应规格；当前登记了 `gpt-5.6-luna`。未知模型回退到 24,000 总额度并在 CLI/TUI 明示；网关额度更小可显式覆盖。兼容某种 API 格式不等于支持相同窗口。这里没有声称通过 API 自动发现了任意模型上限，也没有进行 1M 规模的真实任务实验。字段解释见[配置说明](configuration.md)。

8,192 是本轮**输入**预算，另预留 2,048 输出，所以实验总配置为 10,240；旧 `balanced` 是 8,192 **总额**，实际输入仅 6,144。两者不能混写。主任务的 24 次工具动作、16 次模型决策上限不变；控制题为 16 次动作、12 次决策。本轮没有重跑原来的充足或极紧模型条件。

## 压缩规则与本轮改动

已删除 `tool_output_tokens`。普通工具正文在全局空间足够时完整发送；先归档，再计量包含工具定义、协议包装、历史和状态的完整请求。超预算时先移出可删除的旧普通消息，再缩短旧工具结果或移出旧完整交互组，最后才缩短最近批次与可重建内容。工具调用及结果成组处理，编号、参数、执行状态和必需协议字段保持对应。

技能与计划分页按字符取页，只有全局压力下才缩短；游标跟随实际可见前缀调整。来源先整体脱敏再分页，避免跨页漏脱敏或偏移不一致。工具执行超时、输出采集大小与读取页大小仍保留各自的资源边界。详细代码与字段见[上下文预算](learning/06-context-budget.md)、[归档与分页](learning/07-context-archives.md)。没有增加 LLM 总结器或新依赖。

## 有限选择，然后重新确认

[方案](../datasets/context_budget_protocol.json) 在本轮模型运行前固定：先做原 6,144 输入的 39 次回归，再测试 8,192 / 10,240 / 12,288 三个候选，各 12 次。选择“至少 11/12 完成且平均首请求压缩至少 30%”的最小预算，然后用新批次确认，要求至少 33/36 完成且压缩至少 30%。确认完成后不再换档位、不选择性重跑失败；最终共 **114 次尝试**。

12 道主任务分四类，使用同一份 36 条代码、日志与中文模拟历史。平均 18,434.83 是**初始未压缩请求**的本地估计，包含当前任务和工具定义；不是整个任务累计 token，也不是模型真实执行了 36 轮才生成的历史。输入、初始仓库与隐藏评分器保持不变；全题 52 项、主任务候选 49 项数据依赖哈希精确核对。

## 同预算没有改善，不能将调参收益归给代码改动

## 一次性证据仍是边界

信息丢失控制不混入主任务。原 6,144 回归完成 **1/3**，其中一次调用归档读回；选定 8,192 的新确认是 **0/3**，三次均动作额度耗尽，隐藏功能也未通过，未调用归档读取。机制检查证明归档可以读回，不证明模型会自主选择并正确利用它。当前不能宣称解决了所有长程信息丢失，也不把控制题失败藏在主任务的 100% 后面。

## 这次实际改了什么

- 工具正文先脱敏归档，再按全局剩余预算保留首尾预览。裁剪后的结果携带原文引用，`observation_read` 提供当前运行内的字面检索与分页回读；完整的小结果不附加引用，该工具通过 `tool_load` 按需加载。
- 从已有 `RunState` 生成待办、修改路径、有效测试证据和剩余额度；没有增加第二套工作记忆或 LLM 总结器。
- 调用与结果以完整组压缩，保留调用编号、参数、真实状态和必需的推理元数据。内部历史、供应商请求、检查点与恢复共用配对校验；异常历史在发送请求前拒绝。
- 正常执行与外部策略环境共用 `Runtime.prepare_request()`，保存每次实际模型输入。归档丢失或损坏时明确停止，不先删除唯一原文。

逐段代码与字段解释见[上下文归档](learning/07-context-archives.md)。当前只外置执行器实际采集到的正文，无法恢复采集前已经截掉的日志。

## 实验怎样保持可比

沿用原来的 **12 道代码题 × 3 档预算 × 3 次尝试＝108 次**；一次性历史证据控制另跑 9 次，每个完整批次共 **117 次**。输入上限分别为 30,720、6,144、3,584 个本地估算 token。普通使用由默认预算自动管理，这三档是压力实验条件。

模型均为 GPT-5.6 Luna，使用 Responses，输出预留 2,048，固定动作与轮次上限、采样顺序和并发度。题目、长历史、初始文件与隐藏测试共 **52 个文件的 SHA-256** 与 v5 一致；不改评分、不扩大动作预算，也不只重跑失败样本。

|---|---|---|

## 归档能读到，不等于模型会去读

一次性证据控制的充足／中等／极紧结果：v5 为 **3/3、0/3、0/3**，v6 为 **3/3、1/3、0/3**，v7 为 **3/3、0/3、0/3**。原题与评分器不变。

v6 的一次中等预算成功运行确实查询了归档并找回旧证据，也保留了复制错编号被拒的记录。v7 全部 117 次 **没有调用 `observation_read`**；中等预算控制题三次都未完成。按需加载降低了常规请求的开销，却没有在这一小样本里展示稳定的自主回读收益，不能把 v6 的单个成功案例当作当前版本的成功率。

工程检查已经覆盖归档完整性、越权拒绝、损坏停止、裁剪后分页和恢复后回读；它们证明接口和边界可用，不能替代真实模型的发现、选择与利用。归档设计保留为已实现能力，本轮不宣称“解决了长程信息丢失”，也不以当前结果宣布所有上下文问题都已解决、可直接冻结为后训练基线。
