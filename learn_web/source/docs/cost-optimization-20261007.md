# Aster 一日降耗：先减少无效往返，再处理重复记忆

2026-10-07。用户授权在一天内自行调研、设计、实施并评测。沿用轻量、默认自动学习、约十题对照的约束；本方案先于生产代码修改落盘。

## 诊断与取舍

上一轮后台整理版的 22 个会话已报告 1,507,260 tokens，其中维护 117,263，主任务 1,389,997。维护约占 7.8%，只关闭维护不能解释或解决主任务开销。主任务有 153 次已报告用量的尝试：未缓存输入 491,593，缓存输入 866,816，输出 31,588。维护对应 84,702、27,648、4,913。用量缺失仍保留为未知，不当作零。

轨迹中有可直接解释的额外往返：把临时验证脚本写入 `.tmp` 后，该文件不进入下一次隔离测试的副本，导致找不到文件、重新写测试再执行；还有先跑裸断言、随后再补正式验证的情况。预算收尾会清空工具定义；虽然禁止执行是必要的，修改工具前缀并非禁止执行的必要条件。后台按 run ID 防重复，但新会话重复确认同一材料仍会再请求模型。

最小路径是修正文档、提醒模型避免上述用法。本轮增加一个小型工具能力，让一次 `run_tests` 调用直接携带临时测试源码，并沿用隔离执行及结构化测试报告；同时保留父任务收尾的工具定义，在执行入口继续禁止工具。这比新增摘要代理、模型路由器或压缩服务更贴近已观察到的费用来源。

## 本次补读的研究与实现

以下五篇为 2026 年 arXiv 预印本，本次未核实会议接收，不标作 CCF-A 会议论文。读取方法正文，不将作者的降耗数字套用到 Aster。来源 URL、响应哈希及失败访问见 `evaluations/memory-cost-20261007/research-sources.json`。

| 来源、阅读范围 | 机制与本轮判断 |
|---|---|
| [LeanMem](https://arxiv.org/html/2608.03463)，§3.2–3.4 | 区分可压缩的稳定属性、动态事件和需保留原文的记录，仅对事件做延迟局部整理。语义路由本身仍需模型调用；Aster 只采用确定重复材料免处理，不增加一次分类调用，也不靠关键词丢弃可能有价值的约定。 |
| [Dual-Layer Agentic Memory](https://arxiv.org/html/2608.22215)，§3.3–3.4 | 小模型路由、不确定时升级、慢阶段写回参数；需要模型隐藏状态、训练决策头及权重更新。它支持把维护成本纳入决策，但这些依赖不适合 Aster 的一天范围。 |
| [An Empirical Cost Attribution of Context-Compression Gateways](https://arxiv.org/html/2609.22114)，§2–3、§5 | 总费用取决于调用轮数及缓存计价；删除便宜的已缓存 token，可能不如减少一次往返。工具筛选收益依赖原始工具库规模，Aster 已按需加载，不能照抄其大规模 MCP 场景收益。 |
| [CADOC](https://arxiv.org/html/2609.37012)，§2–3 | 保留原始对象，批量替换可回读卡片；调度比较缓存重建代价与延迟压缩代价。支持保持已有前缀，不逐轮重写历史；其成本模型需要缓存价格权重，不直接植入一个缺少真实计价信息的调度器。 |
| [DTOC](https://arxiv.org/html/2609.26121)，§3.2–3.3 | 模型通过 enable/disable 控制工具结果可见性，原文仍可恢复。Aster 已有观察归档，本轮不再加管理工具和决策轮数；费用收益应包含回读成本。 |

源码与官方说明的核对：

- [pi 的 compaction.ts](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/src/core/compaction/compaction.ts) 从最近一次真实 usage 加尾部估算计算上下文，重写历史后使旧估计失效；`system-prompt.ts` 按实际工具生成短指导。Aster 当前估算会计入加密 reasoning 的序列化长度，可能偏高；本轮保留原始不透明记录，不以删字段冒充省费。
- [LightMem 的 lightmem.py](https://github.com/zjunlp/LightMem/blob/main/src/lightmem/memory/lightmem.py) 通过 buffer/force_extract 决定提炼时机，并显式核算 extraction/update/embedding 调用。与上一轮读取的源码哈希相同；本轮不把已采用的批处理再说成新机制。
- [Codex memories README](https://github.com/openai/codex/blob/main/codex-rs/memories/README.md) 描述整理工作区没有变化即跳过第二阶段。本次 API 限流，若干旧源码路径 404；这里仅按当前仓库说明引用，不声称读到了本轮 phase2 实现。Aster 使用现有审计记录上的输入指纹，不引入它的数据库或任务平台。
- [Claude Code 当前缓存文档](https://code.claude.com/docs/en/prompt-caching) 说明工具定义变化会失效缓存，某些工具暂时断连时保留定义、调用时返回错误。借鉴到父任务预算收尾：保留定义与禁止执行可以同时成立。此次不依据历史非官方源码推断当前内部实现。

## 实施方案

1. **临时测试随调用提交。** `run_tests` 增加可选 `code`，只用于 pytest 或非 discover 的 unittest；测试源码写入已有隔离副本，执行后不污染项目。已有项目测试按原入口运行。真正执行的测试数、失败、跳过、来源版本、只读限制仍由现有报告机制判断，打印“通过”不算验证。
2. **减少小任务的流程开销。** 静态指导明确单项改动从指定文件开始；实现与对应验证是同一项交付，不强制生成 todo。支持测试代码随调用时优先使用该入口；不取消必要的边界验证、用户指定的测试或长期回归测试文件。
3. **父任务收尾保留工具前缀。** 普通父任务进入最终答复时保留已暴露定义；原有 `handoff_only` 执行门禁继续生效。忽略收尾提示仍调用工具的模型，得到阻止结果并停止，不续跑。子任务保留既有交接方式，避免扩大改动面。
4. **相同材料免重复整理。** 用选中证据的内容、日期、工作区指纹和提炼契约生成指纹；只有已有成功整理、没有候选拒绝、当前记忆内容版本相同，才跳过新会话的相同输入。检测到中英文相对时间表达时保留完整时间戳，宁可少跳过；这不是通用时间理解器。记忆被更正、文件变化、日期变化、失败或取消过的整理都重新处理。跳过有审计事件，不冒充新增保存。移除后台输入里的助手答案摘要，它不是事实来源；保留真实用户、文件和失败/通过证据。

预计改动六个生产文件：`tools/schemas.py`、`tools/workspace.py`、`tools/testing.py`、`context/prompt.py`、`core/runtime.py`、`knowledge/maintenance.py`；加上验证和交付材料会超过八个文件。无新增运行依赖、服务、配置开关或模型账户。使用已有 `.env` 的模型和凭据，凭据不进入产物。记忆默认开启，文件格式向后兼容；回退代码不要求迁移或删除记忆。

关键假设是工具往返和重复整理在真实任务中可被减少。若模型不采用临时测试入口，或工具目录保留导致最终输出质量下降，机制存在并不证明降耗；必须以一次对照的真实执行结果决定是否保留。临时测试不会成为仓库的长期回归资产，需持续维护的测试仍应写入项目。

## 验证与费用口径

- 修改前冻结当前工作树生产源码为 `baseline-sources.zip`；不是上一轮有缺陷的中途版本。
- 十题沿用已有任务与独立功能断言，在时区约定、文档归纳两题额外原样重复一次学习输入，检验重复整理；两组完全相同。两组各 24 个会话，各运行一次，失败不补跑覆盖。新题库变化记录在运行前协议，不与旧轮 22 会话总量混比。
- 先跑与上述修改相关的本地机制检查：临时测试实际导入、失败和伪造通过、只读隔离，重复整理与更正/文件/日期失效，父任务收尾不执行工具及前缀稳定。整组结束再运行现有工程检查，不做多组参数搜索。
- 质量报告正常完成且独立验收通过、30 条行为断言、实际保存及后续召回。费用分别报告未缓存输入、缓存输入、输出、维护调用、模型往返、用量覆盖和 pending 数量，不把延期或取消算免费。
- 费用下降优先看三个计价分量是否同时下降；供应商真实单价未知时不报美元。补充 `未缓存输入 + r × 缓存输入 + q × 输出` 的明示权重比较，`r=0.1/0.25/1`、`q=1/4/8`，全部展示，不挑有利权重。这是敏感性分析，不是真实账单。
- 目标是质量不低于当前版本，同时降低完整任务的已报告费用分量；期望至少约 15% 改善，但不把期望写成结论。失败或覆盖不足均如实报告。
- 完成后同步本页、评测报告、相关教学文档、网站和简历；简历只采用有证据、口径清楚的结果，不提交或推送代码。

## 实施结果与交付

六个生产文件完成改动，正式版本通过 1206 项工程检查，4 项因缺少 Go 跳过。十题两版各一次、共 48 会话的[完整报告](../evaluations/memory-cost-20261007/REPORT.md)显示：已报告总 token −39.9%，后续任务 −45.9%，工具调用 −35.4%；未缓存输入、缓存输入、输出均减少。正常完成且通过同为 9/10，功能断言为 30/30 → 27/30，因此没有宣称全部质量指标不下降。

新增遗漏来自 CSV 约定提炼时把“本轮确认”写入适用范围，被临时信息准入拒绝。交付版只增加一句指令澄清适用范围，54 项相关检查通过，并对该题两轮学习和后续实现单独补查，3/3 独立断言通过；原始失败仍留在主表。没有扩大为第二轮全组实验。

缓存输入占比 61.26% → 59.17%，未缓存输入减少 36.8%。固定规则、任务及历史继续排在动态记忆之前；保护前缀不等于保证服务端命中比例提升。正式新版请求副本在临时目录消失后未能完整归档，该证据缺口与可复算的供应商 usage 分开说明；最终单题补查的已归档请求确认前缀稳定。

研发中止候选和单题补查消耗单列，全部已报告模型实验消耗 3,181,015 tokens。供应商单价未知、两组存在用量缺失，报告展示全部九种费用权重而不声称实际账单降幅。教学文档、网站与简历采用这组自己的统计范围，旧报告数据不覆盖。
