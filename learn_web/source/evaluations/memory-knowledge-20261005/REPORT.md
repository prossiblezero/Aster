# Aster 知识记忆：十题开发对照

日期：2026-10-05。调研取舍与最终实现见[设计说明](../../docs/memory-knowledge-design.md)。本轮沿用本地 JSON、已有检索和 Dream，将记忆从文件原文扩展为带出处和适用范围的知识；没有引入运行依赖、向量服务、独立反思模型或自动技能生成器。

主对照中，复用阶段严格成功由 **4/10 提高到 7/10**，独立约束通过由 **17/30 提高到 25/30**；学习与复用总 token **增加 1.7%**。收益主要来自原来无法直接保存的用户口头约定。它是一组已用于开发的针对性任务，不是公开 benchmark、独立保留集或统计显著性结论。

时区、CSV 与两种输出范围的约定在新版中确实写入并在新会话召回，三个案例均通过功能断言；其中 CSV 在交付前被预算挡住，严格成功仍记为失败。金额与用户纠正题两版都失败，模型曾口头承诺记住却没有保存。新版支付题的学习阶段因分类、过期引用和摘录行号问题反复尝试写入，最终耗尽预算；复用阶段依然可凭保留的代码完成，所以全流程成功只有 6/10，不能只看 7/10。

第 10 题两组都存储、召回了“用法语写项目叙述”的约定，代码测试没有验证这条约定。旧版增加一次成功使用，新版保持零计分；它验证了避免连带奖惩的一个实例，不等于准确识别所有因果贡献。两组复用阶段均未出现 `tests_failed`，不能据此宣称减少了重复测试错误。

逐题结果见 [summary.json](summary.json)；对应目录保留学习、复用、最终代码和压缩 trace。真实供应商请求 usage 覆盖为 **187/187 与 193/193**，逐条累计与上表一致。原始 `model_requests` 实际按 Runtime 回合计数，分别多含 2 次在本地被 token 预算拒绝的回合，因此原始 coverage 标记为 false；保留该字段，另列 `provider_usage_complete`，没有把缺报请求记为零。

## 比较方式

固定 [10 个针对性任务](cases.py)，每题先学习，再开启全新 Runtime 完成相关编码任务；用户纠正题多一次学习，共每版本 21 个会话、两版 42 个会话。学习阶段明确要求记住，记忆由模型自己写入；原文件、学习阶段代码和自行创建的笔记都继续可读，旧版也可自行记笔记。这里测的是定向学习后的跨会话使用，不是自然任务流的自主学习率。

两版均使用 `gpt-5.6-luna`、Responses、32,768 上下文、4,096 输出预留；每会话最多 30 个工具步骤、20 个模型回合、200,000 token、480 秒。启用 memory/evolution/Dream，关闭 workers，工具采用 core 按需加载。参数与全部源码哈希在 `results/{baseline,knowledge}/environment.json`。两组使用相同参数，每题每组一次，没有模型裁判、参数网格或挑选最好尝试。

“严格成功”预先定义为**复用阶段完成交付且独立行为断言全部通过**；另列纯功能通过与学习、复用均完成的全流程通过。每题三项断言，共 30 项：这是为本项目定义的约束满足率，不冒充公开 benchmark 分数。断言在 Agent 看不到的独立沙箱运行，但与候选使用同一 Python 解释器，不宣称对抗恶意候选隔离。

token 使用供应商返回的 usage，包含学习、失败尝试和后续复用；不把缺报当零，也不把总 token 直接换算成费用。公开检验与独立断言分别统计：Aster 自测通过可能仍违反用户约定。

## 两个针对性补查

主比较冻结后，只复用第 2、7 题检查实际发现的问题，见 [followup.py](followup.py) 和 [补查协议](followup/protocol.json)。补查使用自己的源码、工作区和结果，不替换主表。

金额约定题仍然失败：虽然提示明确了用户知识的写入方式，模型仍只口头说“已记住”，实际没有写入。不能声称提示修改已可靠解决主动保存问题。

支付修复题去掉“记住”要求，但要求先运行现有测试。实际从 3 项失败修复到 3 项通过，触发一次提炼提示，模型调用 `memory_store` 成功保存一条 `procedure`，联合引用失败、通过两个事件，最终回复说明了原因、修复和真实保存结果。全新会话召回这条经验，退款任务通过 3/3 独立断言。学习 / 复用分别为 61,523 / 51,372 token；原代码仍可读，因此这只证明流程在该案例跑通，不能单独证明记忆造成成功或提高了总体成功率。

补查的两题四会话合计 297,127 token，全部请求用量完整。另保留 [6 个原型或中断会话的成本](interrupted/accounting.json)，供应商已报告 308,572 token；中断中的未完成请求可能没有完整 usage。这些成本不并入固定主对照，也没有隐去或记为零。

## 版本与交付

- [sources.zip](sources.zip) / [change.patch](change.patch)：主对照的旧版、新版源码。旧版来自本轮修改前的工作区，包含用户已有改动，不直接拿 Git HEAD 充当基线。
- [followup/sources.zip](followup/sources.zip) / [补查差异](followup/change-from-main.patch)：加入明确保存提示、一次可跳过的修复经验提醒，并允许真实执行错误作为方法来源。`prompt-fix.patch` 只是未单独运行的中间草稿。
- [delivery-sources.zip](delivery-sources.zip) / [交付差异](delivery-change.patch)：最终代码还让事实、方法共享执行证据准入，并给来源过期、错误摘录等情况返回修正提示。该修正通过相关契约测试，没有再开一轮模型比较；不能把主表数字当成最终源码的重复测量。

最终生产改动涉及五个文件，相对本轮前工作区净增 89 行。记忆仍最多 64 条，每条正文最多 1,000 字符，适用条件最多 200 字符。错误提炼仅在开启记忆与自进化后运行，每个主任务最多提示一次，不强制存储，也不新增完成门槛。词面召回、归纳质量和实际应用条目的选择仍依赖模型；来源认证证明观察真实，不证明归纳一定正确。

回归：核心改造时全套 **1,171 passed / 4 skipped**；末轮记忆相关测试 **86 passed**，小上下文与发现测试 **23 passed**（其中 4 项与前者重叠），涵盖真实执行错误引用、提醒只触发一次、关闭自进化不提醒、用户纠正、过期和伪造来源拒绝、仅应用条目获得反馈。末轮没有再次运行整套测试。同步教学页后 **6 项网站检查通过**，Ruff 与差异空白检查通过。

## 复算

已有结果的指标可直接复算，不消耗模型调用：

```bash
python evaluations/memory-knowledge-20261005/summarize.py
```

如需新一轮复现，将 `sources.zip` 解压到独立目录，分别设置 `PYTHONPATH` 到 `baseline/src`、`knowledge/src`，调用 `run.py --arm baseline|knowledge --work 新目录 --output 新结果目录`。驱动会校验源码及题目哈希；不要覆盖当前结果。实际模型调用需要本地配置的服务，凭据未进入归档。
