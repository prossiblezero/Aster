基线为本轮开始时的生产工作树，已包含上一轮交付后的修正，不是旧报告中途的冻结版。`baseline-sources.zip` 和 `baseline-source.json` 先于新改动生成。修改版在机制检查通过后另行冻结，两组运行中不修改各自源码。所有生产文件哈希写入 environment.json。

十道开发题沿用上一轮 `cases.py`，保留原始独立断言和预算；仅在 01 时区约定与 05 文档归纳题各原样增加一次学习请求，测试现实中的重复确认或重复阅读。两组各 24 个会话，共 48 个。不是新的公开 benchmark，也不能与上一轮 22 会话的总费用直接混比。

每组每题运行一次，不调参或覆盖失败结果。若中断，只能继续尚未完成的部分；已完成结果保留。代码产物、所有阶段用量、压缩 trace、维护 pending/jobs/state、源码和运行器哈希都归档。评测断言只在隔离副本执行，不进入模型上下文。基线与新版各一个顺序进程并行运行，使用独立工作区；记录服务失败及缓存波动的比较限制。

质量：正常完成且独立验收通过的任务数、功能通过任务数、30 条行为断言、实际保存与召回、临时标签是否误入知识。保留未完成和失败题。费用：按供应商已报告的未缓存输入、缓存输入、输出分别汇总；前台/维护分开并与总数核对。空操作、拒绝和失败有用量则计入；未知取消消耗不记零，pending 单列，不把延迟处理算作节省。

补充费用指标为 `U + r*C + q*O`，其中 U 是未缓存输入，C 是缓存输入，O 是输出。展示 r=0.1/0.25/1 与 q=1/4/8 的全部九个组合；不是模型参数实验，不产生额外调用，也不等于真实币种费用。若三个分量全部减少，任何相同的非负分层价格都支持“已报告部分费用下降”；供应商用量缺失仍限制完整账单结论。

实施设计与研究依据：[cost-optimization-20261007.md](../../docs/cost-optimization-20261007.md)。观察目标为质量不低于当前版，并降低费用；约 15% 降幅是期望，不是已实现的结论。

## 正式修改版运行前的工程修正

第一份候选与基线并行启动后，完整工程检查发现小上下文容不下新增工具说明，以及子任务触及工具预算后提前停止的回归。候选因此中止，已运行结果、检查失败、源码及未完成会话的原始工作区保存在 `prototype/`；不覆盖，也不计入正式对照的成绩。精简工具说明并修正“本次请求是否已经进入收尾”的判断后，通过相关检查再冻结正式修改版。基线不重跑，修改版只对修正后的版本运行一次。额外候选消耗单列为研发成本；不是从多组成绩中挑最好的一组。
