# 轻量子会话：显式调查与审查评测

**实现已完成；这组数据支持子任务可以正常运行、分担主代理输入，不支持它比单代理更省、更快或更容易完成整题。** 并行组与 Solo 的严格通过数同为 5/12；事后忽略引用位置的完整行为通过数也同为 10/12。并行组主代理累计输入减少 **35.4%**，但全队已报告 token 为 Solo 的 **2.50 倍**，端到端耗时总和为 **2.39 倍**。保留用户主动使用的只读子会话，模型自主派工继续默认关闭。

实现复用原有 Runtime、WorkerManager 和会话树，增加点击启动、查看、续问、取消和重启后恢复。生产代码净增 **351 行（3.1%）**、一个 UI 模块，零新依赖，新增七个测试情景；详情见 [实现与离线验证](VERIFICATION.md)。这次没有创建另一套多 Agent 执行引擎。

## 样本与版本

- **6 题 × 3 组 × 2 次独立 pass@1 = 36 次运行，已全部完成**。两次结果均保留，不是 pass@2，没有挑选成功重跑。
- 三个来源快照：Django（原 SWE-bench Verified 缓存）、OpenLibrary（原 SWE-bench Pro 缓存）、Terminal-Bench session-window。每个快照各编一题调查和一题受限改动审查，题目在 `datasets/subagent-light-20260930`。
- 这是 Aster 编制的**给定探针的行为推断与受限改动审查**，不是原 benchmark 的修复题、开放式缺陷发现或官方分数，也不是独立 holdout。相同快照的调查与审查存在相关性，不应当作 36 个独立代码项目。
- 每题两个明确给定的独立工作包、八条可执行行为验收。三组都看到完整问题和相同 JSON 交付格式；Solo 直接处理，Serial/Parallel 明确启动两个真实只读子 Runtime，再由真实父 Runtime 整合。两种委派组只改变子任务的调度顺序；未评测模型自主拆分任务。
- 同一 GPT 配置，协议 Responses；成功响应报告的模型名为 `gpt-5.6-luna`。失败尝试可能没有模型名或 usage。全队上限：36 次模型请求、60 次工具调用、300,000 已报告 token、600 秒；子任务分配固定为初始 24 工具/14 轮，团队准入与父方预算保留规则仍生效。各组读取工具并行度为 1，持久记忆关闭。
- 真实模型运行固定在 **`cc43d32b68b724e58decb3a1ae04b6a1bddc222a`**。完成全部运行后合入 **`c12092c`**，修复历史父分支引用未来子消息/观察的问题。该修复有全量离线与 wheel 验证；本表不是最终修复提交的付费重跑。修复增加了快照持久化操作，不能声称其耗时与冻结版完全相同。

冻结方案见 [PROTOCOL.md](PROTOCOL.md)，环境、源码及数据哈希见 [FREEZE.json](FREEZE.json)。离线预检包含 48 个行为验收点和 24 个评分负例。公开任务工作区不含 oracle、答案或旧 benchmark 解答。

## 事前冻结的主要结果

严格通过要求八条行为值均正确、审查分类正确、引用路径/符号/行号通过检查、请求 ID 完整且无重复，父运行正常完成，源码和工作区未改变。引用检查验证 AST 位置，不自动证明说明文字或引用的语义正确。

| 组别 | 严格整题通过 | 严格事实正确 | 全部 12 次耗时合计 | 已报告全队 token | 主代理累计输入 token | 子任务正常交付 |
|---|---:|---:|---:|---:|---:|---:|
| Solo | 5/12（41.7%） | 67/96（69.8%） | 958.6 秒 | 603,004 | 575,934 | — |
| Serial | 3/12（25.0%） | 75/96（78.1%） | 3,132.1 秒 | 1,509,985 | 459,027 | 24/24 |

三组单回合耗时中位数依次为 63.5 / 247.0 / 178.5 秒。并行对 Solo 的严格配对结果为 **5 胜、5 负、2 平**；并行对串行为 **5 胜、3 负、4 平**。相同通过数量并不意味着通过的是同一批回合。

审查每组含 24 个回归与 24 个未改变控制点。包含行为值和引用要求的严格回归命中为 **22/24、22/24、21/24**，误报均为 **0/24**；单看布尔回归分类，三组均正确。不能将引用或输出格式差异解释成发现缺陷能力的提升。

## 事后错误归因：保留主成绩

下表仅解释既有评分字段，不修改回答、不修补 JSON、不重跑模型。行为诊断暂时忽略引用位置，但仍要求所有 ID 完整、无重复、执行正常、工作区不变。

| 组别 | 行为与分类正确的事实 | 行为完整通过 | 仅引用失败 | 实际值不符 | JSON 无法解析的回合 |
|---|---:|---:|---:|---:|---:|
| Solo | 87/96 | 10/12 | 20 | 1 | 1 |
| Serial | 94/96 | 10/12 | 19 | 2 | 0 |
| Parallel | 94/96 | 10/12 | 12 | 2 | 0 |

三组审查分类错误均为 0。Solo 有 8 条因一份 JSON 无法解析而不能逐条诊断，不应称为八条行为理解错误。实际值不符与分类错误在一般情况下可以重叠；本表不将这些数量相加替代主得分。

例如首次 Django 审查，Solo / Serial / Parallel 的严格得分是 3 / 7 / 8，但行为与分类均为 8/8；差异完全来自引用位置。首次 OpenLibrary 单代理调查严格 0/8，行为也全部正确。这些例子说明严格分数高度受引用格式影响。并行严格事实率较高，尚不足以证明更强的代码理解。

## 耗时、总消耗与主代理输入

相同任务和重复编号配对，以下比值为 **Parallel / 对照组** 的逐对中位数，而非两组中位数之比。小于 1 表示并行组更少。

| 选入条件 | 对 Solo 的配对数 | 耗时比 / 已知 token 比 | 对 Serial 的配对数 | 耗时比 / 已知 token 比 |
|---|---:|---:|---:|---:|
| 全部配对（主比较） | 12 | 2.573 / 2.762 | 12 | 0.694 / 1.055 |
| 两边均严格通过 | 0 | — | 0 | — |
| 两边均行为诊断通过（事后） | 9 | 2.313 / 2.656 | 10 | 0.694 / 1.027 |
| 两边均无 HTTP 重试（事后） | 5 | 1.696 / 2.656 | 4 | 0.752 / 0.861 |
| 两边均行为通过且无重试（事后） | 4 | 1.475 / 2.762 | 4 | 0.752 / 0.861 |

并行相对串行的配对耗时中位数减少 **30.6%**；无重试的四个配对减少 **24.8%**，可作为这组显式分工中调度生效的局部证据。但两边均严格通过的配对为零，事后子集很小，不能据此宣称等质量的普遍加速。相对 Solo，即使只看行为均正确且无重试的四对，并行仍更慢且消耗更多。

Parallel 主代理累计输入减少 **35.4%**，单回合主请求峰值输入的中位数从 **15,389** 降为 **13,891（减少 9.7%）**。累计输入会反复计算请求携带的历史，既不是持久上下文大小，也不是总成本。全队模型请求为 Solo / Serial / Parallel **50 / 139 / 139 次**，工具调用为 **140 / 266 / 290 次**。父方仍有读取与整合：Serial 的 69 次父 read_file 中 68 次路径被子任务读取过，Parallel 为 64 次中的 62 次；按路径重叠计数不意味着读了同一行段，但不能把父方核查开销隐藏掉。

全部正常交付的子任务为 **48/48**，轨迹确认 48 份交付都进入父请求边界。运行器异常、源码/工作区变动、已知 usage 对账不一致均为 **0**。此处的正常交付只指生命周期与产物存在，不是正确性通过，也不能和旧评测中不同任务的子任务完成率直接作提升比较。

## 重试与成本边界

Solo / Serial / Parallel 分别有 **2 / 7 / 9 次 HTTP 尝试缺少总 token usage**，涉及有重试的回合 **2 / 4 / 6 个**。所有回合保留在主表，三个组累计已报告 token 为 **3,620,421**；未知 usage 不能按免费处理。本次没有固定服务计价表，也有缓存输入差异，所以不估算金额。

首次 Django 串行调查耗时 514.19 秒，其中三次 transport 失败的尝试耗时合计 257.39 秒且无 usage。保留该回合，并用对两边对称的无重试子集检查敏感性；不直接从 wall time 减去失败请求耗时，因为并行请求可能重叠。已知 usage 一致只说明两套记录对得上，不代表供应商账单完整。

## 使用判断与复算

现在可以从 TUI「子任务」或 `/agents` 明确派出只读调查，检查进展和结果，再沿独立历史追问或取消；重启后查看固定历史快照，明确续问才恢复执行。默认最多两个显式子任务，共享原任务的剩余预算。这个功能的价值首先是用户可控的并行调查和独立上下文；续问、取消、恢复、分支隔离由离线交互测试验证，不能从本次模型分数推断 UX 节省了多少操作。

本轮可引用的描述是“实现轻量、可恢复的显式子会话，48 个真实子任务正常交付，主代理累计输入减少 35.4%”；若报告该输入指标，必须同时说明全队已知 token 约增加 150%、整题通过未提升。**不建议写成提高任务通过率、降低总成本或相对单代理加速。** 继续以单代理为默认，将子任务留给用户确实需要独立调查或审查的场景。

旧 [十题两次的 Worker 评测](../worker-owned-20260930/REPORT.md)保持原样；本次没有替换那些负面结果，也没有将这六题包装成更广泛的代码能力基准。

机器可读结果：`results.json`（全部 36 次结果）、`summary.json`、`pairs.json`、`diagnostics.json`。保留本地 `artifacts/private/subagent-light-20260930/` 的请求账本和轨迹，可以在 Conda aster 中运行：


`summarize.py` 按冻结口径复算，同时会覆盖 REPORT.md 为英文基础表；本中文解释请通过 Git 保留。`diagnose.py` 是事后诊断脚本，按冻结提交校验历史源码，支持在合入恢复修复后复算。公开聚合数据不含 API 密钥；原始请求记录仍保存在本地。
