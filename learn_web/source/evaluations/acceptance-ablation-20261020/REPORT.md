# GPT × fresh30b：验收门禁对照（2026-10-20）

**本轮没有显示关闭验收能降低成本，建议继续保留产品默认验收。** 三组共同可比的 14 题均通过 13 题；关闭组比默认组多 14 次请求（+13.3%），已知用量折算费用高 6.5%。这是单次开发集对照，样本受供应商异常影响较大，不能据此宣称稳定排名或因果收益。

严格组复用 `fin-fresh30b-gpt-v15`。本次新增产品默认、关闭验收各 30 题，共 60 次题目执行、539 次模型 HTTP 请求；执行与判分同时进行，用时约 **37 分钟**（北京时间 16:50:18–17:27:20，不含准备及汇总）。关闭组约 28 分钟完成。所有 60 题均完成独立判分，未追加付费冒烟或失败重跑。

费用按历史相同权重计算：`(非缓存输入 × 1.25 + 缓存输入 × 0.125 + 输出 × 10) / 1e6`，单位为美元等价估算，**不是实际账单**。本次两组合计已知费用为 3.428267，90 次请求没有用量，不能视为免费，也未按平均值外推补齐。本报告先合计 token 再算费用，与逐题费用先保留六位小数再相加的旧汇总会有百万分之几的舍入差。

任务耗时是各题 agent 进程运行时间之和，包含等待模型、工具执行等；它不是并行运行的墙钟时间，也不包含独立判分时间。模型超时、中断以及更早失败会影响这个指标。

## 为什么不能把全表的成本下降都算作门禁收益

`terminal-write-compressor` 在严格组花了 61 次请求、0.487090 的已知费用；默认组、关闭组都因供应商错误提前结束，分别只有 6 次 / 0.034337、8 次 / 0.018608。

- 默认组全表仅少 0.145067，但压缩器一题就少了 0.452753；其余 29 题的已知费用合计反而多 0.307686。原始总成本下降不能作为默认验收降本的证据。
- 关闭组全表少 0.763151，其中压缩器一题占约 **61.4%**；其余任务也包含供应商提前中断。

内部要求补做的 `final_revisions` 在严格组累计只有 3 次；默认组可读取终态的 29 题累计 4 次，关闭组为 0。默认组另 1 题超时未写出终态，这里的补做次数、回合及步骤统计只包括已有终态的任务，未知值没有填作 0。最终验收补做次数本就很少，关闭这一步没有在本轮带来更少的同题请求。

## 配置与默认规则的发现

三组都固定到 `v15-rc3`，提交 `ce2b79e135492276996d19bdd850dfa07dcd781c`。源码、题目及顺序、模型参数、每题预算、评分器和容器资源均相同；新增两组同时启动，各并行 3 题，总并行 6 题。

产品默认仍然是 `completion=strict`，区别在于不再显式强制每题 `require_edit=True, require_verification=True`，而是让产品按提示推断要求。实际提示下，8 道仓库题和 10 道 Aider 题仍要求测试；10 道 BigCodeBench 和 2 道终端题不强制测试。前 18 题的有效验收要求与历史严格组相同，其运行差异不能直接归因于“放宽了验收”。关闭组沿用相同的推断结果，仅设置 `completion=off`。

另发现一个现有产品缺陷：`bigcodebench-966` 中的“without changing existing values to NaN”会命中 `Verifier.infer()` 的 `without changing` 否定词，使默认模式推断为 `require_edit=False`。它表达的是算法行为，而不是禁止修改代码。本轮保留原行为以完成真实默认配置对照，未在评测中途修改产品；后续若修复，应为这个语义误判单独验证。
