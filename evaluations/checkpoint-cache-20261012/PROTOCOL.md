# 检查点与缓存优化：事先登记

2026-10-12。当前生产代码在修改前冻结为 baseline。本轮 candidate 仅改变不可变差异基线持久化、同一次检查点快照复用，以及 Responses 请求缓存标识；保持自动记忆、验收、隔离、模型及用量回执。

## 本地与短探针

- 先运行恢复、分支、便携复制、旧格式、缺失/篡改引用、凭据脱敏、原生推理历史、请求字段一致性回归及完整现有测试。
- 对保留的 Django 17029 checkpoint，在临时目录使用新旧生产 `save_checkpoint` 和 `SessionTree.commit`，分别记录首次保存与后续五次更新，核验每个版本保存的初始文本/权限及 SQLite 恢复结果。只测持久化，不把它当作端到端加速。
- 固定缓存探针：两组独立约 4K token 前缀，各重复三次；一组固定 `prompt_cache_key`，另一组省略，顺序为无键/有键、有键/无键、无键/有键。同模型 medium，最多 128 输出 token、单请求 60 秒、禁用自动重试，总计最多六次。再做四并发小请求连通性检查（每次最多 128 输出 token、60 秒），共最多十次。全部请求/响应私有存档，公开只展示用量、时间及错误；不因探针结果追加尝试。
- 缓存探针只检查供应商接受字段及探索回执；小样本不用于承诺缓存或费用收益。四并发检查若出现 HTTP/连接错误、模型不符或缺失用量，则停止付费扩展并报告。

## 固定四题

`django__django-17029`、`psf__requests-2931`、`sphinx-doc__sphinx-11510`、`terminal-schemelike-metacircular-eval`。每版每题一次新运行，先 baseline 后 candidate，各四题并发。每题预算 900 秒、4 CPU / 8 GiB，gpt-5.6-luna / medium、Responses、64000 上下文、8192 输出、空会话、单 agent、自动记忆开启。复用历史独立评分器和已披露环境适配；pi/Codex 不重跑。

所有尝试、超时、供应商失败、未知用量都保留；不替换，不选最好成绩，不改变评分断言。固定成功对照题是 Django 17029 与 Scheme，两版均需独立通过且正常交付，不能根据本轮结果另选对照题。

只有以下条件全部通过，才执行正式二十题 candidate 各一次：

1. 八个 pilot 尝试全部独立评分，无评分环境错误；candidate 通过题集合包含 baseline 通过题集合。
2. 两个固定成功对照题在两版中均正常交付并独立通过，且其请求无缺失用量。
3. 固定成功对照题合计未缓存输入至少下降 5%；权重 `U + r*C + q*O` 在 r=0.1/0.25、q=1/4/8 六种组合下均至少下降 5%。这是费用权重敏感性分析，不是真实账单。
4. 固定成功对照题合计任务耗时至少下降 10%，其中任一道题不增加超过 10%。
5. 四题总费用权重均不增加，candidate 缺失用量次数不超过 baseline。

未达标就停止扩展，保存四题结果与原因；失败题提前退出不能建立降本结论。历史 15/20 不被 pilot 替换。本轮更高并发与历史条件不同，新旧 pilot 相同并发；所有模型成本含背景记忆与失败请求。

生产源码、runner、协议、任务、评分依赖与环境适配在调用前冻结摘要。完整评测如获准入，沿用相同四并发和预算，不追加重跑。
