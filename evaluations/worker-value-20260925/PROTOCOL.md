# 委派适用场景迭代协议（2026-09-25）

用户授权继续迭代委派，直到在真实需求对应的任务上观察到可解释的收益。本轮仍保持简历项目的轻量体量：复用现有 Runtime、工具、账本、沙箱与独立评分器，不增加调度框架、供应商或更便宜的子模型。

## 任务与比较

两类三子系统仓库调查：删除/保留契约审计，以及导入对账兼容性调查。需结合各子系统的合同、代码、配置和样本，区分当前实际行为与期望行为，写出带文件证据的 `report.json`。候选工作区不含参考答案或评分器，不得改动被审计源文件。独立评分器检查具体结论、证据及源文件完整性；离线先验证参考报告通过、缺报告/错误报告/改源失败。

对照为同一模型 `gpt-5.6-luna`、同一任务与配置，只调整 `max_workers=0/3`。同一提示在工具可用时明确请求三个只读 Explore 子任务，否则由单 Agent 完成；不要求单 Agent 使用低效工具或手工逐行推算。双方都可使用已授权工具、批量读文件、执行原项目代码和脚本。父任务负责整合报告，报告任务不强制编写测试，最终正确性由独立评分器判断。

先在删除/保留任务运行基线 `4a31335` 的 solo/Worker 对照，再迭代实现并比较。第二种任务在设计时冻结，留作场景迁移检查；不会读取它的模型结果来修改已经冻结的任务与答案。

每次实现变更先离线验证、提交并固定源码，再运行模型；所有尝试、错误、取消、服务故障和开销保留。已运行的实验不更换结果。最终候选与 solo 在两类任务各执行两次，交替先后顺序；已完成且配置/源码行为一致的轮次可以标明复用，不重复计费。没有重复直到成功的单题重试。若某版无收益，先依据轨迹定位具体问题再修改；每个新增批次在运行前记录理由和预算。

## 预算与身份

复用 `worker-memory-20260922/run.py` 的全树请求账本和工具预算：每个 episode 最多 40 次逻辑模型调用、60 个工具动作、500,000 已报告 token、600 秒。子任务仍最多 12 步/12 轮；3 个同时存活。token 限额是已知 usage 达限后阻止后续请求，不宣称并行在途请求具备精确预留的硬 token 上限。

Conda `aster`，显式 `PYTHONPATH` 并断言导入路径；基线独立 worktree，最终版本当前源码。冻结提交、配置、驱动/源码/评分器哈希。Responses 流式、64k 上下文、8192 输出、120 秒单请求超时、必要沙箱、无网络、读并行 1；Memory/Skills 无额外注入。不放宽权限，不使用 base。

## 预定义指标与成功条件

- **正确性门槛**：报告各子系统结论与来源通过独立验收，被审计源文件不变；遗漏或捏造结论不算收益。
- **通用指标**：整个父子树的 token（包含缓存分项与 usage 覆盖率）、模型调用、工具动作、墙钟时间和通过数。没有明确价格则不换算账单；父用量下降不等于总成本下降。
- **主任务上下文负担**：父运行接收的原始文件/搜索/命令观察 token、最大请求估计 token、累计输入 token、直接调查动作数；这是“主任务正在处理设计工作，把独立调查交给子任务”对应的上下文保留收益。子摘要单独计入父上下文，不能从用量中排除。
- **协调与证据覆盖**：status 次数、全体子任务状态、真实并行请求峰值、独立评分通过项。子任务终止不直接等于事实正确。

优先目标是在双方都正确的配对任务上，重复观察全树 token、调用/动作或耗时的改善。若全树成本不降，而主任务的直接调查动作与原始上下文负担都稳定下降，且独立验收保持，则仅声明这种隔离与卸载收益，并给出全部额外成本。单次偶然成功、移除验证要求、选择更容易的评分或只算父成本，都不作为委派性能优势。

两类场景各两次的重复可以支持项目级小样本结论，不能代表公开基准或所有任务。旧版微型编码任务中的负收益继续保留作为适用边界，不重命名为新发现。

## 第一版

扩展现有 `worker_status`：单 ID 兼容，最多四个 ID 一次等待，共享最长 300 秒期限，返回每项完整终态。父模型无需逐个轮询；超时、取消查询不取消子任务。只改等待协调，不更改模型或子任务预算。依据是 pi subagent 示例的一次并行汇总与 OpenHands task 的运行时等待方式。

调研引用与取舍另存 `RESEARCH.md`；最终报告列出版本、所有尝试及可复算数据。

## 第二版：真实模型运行前发现的角色契约错误

第一版离线通过后，确定性探针发现 `mode=explore`、任务文字包含“identify the minimal fix”会同时产生 `read_only=True` 与 `require_edit=True`，子任务永远无法满足完成门槛。第二版让只读子任务保留调查观察要求，但不从“fix/tests”等关键词推断强制编辑与正式测试。可写子任务和父任务验证契约不变。此问题可离线复现，不为第一版追加已知有故障的模型实验；真实配对基线对比第二版，第一版批量等待单独有取消/超时/状态验证。

## 第三版：让第一轮能发现委派能力

第二版删除审计正确通过，却没有启动任何 Worker（6 次模型调用、83,553 token），不能计为委派收益。轨迹显示父任务直接通读所有文件；工具说明按需加载，因此新增分工指导未在首轮出现。第三版沿用现有 Memory/Skills capability 的方式，在启用 Worker 时向系统提示加入简短能力说明：先做足以分工的发现、及时分派独立调查、等待整组交付并检查证据与缺口。关闭 Worker 与子任务都不加这段。它进入统一预算计算，也同步会话预检；不把仓库文本或子输出提升为系统指令。

第三版先跑删除审计的一次开发验证；若正确且实际发生委派，再固定版本跑两题 × solo/Worker × 两次的最终确认。第二版无委派结果继续保留。所有版本的评分题、验收与预算均不变。
