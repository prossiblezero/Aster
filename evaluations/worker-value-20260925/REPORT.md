# Worker 委派适用场景迭代（2026-09-25—26）

**五版迭代后，委派在“多子系统规则／对账审计”小样本中观察到质量收益：固定八次对照里，单 Agent 通过 3/4，委派通过 4/4，12/12 个子任务正常交付。** 对账任务两次运行是 1/2 对 2/2；删除审计双方都是 2/2。这个结果支持“独立调查加父任务核验有时能减少漏判”，不证明通用成功率稳定提升。

**效率目标仍未达成：** 委派全树 token 为单 Agent 的 **2.08 倍**，墙钟之和为 **1.69 倍**；父调查动作虽减少 24.3%，父累计输入和峰值反而增加。保留为需要更充分核对时按需开启的能力，默认仍是单 Agent。

## 解决的问题与实现

此前 Worker 在微型编码题中经常造成重复发现、反复轮询、测试责任冲突和空交付。本轮保留原有 Runtime、权限、独立上下文及 12 步/12 轮预算，迭代五版，没有加入新调度框架、供应商、便宜子模型或额外依赖。

| 版本 / 提交 | 改动及依据 | 验证结果 |
|---|---|---|
| V1 `d6d586b` | `worker_status` 兼容单 ID，并支持最多四个 ID 共享期限等待；最长 300 秒，取消查询不取消孩子 | 离线通过；模型运行前发现 V2 的角色问题，未额外花费模型调用测试已知故障 |

| V3 `f163b50` | 把 Worker 能力说明加入首轮系统提示及同一套上下文预检，解决工具按需加载前不可见的问题 | 启动 3 个孩子，全部耗尽工具步数、没有摘要；父任务重做后通过 |

父任务编辑后验证、fresh-read 编辑要求、写入范围、沙箱、安全校验及持久化／训练 schema 没有改变。`finished` 只是整组没有仍在运行的孩子，不保证孩子成功，更不保证答案正确。Worker 仍默认关闭；产品中每个运行独立预算，本实验使用外加的全树账本约束所有父子调用。

产品源码从 **54 文件、10,780 行**变为 **54 文件、10,846 行**，净增 **66 行**；非空行从 9,960 到 10,025。指标按对应 Git 提交下 `src/aster/**/*.py` 计算，不把生成站点、实验夹具或测试算进产品源码。本轮只新增两个回归测试函数，其余扩展或复用已有测试。

参考了 pi 官方 subagent **示例扩展**的一次汇总与局部上下文、OpenHands 的任务交付，以及 ACL 2026 ExtAgents／AgentSlimming、NeurIPS 2025 MAST 和 2026 更新的系统扩展预印本。借鉴的是减少协调和重复劳动的机制，没有把来源论文的性能数字当作 Aster 的结果。固定源码提交、官方论文状态与具体取舍见 [RESEARCH.md](RESEARCH.md)。

## 任务、对照与验收

任务是围绕维护需求自编的仓库夹具，**使用真实 GPT API，不是生产项目基准**。没有填充无关代码来制造上下文优势：

- `retention-audit`：11 文件、566 行，审计账号删除冷静期与会话撤销、物理对象版本保留、搜索服务索引范围。
- `reconciliation-audit`：11 文件、430 行，审计银行金额舍入、订阅退款去重、跨时区平台结算日期。任务和答案在模型运行前冻结；V5 开发只使用第一题，第二题首次进入确认批次。

两个任务各有三个独立子系统，须结合代码、合同与冻结输入写出 `report.json`：实际输出、期望输出、受影响 ID、来源路径和原因。候选工作区不含答案或评分器。独立评分器逐项核对值、类型、ID、存在的实施／合同／输入来源及全部初始文件哈希；报告缺失、错误结论和改源在预检中均失败。自然语言 `cause` 自动评分只检查非空，另由人工对照源码复核，不能声称自动完成了因果语义验证。

最终比较同一 `gpt-5.6-luna`、同一任务提示、源码 `f812df8e5ed86705553af32320faae93bd27006a` 与配置，只改变 `max_workers=0/3`。提示在能力存在时要求委派三个只读调查，否则自行完成；单 Agent 可以使用全部已授权批量读取、搜索和执行工具。每题各两次，第二次反转 solo／Worker 先后顺序；无失败替换或选择性重试。

每个 episode 全树上限为 40 次逻辑模型调用、60 个获准工具动作、500,000 个**已报告** token、600 秒。并发在途请求不具备精确 token 预留，不能当成账单硬封顶。使用 Conda `aster`、显式 `PYTHONPATH`，断言解释器、源码导入位置、提交及前后源码哈希。Responses 流式，64k 上下文、8192 输出、120 秒请求超时、必要沙箱、无网络、读取并行 1；不启用额外 Memory／Skills。

本任务是审计而非改代码，不要求候选编写测试；双方都要交付报告并接受同一独立验收。运行器的 `completed/verified` 不等于评分通过，也不等于子任务运行过正式测试。

### 具体在哪一类任务有用

在对账审计首轮，单 Agent 正确识别“应按当地日期结算”的根因，却把 `p-late` 错纳入当天，得到 14,400 cents。合同明确使用 `Europe/Berlin`：`2026-09-25 22:30 UTC` 已是当地 9 月 26 日 00:30，应排除；正确结果为 **12,600 cents**，受影响 ID 还必须包含 `p-late`。人工独立用 `ZoneInfo` 核对了转换与金额，排除了评分歧义。

两次委派都正确完成该题，对账最终是 **单 Agent 1/2、委派 2/2**；第二次单 Agent 也通过，因此不能说单 Agent 不会解决。对账两次合计 token 为 202,354 对 382,173（委派增加 88.9%），耗时为 168.2 对 245.2 秒。实际可辩护的价值是需要多角度核对时，以更多计算换取本样本中更完整的结论；不能写成低成本提速方案，也不能据一个错误样本把 50 个百分点泛化出去。

### 子任务交付不等于事实保证

12 个子任务均读到了各自的实现、合同和输入，轨迹内容哈希与文件一致；8 个成功执行对应冻结输入的真实接口，4 个接口执行受审批限制（其中一个另有 smoke tests 通过）。最终 12/12 个委派子系统结论正确，但孩子自由文本仍有两项额外错误：一个把 Eve 的请求年龄 48 小时说成 24 小时，另一个给退款影响 ID 混入原始事件和客户名。父任务最终纠正或没有采纳这些错误。

这种事实也说明不能删除父核验来追求更低 token。本轮没有再加入来源清单、调度器或更多提示层；重复阅读与摘要不完整仍是清楚记录的边界。

本轮总计 **14 次付费运行、217 次逻辑模型调用、219 次 HTTP 尝试、2,461,121 个已知 token**，包括所有开发失败与零委派轮次。总 HTTP usage 覆盖 216/219；不把缺失 usage 补成零，不推算美元费用。


## 指标口径与边界

- 全树 token 包括父任务、所有孩子、失败和重试；缓存读取输入是输入的子集，reasoning 是输出的子集，不重复加总。没有可靠实际单价，不换算或宣称账单节省。
- “父原始观察 token”使用 `cl100k_base` 对 `read_file/list_files/search/run_shell/observation_read` 的工具输出计数，包含报告回读，排除 Worker 摘要与 `git_diff`。摘要仍完整计入实际父输入和全树用量，因此该自定义指标下降不自动代表上下文峰值或成本下降。
- “父调查动作”是上述工具的尝试数，包含受阻和失败；全体工具尝试还含协调和写入，与获准动作预算口径不同。分别报告父累计输入和单请求峰值，避免把操作转移给孩子等同省钱。
- 路径引用不是机制强制绑定的事实证据。部分自然语言调查任务仍可能未被推断为 `require_observation=True`；本轮通过实际轨迹核对孩子读过对应来源，并由独立评分验收结果，不将提示约束宣传为硬保证。
- 两个自编任务各两次属于小样本项目验证。即使有质量差异，也不能外推为通用提升；实际计算量不相等，不能区分独立调查拓扑与更多推理投入的贡献。耗时还受到远端服务、缓存与生成路径波动影响。
