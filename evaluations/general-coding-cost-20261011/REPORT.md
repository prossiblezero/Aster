# Aster 上下文成本优化与二十题复测

**本轮修正上下文计量并减少模型调用，但尚未解决与 pi/Codex 的成本差距。** 实验于 2026-10-11 登记并启动，2026-10-12 完成。二十题全部独立评分，通过 **15/20（75%）**，与上一版及 pi 固定历史成绩持平；正常交付且独立通过也为 **15/20**。

## 质量变化与失败

本轮仓库 **7/12**、终端 **6/6**、小型实现 **2/2**；上一版为 8/12、5/6、2/2。解释器在绝对路径修复后通过全部 **63 个程序比较**，Requests 2931 则新增回归，两者抵消后总分持平。没有用 pilot 或旧轮答案替换本轮失败。

| 题目 | 本轮状态 | 独立失败原因 |
|---|---|---|
| Django 11400 | 900 秒超时 | 仍遗漏 Field.get_choices 及反向关联字段的默认排序，两项目标测试失败 |
| SymPy 17630 | 内部 completed / verified | 通用零矩阵加法 test_zero_matrix_add 仍失败 |
| Sphinx 11510 | 内部 completed / verified | 普通 include-source-read 事件测试失败；嵌套 include 本次通过 |
| pytest 10356 | 内部 completed / verified | test_mark_mro 仍失败 |
| Requests 2931 | 内部 completed / verified，新增退步 | 修复二进制请求体时让共享编码函数直接返回 bytes，URL 字节参数路径因此混合 str/bytes；已有 test_params_bytes_are_encoded 回归 |

内部 completed **19 题中有 4 题独立失败**，上一版是 18 题中 3 题；另有一次超时。独立评分基础设施错误为零，没有任务以 provider_error 终止。模型自测和框架验收仍有遗漏关联调用、覆盖不足的问题，不能将本轮失败都归因于环境或供应商。

## 生产改动与工程验证

此前第二版的 393 次前台请求中，373 对相邻请求有 138 对改写已发送的历史前缀。Requests 5414 的一次请求，本地按序列化内容估算约 54,682 tokens，服务端实际输入回执 22,665；其中密文就被本地算成约 29,610 tokens。下一轮发生裁剪，缓存输入从 20,992 降至 5,632。密文文本长度不是重放时的模型上下文长度。

本轮改动三个生产文件，详见 [source.patch](source.patch)：

- `context/budget.py` 用成功单次请求的用量回执校准对应加密推理项。密文仍原样进入请求、历史与 checkpoint；失败、诊断异常、累计重试或缺失回执不用于校准。只在当前运行/模型内保留校准和已观察到的最大正向输入开销，恢复后的未知记录继续保守计量。
- 达到原输入上限才裁剪，并预留不超过输出预算且不超过输入额度 1/8 的空间，减少连续多轮裁剪；保留用户约束和最新完整交换。没有新增摘要模型调用。
- `core/runtime.py` 将实际请求及成功回复交给计量器；`context/prompt.py` 要求先执行聚焦回归，代码和环境不变时复用检查，环境问题需未改动基线证据后再决定修复范围。正式验证门禁、失败保留和工作区变化失效规则不变。

没有新增依赖、服务、配置或模型；自动记忆继续开启。上下文策略为 `deterministic-v8`。该计量依赖回执，只是估算，不是解密，也不保证所有兼容服务都不会低估。

工程回归先运行 `tests/`：**1217 通过、3 失败、4 跳过**，三个失败均为旧策略版本 `v7` 的断言；更新为 `v8` 后，整个 `test_stable_prefix.py` **13 项通过**。合计 **1220 个不同测试通过，4 项 Go 测试跳过**，并非声称一次完整运行全绿。相关上下文回归 **65 通过**，改动代码 Ruff 与空白检查通过。[工程检查汇总](engineering-checks.json)。

旧第二版请求离线重放中，372 次可校准的后续请求没有低于服务端输入回执的估算，保守差值中位数 6,383 tokens；这是旧轨迹验证，不保证未来所有请求。见[离线统计](offline-estimator.json)。二十个任务镜像全部通过无模型的绝对路径执行与正式 unittest 预检，见[环境检查](full-candidate/environment-preflight.json)。

## 运行口径与证据

三来源固定二十题：12 道 SWE-bench Verified、6 道 Terminal-Bench 归档任务、2 道 Aider Polyglot Python 任务；同模型 `gpt-5.6-luna` / medium、Responses、64000 上下文、8192 输出、每题 900 秒、4 CPU / 8 GiB、空会话、单 Agent、两题并发。原始题面、镜像与独立断言保持一致，每题仅采用本轮唯一尝试，失败和超时全部保留。

沿用披露过的解释器、pytest 源码导入、原始跟踪夹具和 gRPC 持久服务容器适配。专用任务容器使用只读挂载的 Debian 12 bubblewrap，并允许其创建命名空间；内部仍执行生产 Landlock、seccomp 与回写检查。完整复测与历史第二版之间还包含绝对路径隔离修复，不能把所有差异都归因于本轮三文件改动。三题新旧对照两组均含该修复。

冻结材料包括运行源码、工具驱动、题面、模型和预算。Terminal 222 个文件与 Aider 16 个文件的摘要均与此前冻结来源一致，补充完整 238 文件清单核对；见[来源核对](source-integrity.json)、[来源清单](upstream-hashes.json)和[本轮冻结清单](full-candidate/manifest.json)。模型请求/回复、后台调用、原始故障和完整测试日志保存在 `artifacts/private/general-coding-cost-20261011/`；公开逐题结果包含启动记录、仓库补丁与独立测试日志。

结束后确认三阶段冻结源码与运行器摘要一致，当前生产源码与 candidate 相同，二十题题面、镜像、模型、预算核对通过。任务容器、专用网络与模型网关均已退出。`analyze.py` 只做事后统计，不参与冻结解题或评分；汇总回执与逐题统计逐项一致。

这些题已用于诊断与优化，因此是开发集复测，含本地环境适配，不代表原 benchmark 完整榜单、未见任务泛化、稳定排名或单项优化的严格因果收益。费用分量 U/C/O 与真实货币支出分开解释；不将研发累计成本与其他 Agent 的单轮成本直接比较。
