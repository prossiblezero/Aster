# Aster 上下文成本优化：事先登记

2026-10-11。用户授权优化并评测。先冻结包含绝对路径隔离修复的当前 Aster 为 baseline，candidate 只增加用量校准、裁剪余量和精简后的验收指引。两组自动记忆、验证门禁、任务镜像、题面、模型和运行预算一致。

- pilot-baseline、pilot-candidate：各三次全新尝试，题目固定为 Requests 5414、C++ heap crash、Sphinx 11510（两道此前通过的高消耗题和一道长任务）。
- 同模型 gpt-5.6-luna / medium，Responses，64000 上下文、8192 输出、每题 900 秒、4 CPU / 8 GiB、空会话、单 Agent，两题并发。每题每阶段只执行一次；供应商失败、超时及未知用量均保留。
- 预检不调用模型。使用先前独立评分器、原始题面与上游断言。所有任务容器使用相同的 bubblewrap、命名空间权限与已披露的解释器/pytest/gRPC 容器适配。
- pilot 的扩展条件：candidate 独立通过数不低于 baseline，未缓存输入下降，并且预先列出的费用权重 r=0.1/0.25、q=1/4/8 下，U+r*C+q*O 均不增加。U 为未缓存输入，C 为缓存输入，O 为输出。未知请求须单列；这是估算权重，不是真实账单。
- 条件满足后，full-candidate 固定原二十题全部一次全新运行。pilot 不并入正式成绩；pi、Codex 不重跑，保留原成绩和用量。
- 全组同时报告独立通过、正常交付且通过、内部误报、全部尝试的请求/时间/U/C/O/总 token、缺失用量和压缩行为。与第二版历史结果的比较不解释成单一机制的严格因果收益；主要因果对照来自新三题 pilot，仍只有每题一次样本。
- 不通过修改测试、减少验收要求、丢弃加密推理记录、关闭记忆或删除失败记录获取改善。不承诺达到某个降幅或超越竞品。若 pilot 不达标，先分析，后续改动与试验独立冻结，不覆盖记录。

基线源码在任何生产修改前保存至私有 baseline/aster。模型请求与回复保存在私有阶段目录，公开产物仅包含冻结哈希、补丁、用量和独立评分证据；不输出供应商凭据。
