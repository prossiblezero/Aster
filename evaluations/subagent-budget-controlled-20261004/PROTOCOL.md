# r5 / r6 受控委派评测（2026-10-04，首次请求前预登记）

目的：实际检验 r6 孩子在 token 不足时提前交付的路径。候选与对照分别使用原冻结 r6、r5 的全部生产源码，不改模型、任务、评分或硬预算门禁。使用现有十题、80 个可执行事实，全部原评分与 90 个负对照先离线核验。本轮比较两个父子版本，不声称重新估计相对 Solo 的优势。

## 固定设计与顺序

共 44 个首次真实回合，全部保留。A 组：十题从头执行，r5/r6 各一遍，共 20 回合；每题由真实 WorkerManager 显式启动一个只读孩子完成第一包，父方并发完成第二包再整合。顺序按题交错。与原十题固定分工评测相同，max_workers=0 隐藏额外启动入口，explicit=True 首次派工；局部额度使用原两槽回退（24 工具、14 模型调用），不冒充 adaptive 的单槽额度。

B 组：取 r5 全部三个实际委派案例（Boltons/1、More Itertools/1 与 /2），不依据本轮结果选例。只提取成功 read_file 返回的实际路径/行区间/源码哈希；父方截断于首次自动交付或 worker_status 返回交付，以先到者为准，排除 REQUEST.md，不重放模型答案、shell 或历史 observation ID。原 trace 链和来源哈希必须匹配。用这些记录调用真实 read_file 构造双方相同的初始证据；这不是完整历史 checkpoint 或原并发时间线的复演。

每个前缀分压力和充足额度两条件，r5/r6 各两遍（第二遍反序），共 24 回合。父方也预读自己的证据，待孩子终止后开始模型整合；两版使用同样调度。前缀没有历史模型费用，预读计入工具额度；报告明确限定为“已经取得这些证据后的交付/恢复”，不与 A 组整题通过率混合。

常规/充足额度为全队 36 次模型、60 次工具、300000 token、600 秒，64k 上下文、8192 输出上限，Memory 关闭，服务使用项目正常配置，身份与 endpoint 哈希冻结。实际供应商模型标签也记录。

压力额度在零模型预检中确定：r5 充足条件构建父/子请求，估计为 P、C（都含输出保留），L = 2P + C + floor(C/4)。两版冻结相同 L；原父保留 R=max(floor(L/5),2P)。重新构建后必须验证 r5 保留工具且 C+R <= L < 2C+R；r6 去掉工具、handoff reason=team_token_limit；两版首次孩子请求均通过原硬准入。充足条件两版均保留工具。预检 fake model 的 complete 一经调用即报错，覆盖十题真实 start 和三个前缀的两条件；必须全部通过才能发起真实请求。预检与真实回合用全新 Runtime。公式只由请求长度决定，不参考 oracle 或新一轮答案。

## 结果与采用门槛

三条件分开报告严格整题通过、原行为事实、格式失败、空答案、实际委派/无工具请求、PARTIAL/完成交付、父方实际接收与逐值保留，以及全队完整 token/耗时。交付接收和行为保留是可观察证据，不证明父方思想的因果来源。散文子交付不自动修补成 JSON，也不把 PARTIAL 标为 completed；单列可解析覆盖。

r6 只有在压力组确实触发且交付/父方质量收益有证据、正常十题及充足对照无明显质量损失、成本仍合理时才考虑采用；小样本仅支持本评测观察，不能宣称显著性或普遍优于 Solo。若压力两版同样好，或提前收尾反而丢失必要证据，则保留 r5，报告负结果。

所有首次失败计入结果；不替换、不补跑最好值、不改变分数、额度或生产源码。全部请求无 usage 的服务故障暂停后续以免无效收费，保留失败，恢复只继续未启动的回合。任何已启动但结果缺失必须审计，不能自动覆盖。冻结涵盖两个版本源哈希、历史冻结、驱动全部依赖、协议、前缀、数据、oracle、模型身份、环境、预检和精确回合顺序。生产仍保持 r5，候选采用另凭完整证据决定。

## 首次请求前驱动修正

首份零模型冻结保留为 PREFLIGHT-INITIAL-FREEZE.json（没有付费请求）。自审发现 live setup 预构建孩子会使 r6 的提前收尾提示在 _run 中重复。最终驱动仅在离线 probe 预构建孩子；live 直接进入正常 _run，在实际首次模型调用前断言工具/原因并保存请求估计，不修改消息。修正后重新做全部零模型预检并冻结，评分、题目、顺序和额度公式不变。
