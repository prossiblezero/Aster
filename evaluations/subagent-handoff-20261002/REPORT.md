相关工程检查全部通过。48 份已保存交付的正文 token 本地估算减少 **10.6%**。真实模型检查中，两个子任务均首次提交成功并使用短引用；修正测试脚本的只读任务声明后，父答案四条事实与引用通过。首次因脚本触发编辑完成门槛而失败的记录保留在本目录，不计为成功。

这些结果验证工具机制和一次整合流程；没有新旧模型任务对照，不能声称全队成本、速度或正确率提升，也不能证明自主委派能力。

## 实现与边界

- 子任务成功 `read_file` 的模型输出额外提供 `source_ref`，为完整证据 ID 的前 12 位；原有完整 ID 保留。`worker_finish.sources[].evidence_id` 接受完整 ID 或恰好 12 位的短引用。匹配仅在当前子分支 `worker_reads` 内进行，必须唯一匹配，随后还原完整 ID，再沿既有读取事件、文件哈希及正文校验。歧义要求完整 ID；11 位、13 位或后半段抄错的长 ID 不会被模糊接受。
- 反馈分别说明未知引用、歧义引用、授权记录缺失、行段越界及源码过期。越界给出路径、请求行段和实际可用行段。超过 4,000 字符时给出总字符数和每个选择的字符数；计数口径仍是原文字符数，不包括展示用行号。
- 既有 `WorkerManager.model_view` 为自动交付和状态工具输出生成展示副本：摘录不再携带长证据 ID 和文件哈希，正文逐行显示真实行号，保留路径、行段、结论标识、截断与过期信息。原始交付、检查点、界面及直接状态 API 保留完整元数据和未加行号的正文。父观察认定仍不提供编辑权限或替代父方测试。

增量修改见 [candidate.patch](candidate.patch)，前后源码摘要见 [SOURCE-FREEZE.json](SOURCE-FREEZE.json)。没有改动等待策略、消息续跑或自主派工规则。
