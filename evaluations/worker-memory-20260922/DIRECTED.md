# 明确要求委派的补充对照

在主批次首个 Worker 开启条件尚未完成时登记：主批次允许模型自行选择委派，可能无法观察到实际 Worker 行为。为区分“工具可用但模型未选择”和“委派流程本身是否有效”，补充固定的 csv-ledger、access-report 两题，每题重新运行 solo/directed 两条件，各一次。总计额外 4 次真实尝试，不覆盖主批次，不将其当作四种新任务，也不因结果决定是否保留。

两条件使用同一份新增用户指引：有 Worker 工具时，明确要求把两个独立实现模块委派到两个互不重叠的写入范围；父任务处理集成测试并等待汇合。无 Worker 工具时自行实现。子任务划分、调用、等待和整合仍由真实 GPT 完成，评测脚本不调用 worker_start，也不人工完成代码。这样测的是用户明确请求委派的工作流，不能与主批次“自主选择”的结果混写成单开关效果。

顺序为 csv solo→directed、access directed→solo；与主批次顺序执行，不同时占用网关。不扩大单题预算，不做任务级重试。复用已预检的评分器及主批次 execute、配置、完整父子用量账本。分别记录是否真的委派、子任务完成、最终独立代码验收、墙钟时间、父子总 token。若依然没有委派或流程失败，照实记录；不继续追加试到成功。
