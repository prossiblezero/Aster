# 评分口径修订：dependent-export 输入行类型

主批次 `worker-dependent-export-solo` 第一次外部评分失败后检查发现：公开需求只写 `render_csv(rows)`，没有指定每一行是 `{'id': ..., 'value': ...}` 还是 `(id, value)`。候选实现并自测的是二元组接口，原评分器却只给字典，产生 `id,value` 被当作数据行的假阴性。源数据结构是题目遗漏，不能当成模型违反要求。

不改冻结需求、不修候选、不重跑模型。保留 `results.json` 中原判定与 JUnit 输出；在新文件 `regrade.py` 中统一允许字典行或二元组行，只要在同一种表示下完整满足正常导出、空输入、规范化重复拒绝和共享 normalize_id 接口要求。两个条件、参考实现和负向控制均使用同一新评分器，不按候选分别定规则。独立 normalize_id 验收不变。

最终报告同时标注原评分与修订后评分；用于质量汇总的是修订后独立验收，不把修订说成代码修复。此问题也说明参考实现通过、删模块失败的预检不能发现所有需求歧义。
