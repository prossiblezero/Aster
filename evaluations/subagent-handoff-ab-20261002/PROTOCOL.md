# 短引用等三项改动：真实模型前后对照

在任何正式模型请求之前冻结本协议、24 个新探针及执行答案、评分依赖、源码、配置身份与运行顺序。比较改动前的 12,024 行版本与当前 12,060 行版本，唯一生产差异为短引用、具体修正反馈和父模型交付展示三项改动。两版均包含此前的 any/all 等待能力。

三组新题分别使用 Django、OpenLibrary 和 Session 的已有固定源码，各含两个独立工作包、八条行为问题。探针未在旧批次使用，但项目、源码和部分行为主题已经见过，因此不是未见仓库上的泛化评测。所有题均为只读调查，不能当作原 benchmark 修复题的得分。

每题每版两次，共 12 个首次回合。第一遍按项目轮换 before/candidate 顺序，第二遍反转同题顺序；两版在每个位置各三次。回合串行，回合内固定两个 Explore 并发，驱动通过真实 Runtime 调用首次 worker_status(wait_for="all", wait_seconds=300)。之后父模型自主整合；不强制后续等待方式，也不测自主拆分或何时应该委派。无 Solo 对照，不能据此判断多 Agent 是否优于 Solo。

沿用现有模型、端点、64k 上下文、8,192 输出上限、36 次全队模型请求、60 次工具、300,000 token 预算和 600 秒上限；源码只读，Memory 与工具网络关闭。直接使用现有配置读取与模型客户端，凭据不进入公开文件。开跑前断言父任务实际只要求观察，避免此前脚本的只读表述触发编辑门槛。健康探测独立记账；若服务拒绝探测则不启动批次；某回合所有 HTTP 尝试均被拒绝时停止后续回合并保留失败。

预检执行全部探针生成行为 oracle；引用范围沿用修正后的递归 AST 索引。严格评分同时要求问题 ID 唯一完整、行为值正确、文件与符号内行号正确、正常父运行和源码/工作区完整。评分器检查结构与定位，不证明片段语义充分。额外报告纯行为正确与引用错误；不修补模型 JSON 或放宽旧规则。正例与缺项、重复、错误值、错误路径、越界行号、不存在/拼接符号的负例必须在冻结前通过。

主指标为严格整题通过、正确事实、全队已报告 token、端到端耗时。同时记录 worker_finish 尝试与拒绝原因、12/64 位引用使用次数、父方读取与此前子方读过的行数、父/子模型调用、HTTP 尝试与缺失 usage。缺失用量不补零，首次失败不替换为成功重跑。汇总每对比值及中位数、总量和全部逐题结果；两个重复和三个熟悉项目不足以证明稳定提升。

公开结果存于本目录，冻结源码、独立工作区、请求账本与原始轨迹存于 artifacts/private/subagent-handoff-ab-20261002。已有历史批次保持不变。
