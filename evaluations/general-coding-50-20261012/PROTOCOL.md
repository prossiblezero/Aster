# 50 题同模型比较（2026-10-12）

用户授权扩展数据并重新评测 Aster、pi、Codex。旧 20 题结果不被替换；本轮每种 Agent 每题一次，共 150 次正式尝试。不按模型结果换题，不追加采样到通过，不修改生产代码。

## 固定组成

| 来源 | 题数 | 旧题 / 新题 |
|---|---:|---:|
| SWE-bench Verified | 20 | 12 / 8 |
| Terminal-Bench archive | 8 | 6 / 2 |
| Aider Polyglot | 12 | 2 / 10 |
| BigCodeBench v0.1.4 | 10 | 0 / 10 |

旧 20 题全部标记为参与过 Aster 开发的题；新增 30 题单列。新增 SWE 题覆盖 Astropy、scikit-learn、Matplotlib、Pylint，每仓库两题，按专家耗时分层后以 `sha256("20261012:" + instance_id)` 排序选择，无较长题时退回短题。新增 Aider 按同一种哈希方式选 Python 2、JavaScript 4、C++ 4 题，排除已知旧题及其同名练习。BigCodeBench 从声明的离线 CPU 依赖范围中按相同规则选十题，排除历史 ID。两道 Terminal 新题事先按 PTY 交互程序和正则编译任务覆盖选择。

选题不使用 Agent 成绩或是否适合子 Agent。环境预检必须在正式运行之前完成；若原始断言无法区分初始代码与参考解，或任务无法在声明环境运行，记录原因并取相同层的下一哈希候选。不能因难度或模型失败换题。公开 benchmark 可能已进入基础模型训练，新增仅指本项目未使用。

## 运行预算

Aster 使用本轮开始时保存的回退版本 `c6b651d`，以私有不可变快照的逐文件哈希为准；准备期间出现的并行工作区改动不纳入本轮；pi 1.1.0，Codex CLI 0.154.0。三者均使用 `gpt-5.6-luna`、Responses API、medium reasoning、64000 上下文、8192 输出上限，900 秒/题，4 CPU、8 GiB/容器。6 个运行槽，按固定哈希任务顺序轮换 Agent 提交顺序。模型调用、原生重试、Aster 后台记忆调用全部计入。评分和镜像准备不计入答题时间，另报告整轮墙钟时间。

每题独立容器、空状态、单 Agent。Aster 保留严格验收和原生沙箱；仅适配任务 Python 与 Node 的只读运行库路径，不重新引入已回退的产品优化，不为个别任务改写工具行为。pi 禁用用户扩展；Codex 禁用多 Agent 和 web search，由外层 Docker 隔离。三者得到相同任务与环境提示。所有容器不挂载凭据、答案、Docker socket 或外部工作区，只访问模型 gateway 和本轮隔离网络。

容器统一提供正确 PATH（包括登录 shell，保留原 profile/rc 的加载行为），pytest 的 src 布局、Matplotlib 的 lib 布局及生成版本文件、科学计算项目的预编译扩展均保留，重建 Git 初始状态保留原 tracked-but-ignored 文件。包在控制端预装，正式题不联网安装依赖。三者均在答题计时前预加载项目依赖，避免将冷盘导入延迟混入解题时间。每种 Agent 先跑非 benchmark 的基本接入检查；若检查失败，不启动正式题。

## 评分与适配

SWE 使用固定版本原记录、官方 F2P/P2P 与评分器。官方测试路径按每个路径单独还原；原版本不存在的新增测试先删除，再应用未改动的上游测试补丁，以避免一个新增路径导致所有测试还原失败。冻结镜像 ID 与原始记录哈希。正反预检核对要求的测试条目确实执行。

Aider 保留公开测试并在独立新容器内恢复上游版本，只接收题目指定的 solution 文件。JavaScript 启用练习默认禁用的必做 `xtest`/`xit`，明确可选的 `test.skip` 保留；C++ 定义 `EXERCISM_RUN_ALL_TESTS`，使用原 Catch 断言；CMake 的练习目录名适配到 `/app`。BigCodeBench 只提供原题和代码框架，独立新容器仅接收自包含 `solution.py`，评分时按上游共享全局命名空间的语义把候选代码与原始 unittest 拼接执行。参考解的执行数和明确跳过数冻结，正式评分必须匹配。

Terminal 使用原工作区和原测试断言，统一以预装 Python 3.12 运行评分，保留上游的原生任务镜像；headless-terminal 预装上游评分器要求的 vim。测试启动器的联网依赖安装由预装代替。Terminal 评分仍在每题专属容器内进行，以保留 gRPC 等本地服务状态；测试只在答题后注入。其安全边界与原断言覆盖有限，尤其既有 C++ heap 题不能证明完整清理语义。所有适配结果都属于本地混合集成绩，不是上游官方榜单成绩。

主要指标：独立整题通过数/50，整题等权；另列来源、语言、旧 20/新 30、正常交付且通过、超时、环境/供应商问题、累计及中位耗时。用量以 gateway 的全部请求统计输入、缓存输入、输出、总 token；缺失用量不能计为零成本。没有可信单价，不换算金额。过程状态、缺失评分、失败尝试保留，不择优拼接历史分数。50 题仍是小样本混合集，不能据一次运行认定稳定排名或优化的因果收益。
