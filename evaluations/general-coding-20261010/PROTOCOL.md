# Aster / pi / Codex 通用编码小集

2026-10-10。最多 20 道原始任务，每题每种 Agent 一次，最多 60 次正式运行。
本轮只评测，不根据结果修改 Aster、不换题、不采样到成功。生产源码冻结为
`c6b651d`；pi 1.1.0、Codex CLI 0.154.0。使用现有安装，不把历史成绩当作本轮结果。

  Sphinx、xarray、pytest、Requests 各两题。排除此前 worker v1/v2/v3 和十题
  SWE-bench 中的题。按 `sha256("20261010:" + instance_id)` 排序，各仓库取一题
  专家耗时小于一小时、一题至少一小时；后一层没有剩余题时依次取 15 分钟至一小时、

  单列为历史题；其余三题为本项目新增题。归档来源不称为当前完整榜单发布版。

  27 题按同一种 SHA-256 规则取前两题。保留公开测试，独立评分恢复不可修改的原测试。

## 公平条件和预算

三者使用 `.env` 配置的同一模型 `gpt-5.6-luna`、同一供应商 Responses 接口。
控制端代理固定 reasoning effort=medium、输出上限 8192，记录原始参数和所有请求用量。
上下文窗口 64000，保留各自原生提示词、工具和压缩策略。每题 900 秒；不以工具次数
对齐不同实现，不设未被统一执行的 token 上限。Aster 最多 500 轮/500 工具步，实际
触及单列。每题资源相同，最多三题并发；按题固定轮换三种 Agent 的提交次序。

每题独立容器、空会话、空记忆，不读取操作者配置、skills、项目或历史答案。默认单 Agent。
Aster 保留当前默认记忆和后台整理，收尾计入时间；pi 禁用用户扩展，Codex 关闭多 Agent
和外网检索。允许容器内无人值守操作及本地服务，网络只通向模型代理和隔离评测网络。
凭据只在宿主控制端；容器不挂载 Docker socket、数据答案、隐藏测试或参考解。

所有模型运行前必须冻结数据、源码、运行器、镜像及预检记录。每题先确认原始状态
不能通过、参考解通过且测试确实执行。预检失败保留，修复环境后可重做预检；正式
题目开始后不更换题面或评分规则。三种 Agent 先各做一次非 benchmark 接入检查。
正式结果存在时不重复调用；不完整运行需要分类记录，禁止静默覆盖。

## 评分

SWE-bench 使用官方镜像和未修改的官方评分器，分别检验 F2P 和 P2P。
终端题保留上游原始测试断言、路径和原生初始镜像；预装测试依赖，允许离线运行原测试。
若测试启动器、解释器或依赖有适配，逐题记录，称为上游测试在本地适配环境的结果。
隐藏测试仅在 Agent 结束后注入，模型看不到参考解和评分端目录。

主指标为独立整题通过数/固定题数；同时报告分任务类型、历史题/新增题、耗时和已报告
input/output/cache/total token。全部请求失败、超时和无用量请求保留，未知用量不当作零费用。
没有可信供应商单价，不换算金额。评分环境错误单列，不解释为能力失败。

另外保存 Agent 最终答复、进程状态和 Aster 内部完成状态。人工按相同规则标记最终答复
是否明确宣称任务成功，再统计“声明成功但独立评分失败/声明成功次数”；有疑义单列。
这与进程退出码为零、Aster 内部 completed 是不同指标。没有单独的改动前同条件对照，
不把本轮与旧分数之差解释为验收优化的因果收益。
