## 冻结与隔离

- 两组启动前冻结源码、需求、公开设置、驱动和新版评分器的SHA256，记录实际加载的Aster源码路径。
- 源码使用不同的只读快照，由同一个aster Python运行公开CLI；不重新安装到base或改写已安装依赖。
- 各组全新空工作区、全新进程、全新会话/执行环境；Memory、Dream、Worker关闭，不安装Skills。没有旧候选、自测、README、反馈、checkpoint或观察归档。

## 配对运行与预算

只运行一对新生成任务。顺序在首次模型请求前用固定随机种子`20260919`确定并记录，不因结果追加采样。主profile沿用已有`main`（请求模型gpt-5.6-luna、Responses流式），两组相同128000上下文、32768输出预留、120秒请求超时、自动审批/required沙箱/授权网络/依赖复用。

每组累计80工具步、45模型轮、1500秒，包含传输重试、恢复和返修。首先不给定向反馈，保存首次候选及其独立得分。若失败，完成全部产品与过程检查后一次性汇总缺陷，最多一次定向返修，仍消耗剩余总额度；无隐含的第二次产品修复。一次同服务人工故障恢复也只使用剩余额度。预算用尽就记录失败。

若过程中必须改框架，保留该组失败，本配对不再声称只改变原冻结变量；不得一边修框架一边维持受控实验结论。任何额外诊断模型请求另列，不能漏记。两组顺序执行，不用并发给网关负载额外引入差异。

## 独立验收与证据

新版评分器保留原16项，并补“公式样式文本进入所选数值列、异常值和动态列名等输出位置”的反例，读取XLSX ZIP/XML而不导入候选实现。按表头语义检查，接受合法列/行顺序、共享/内联字符串；核对原始单元格文本类型、未合并表头、无BOM的UTF-8输入，以及交互错误与覆盖保护。评分器先用正负夹具检查，再在旧冻结候选上复现遗漏，结果单独保存，不覆盖旧16/16。`old-candidate-regrade.json`是首次19项草稿评分器的复评，最终冻结前的独立审查补缺另存`old-candidate-regrade-final.json`，双方真实生成使用同一个最终评分器。

过程门槛单列：官方教程相关正文确实进入模型观察；安装在受控环境，后续独立命令实际导入/使用；自测调用真实实现/公开CLI；README与错误语义一致；干净venv按README重建。只下载URL或测试报告通过不足以证明这些门槛。清理命令掩盖前序失败作为观察记录，不靠stderr关键词改变工具状态。

比较首次/返修后的产品与过程门槛、工具步/模型轮、时间、已报告tokens/缓存读及未知usage。每run只累加一次usage，不叠加provider/reply/state重复计数。缓存只描述，不作本轮因果目标。双方均成功是有效结果；B更好或更差的一次结果都不能证明普遍收益。本任务及全部调试材料继续排除于未见后训练测试集之外。

## 复现入口

所有命令从仓库根目录执行，先`conda activate aster`。离线自检不会调用模型：

```bash
python -m pytest -q evaluations/lab-followup-20260919/test_grader.py evaluations/lab-followup-20260919/test_driver.py
python evaluations/lab-followup-20260919/run_pair.py --help
python evaluations/lab-followup-20260919/grader.py --help
```

`sources/<arm>/`由记录的Git提交提取`src/aster/`与`pyproject.toml`，`SOURCE.json`记录提交与逐文件SHA256。原始快照、候选及会话轨迹在本地保留并忽略；公开的`freeze.json`和`runs/*/source-manifest.json`用于核对。`run_pair.py`使用`aster`环境的公开console script，`--source`指定冻结实现；先`--probe-only`，再指定新空`--workspace`、原需求`--prompt`及唯一`--name`。恢复显式传`--resume`与剩余`--steps/--turns/--seconds`，不得重置整组额度。独立评分使用`grader.py <candidate> --rebuild --output <新结果文件>`，不向候选目录加入评分代码。
