# 回到第 `i` 轮重新探索：专项结果

这轮直接测量的需求是：完成前 `i` 轮设计、经历后 `j` 轮探索后，回到第 `i` 轮提出新想法，并选择是否带入后续探索结论。

在固定的 `i=4、j=3` 课程导出场景中，四条路径的离线边界检查和真实模型最终回答均通过。候选分支确实隔离了后续内容；带摘录时，后续结论可显式带入；后续压缩没有改写早期恢复点。

## 场景和对照

前四轮建立硬约束：`storage=sqlite`、`privacy=offline_only`、`timezone=Asia/Shanghai`。后三轮探索云端 PostgreSQL、上传和 UTC 方案，并明确它们与当前约束冲突。最终任务要求保留三个硬约束，并把探索方案当作被拒绝的备选。

| 路径 | 含义 | 准备操作数 |
|---|---|---:|
| `legacy_summary` | 旧版请求模型总结，新建会话，手动复制粘贴摘要 | 4 |
| `legacy_checkpoint` | 旧版查找 checkpoint，复制运行编号后 `/resume` | 4 |
| `branch_clean` | 候选打开历史树，选择第 `i` 轮，不带摘录 | 2 |
| `branch_excerpt` | 候选打开历史树，选择第 `i` 轮并带入摘录 | 2 |

操作数只计算从决定回到历史位置到提交最终任务前的准备步骤，不是真人耗时。共同的四轮加三轮历史由离线替身预置，不混入路径比较。

## 真实模型结果

模型为 `gpt-5.6-luna`，两版使用相同 Responses 配置、只读模式和 1,024 输出 token 上限。每条路径一次真实尝试，四条均通过独立约束检查。

| 路径 | 模型请求 | 手动交接字符 | 已报告总 token | 结果 |
|---|---:|---:|---:|---|
| 旧版总结交接 | 2 | 303 | 12,597 | 通过 |
| 旧版 checkpoint 恢复 | 1 | 0 | 6,152 | 通过 |
| 新版干净分支 | 1 | 0 | 6,158 | 通过 |
| 新版带摘录分支 | 1 | 0 | 6,517 | 通过 |

与“旧版总结交接”相比，新版带摘录分支把准备操作从 **4 降到 2**，手动交接从 **303 字符降到 0**，模型请求从 **2 降到 1**，本批已报告 token 从 **12,597 降到 6,517**（减少约 48.3%）。

与旧版已有的 checkpoint 恢复相比，新版干净分支的模型请求同为 1、token 为 **6,158 vs 6,152**，基本持平；主要收益是把查找、复制、粘贴和 `/resume` 的准备操作从 4 步降到 2 步。这个对照很重要：不能声称会话树相对于旧版所有路径都节省模型成本，旧版 checkpoint 本身已经能恢复早期上下文。

带摘录分支比干净分支多 **359 token**，因为它把后续探索资料送入最终请求；这属于用户主动选择的交接成本，不是隐藏的模型总结成本。

## 隔离检查

- `branch_clean` 的最终模型请求中不含 `FUTURE_POSTGRES`、`FUTURE_UPLOAD`、`FUTURE_UTC`。
- `branch_excerpt` 的最终模型请求包含三个探索标记，同时保留三个原始硬约束。
- 旧版 checkpoint 恢复也能得到不含后续探索的请求，证明旧版具备技术恢复能力；新版改善的是位置选择和分支交互。
- 旧版和新版各执行一次“后续压缩后恢复早期位置”探针，均保留 `storage=sqlite` 且排除 `COMPACTED_FUTURE_ONLY`。这是持久化正确性检查，不是新版独有收益。
- 四条真实回答均保留三个约束；带摘录回答把三个探索方案列为拒绝的备选。

## 结论范围

这轮证明了当前实现满足你描述的核心流程：可以回到第 `i` 轮，默认隔离后 `j` 轮，按需显式带入后续结论，并避免为交接额外调用一次总结模型。它也证明了在这个场景中，真实模型没有因分支而丢失原始约束。

这不是通用成本或通过率结论：只有一个场景、每条路径一次真实尝试，历史准备阶段是离线预置，没有采集真人点击时间。金额未测，因为没有网关计价信息。已有 [会话操作评测](../session-ux-20260920/REPORT.md) 的 `69 → 36` 是更宽的固定工作流指标；本报告的 `4 → 2` 是针对这个具体需求的专项指标，不能把两者合并。
