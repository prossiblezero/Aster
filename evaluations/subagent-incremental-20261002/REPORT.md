# 增量等待与交付消息精简（2026-10-02）

本轮解决两个可确定的工程问题：父任务批量等待时被最慢子任务阻塞，以及已读文件哈希表重复进入模型上下文。保持 Solo 默认、自主委派默认关闭。

## 改动

`worker_status` 的列表查询现在等到任一新结果完成就返回，携带全部选中任务的当前快照；已有未消费结果立即返回。父任务可以先审阅可用结果，再等待剩余部分。已消费结果不会让下次等待立即空转。复用 `asyncio.FIRST_COMPLETED` 和既有 `pending_handoffs`，不增加调度器或状态字段。

一并修复恢复后的重复通知：工具消费保存的子任务结果时，根据子运行编号清理待交付记录。快照不可用的结果也带运行编号，可以被消费；界面轮询仍只查看。失败、取消、缺失结果保持逐项可辨识，外层 `finished` 不代表成功；超时和取消查询不会取消子任务，Final 仍须等待所有活跃子任务。

自动交付与状态工具发给模型的正文，用 `read_paths` 代替路径到哈希的 `read_evidence` 表。答案、支撑源码及其版本、过期路径、错误和验证信息保留。原始工具返回、磁盘和界面仍保留完整哈希表；超过自动通知上限的答案可用状态工具取回全文。精选源码不授予父方编辑凭证或测试通过状态。

生产源码 **55 个 Python 文件，11,993 → 12,014 行，净增 21 行（0.18%）**；修改四个既有文件，零新增依赖、工具或配置。相对本轮前未提交源码的增量见 [candidate.patch](candidate.patch)，源码清单见 [SOURCE-HASHES.json](SOURCE-HASHES.json)。旧轮次报告、冻结代码及评测记录保持原样。

## 离线证据

新增七个回归案例，在本轮前保存的源码上全部失败，在新实现上通过。覆盖先完成先返回、已有未读结果、后续等待、恢复与快照不可用、过早 Final，以及自动/单个/列表交付的模型视图与完整原始证据。既有测试继续检查超时、等待取消、缺失编号、失败子任务和列表去重。完整测试与安装验证记录在 [VERIFICATION.md](VERIFICATION.md)。
