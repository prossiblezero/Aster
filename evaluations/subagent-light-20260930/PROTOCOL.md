# Lightweight explicit-subagent scenario experiment

Frozen before paid execution. Six derived scenarios, three source snapshots, 48 fixed executable behavior questions. Each has two independent work packages with four questions each. These are given-probe behavior-inference and constrained regression-review tasks, not open-ended defect discovery. Each task runs twice independently under Solo, serial subagents, and parallel subagents (36 episodes). Repetitions are repeated pass@1, not pass@2, and all outcomes remain in the report. All six arm permutations appear twice over 12 matched task/repeat blocks, balancing order and positions.

The sources are pinned Django utility modules from an existing SWE-bench Verified snapshot, OpenLibrary list/compression modules from an existing SWE-bench Pro snapshot, and Terminal-Bench session-window modules. Investigation and review reuse a source snapshot. The questions and review patches are Aster-authored scenarios, not the original benchmark issues, and must not be reported as official scores or independent holdout performance. The small utility slices are deliberate bounded parallel-reading opportunities, not representative of full repositories or difficult patch tasks.

## Controls

- Same source commit, provider, model and settings for all arms; read-only, strict completion, memory off, read tool parallelism one.
- All arms get the same two work packages, full behavior questions and output contract. Solo investigates and integrates directly. Serial and parallel each start exactly two real `WorkerManager` explore tasks, receive native handoffs, then call the real parent's `Runtime.run()` to integrate. Only child scheduling differs between serial and parallel. Explicit assignment bypasses model task decomposition; it does not bypass Aster's runtime, tools, permissions, handoffs or team budget.
- Team ceilings: 36 model calls, 60 admitted tool calls, 300,000 reported tokens, 600 wall-clock seconds. All child calls and integration calls consume this shared budget. All three arms set max_workers=0 to disable autonomous delegation; the harness uses start(explicit=True) for the two authorized children. Native admission reservations can stop execution earlier. To isolate scheduling, the harness freezes manager.limits() at the pre-execution allocation for both children (recorded per child), while leaving native shared budget admission and parent reserves unchanged. This prevents the serial second child receiving a smaller initial local allocation solely because the first child already spent budget. No extra parent or child retries after the first attempt; ordinary provider retries remain in the ledger.
- No dollar-cost estimate without a pinned price schedule. Tokens, known/unknown HTTP usage, response model names and accounting mismatches are recorded.
- Clock starts before delegation/direct execution and ends after child cleanup. Preparation and oracle execution are excluded equally. Parent cumulative input usage and peak request input usage are separate metrics. Strict parent observation remains enabled; parent reads and overlap with child-read file paths are counted rather than hidden. They are not equated with persistent context size or accuracy gains.

## Ground truth and scoring

The public workspace contains only selected upstream source files, REQUEST.md, and (for review) candidate.diff plus originals of changed files in baseline/. It excludes the dataset metadata, oracle, reference outputs, old benchmark solutions and evaluation driver. References to upstream archives and file SHA-256 values are in datasets/subagent-light-20260930; source code is restored from the existing checksum-verified offline asset cache.

The offline oracle runs every question in a fresh Python subprocess using the actual modules. Review compares original and candidate executions, with exactly four changed and four unchanged behaviors per task: 12 regressions and 12 non-regression controls. These are deliberately introduced changes; they are not claimed as upstream defects. Investigation reports existing behavior even if it is buggy.

A fact requires exact JSON-normalized observed behavior, correct regression classification when applicable, and a valid file/symbol/line citation within the relevant source file. The citation check verifies an actual AST location, not semantic entailment; prose explanations are retained for audit but not automatically judged. Different valid symbols in the relevant file are allowed to avoid penalizing legitimate caller/callee citations. An exception answer uses its class name only. Each question starts with fresh modules. Arrays are ordered, objects are order-insensitive, and booleans are distinct from numbers.

A whole task passes only with all eight facts, exactly the requested IDs without duplicates, a normally completed parent, unchanged public source and no runner exception. Missing/malformed output and budget exhaustion are failures. Fact accuracy, regression recall and false-positive rate are reported alongside complete-task accuracy; child termination alone is never counted as benefit. The offline positive oracle must score 8/8; wrong value, invalid citation, omitted answer and duplicate answer negative controls must fail for every task.

## Interpretation

Primary checks are task/fact accuracy plus paired end-to-end time. Report all-team cost, main-thread input consumption, child completion and failure cases. Serial versus parallel isolates scheduling within this harness. Solo versus delegated arms combines context isolation, coordination and extra independent reasoning. Do not attribute reduced cost to delegation unless quality and actual child deliveries support that conclusion. Preserve the old ten-task Worker results unchanged. These scenarios do not evaluate autonomous delegation, edits, persistent follow-up, cancellation or restart UX; those are verified separately offline.

## Commands

Use the Conda aster interpreter; source imports are checked explicitly. First `python evaluations/subagent-light-20260930/evaluate.py preflight` performs no model call. After the production and evaluation files have been committed, use `freeze --commit FULL_SHA`, then `run --commit FULL_SHA`, and finally `python evaluations/subagent-light-20260930/summarize.py`. Existing results are retained. An incomplete episode requires an explicit audit rather than a silent retry.
