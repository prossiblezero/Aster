# 期末复习安排器：冻结的模糊需求与独立浏览器验收

本场景通过公开 CLI 验证 Aster 先澄清模糊需求、再从空目录完成可使用的小项目。操作员只发送下述初始需求，以及模型首次使用 `ask_user` 后的一次完整答复，不补写候选实现。需求、评分器、自检文件和复用的静态服务器源码在候选启动前记录 SHA256。

## 初始需求（原样发送）

我快期末了，想要一个能帮我安排每天复习内容的小网站，手机也能用，能记住我填过的东西。现在我的想法还比较模糊，请先用 ask_user 问清楚必要的信息，再开始实现。最后给我一个能放到 GitHub Pages 上、别人也能直接使用的完整小项目。

## 一次完整澄清答复（首次 ask_user 后原样发送）

做纯静态的中文“期末复习安排器”，不需要账号或后端，HTML/CSS/JavaScript 即可，不依赖 CDN。需要我录入多门课程，每门包含课程名称、考试日期、还要复习多少小时。我能设定开始日期和每天最多学习多少小时；小时支持小数，例如 1.5。默认值可以方便第一次使用，但开始日期必须可改，不能只能用今天。

请把每天复习什么列成计划：安排日期从开始日期起，必须严格早于该课程考试日，同一天所有课程合计不能超过每日上限，每门课程不能多排。能全部安排时每门课程的总小时必须等于它的剩余小时。安排不下时尽可能安排可完成的部分，给出明确包含“不足”的可见提示和缺少的总小时数；不能为了排满而超出上限、挪到考试当天或悄悄丢掉课程。课程考试日等于或早于开始日时，该课没有可用复习日，应报告不足。只支持正的有限小时数，空课程名、无效日期、零/负小时不应成为有效课程。每门课程可以编辑、删除，修改课程或开始日期/每日上限后可以再次生成正确的新计划。

为方便我实际操作和验收，表单请用可见且关联到输入框的 label：`开始日期`、`每日上限（小时）`、`课程名称`、`考试日期`、`剩余小时`。用按钮 `添加课程`、`生成计划`；课程表 caption 为 `课程列表`，每行有 `编辑`、`删除` 按钮。编辑时回填同一组课程输入框，修改后用 `保存修改` 按钮保存。计划表 caption 为 `复习计划`，列名包含 `日期`、`课程`、`小时`，一行表示某天某门课程的小时数；日期显示为 YYYY-MM-DD，小时显示数值，可带“小时”单位。计划排序和具体拆分方式由你决定，不要求某个内部算法或函数名。状态、错误与不足提示请放在可见的 `role="status"` 区域，成功时清除旧的不足提示。课程列表中也显示该课的考试日期和剩余小时，便于编辑前检查。

使用 localStorage 保存课程、开始日期、每日上限和当前计划；页面刷新后仍能看到刚才的数据与计划。手机宽 390px 时能添加、查看和操作，页面整体不能横向溢出。可以让计划表自身横向滚动。请提供 README，说明本地预览、GitHub Pages 发布、自测方式和排程规则/限制，做有意义的自测。空目录交付 index.html 及所需资源即可；不需要构建工具或安装依赖。界面请清楚、好用，但不要求特定配色。

## 执行约束与预算

- 总预算：70 工具步、40 模型轮、20 分钟，澄清阶段也计入；中断恢复消耗剩余预算。
- 产品最多一次定向返修；相同服务故障最多一次人工恢复。首次结果和后续结果分别保存。
- Aster 通过真实公开 CLI 运行，操作员不调用其私有 Runtime 接口代替产品入口，不代写产品实现。
- 候选在评估运行目录内生成；可用交付后复制到 `exam_project/`。不改 Aster 根目录结构。
- 模型 profile、Aster Git SHA、协议和评分器 SHA256 在启动前冻结。模型身份/usage/基础设施错误分别报告。
- `ask_user` 先于产品实现的轨迹、Aster 自测、README 使用说明由运行证据单独验收，浏览器通过不能替代这些门槛。

## 独立验收与评分器自检

`study-grader.py` 只通过上述公开 UI 填表、点击、读表、刷新；不导入候选函数、不读候选 localStorage 的私有结构、不把候选自测当作独立验证。每项浏览器场景使用全新的浏览器上下文。检查多课总量、每日上限、逐课截止日期、小数小时、容量不足与过期考试、编辑删除重排、设置变化、刷新持久化、390px 手机操作和无外部网络依赖。排程顺序不限。

独立 oracle 检查所有输出行的约束，并按截止日期的累计需求和此前容量计算最少不可安排小时数：所有课程从同一开始日可学习，小时可拆分，因此最大累计超额就是最少欠缺。既不拿某一份固定排程逐行比较，也不复制候选算法。

```bash
# 评分器自己的正负自检：只验证独立排程 oracle，不生成候选网页、不调用模型
/home/dzh/.conda/envs/aster/bin/python -m pytest -q evaluations/v0.2-release/test_study_grader.py

# 候选已存在时才运行；输出路径必须是候选目录之外的新文件
/home/dzh/.conda/envs/aster/bin/python evaluations/v0.2-release/study-grader.py \
  /absolute/path/to/candidate --output /absolute/path/to/new-study-result.json
```

评分器复用 `evaluations/benefit-20260918/check_browser.py` 的只读静态服务器，使用 aster 环境已安装的 Playwright/Chromium，不新增依赖。截图、逐项结果、外部请求记录和基础设施错误保存到结果旁。所有必需场景通过才可宣称浏览器验收通过；单个小项目不构成泛化或统计收益证明。若评分器有误，保留原版/原结果，说明修订后另存结果，不能覆盖首次失败。
