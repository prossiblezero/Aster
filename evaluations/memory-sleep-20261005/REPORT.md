# 自动学习与异步 Dream：十题结果

运行始于 2026-10-06，2026-10-07 收尾。两组各 10 题、22 个会话，各运行一次；源码、任务与驱动在运行前固定。没有用补查替换失败样本。

自动补存和经验迁移已在真实模型上跑通：正常完成且通过验收从 **4/10 → 7/10**，独立功能检查从 **4/10 → 9/10**。但预设的 8/10 完成率和降耗目标没有达到：已报告总 token **增加 12.6%**，后续会话增加 **20.0%**。两组都存在缺失 usage，基线还有三个后续会话因服务错误终止，因此不能把分差全部归因于记忆，也不能用这轮宣称实际费用下降。

## 条件与版本

模型为 `.env` 配置的 `gpt-5.6-luna`、Responses；两组均开启 Memory、Evolution、Dream，关闭 Worker。旧版已能提炼知识、响应修复提醒，新版增加独立后台提炼及整理、召回修正和父任务预算收尾。学习提示不要求“记住”，不预填记忆；每次混入明确临时标签。源文件与学习后代码均继续可读。

预算、隐藏断言和退出行为见[运行前协议](PROTOCOL.md)、[任务](cases.py)与[驱动](run.py)。两组在独立进程/工作区执行；没有重新运行失败任务。实验使用内部开发题，不是公开 benchmark 或未见测试集。

- 基线：[源码](baseline-sources.zip)、[哈希](baseline-source.json)。这是改造前工作区的快照，包含当时未提交代码，不等同于某个 Git 提交。
- 主对照新版：[源码](sleep-sources.zip)、[哈希](sleep-source.json)。所有主表数字属于这份冻结代码。
- 最终交付：[源码](final-sources.zip)、[变更与哈希](final-source.json)。随后修正后台输出的必填适用范围、TUI 的最终状态展示，未发出请求就退出时的预算释放，以及历史预览/新分支的费用归属；没有重跑整组。
- 统计：[汇总代码](summarize.py)、[summary.json](summary.json)。各题目录保留学习/后续摘要、压缩 trace、代码产物和维护候选；来源网页核对另存 [research-sources.json](research-sources.json)。

## 质量与自动学习

| 指标 | 基线 | 后台整理版 |
|---|---:|---:|
| 正常完成且通过验收 | 4/10 | 7/10 |
| 只看独立功能检查 | 4/10 | 9/10 |
| 学习与后续均完成且后续通过 | 4/10 | 7/10 |
| 约束满足率（自定义） | 13/30（43.3%） | 27/30（90.0%） |
| 后续阶段有最终答复（含错误与部分答复） | 6/10 | 10/10 |
| 学习阶段结束时已有知识的任务 | 2/10 | 5/10 |
| 后续结束时，已保存学习来源知识的任务 | 2/10 | 6/10 |
| 后续召回过学习来源知识的任务 | 2/10 | 6/10 |
| 完成且召回学习来源知识的任务（自定义迁移指标） | 1/10 | 5/10 |
| 临时演示标签误入长期条目 | 0 | 0 |

后三项按条目的来源任务 ID 统计，包含在后续会话才完成的后台提炼，不能只看学习结束时的快照。成功并召回不等于记忆是成功的唯一原因；普通源文件与早先代码仍可查阅。

新版共有 **14 次新增/替换回执，14/14 均对应当时保存的条目**；它检验“说已保存”是否确实落盘，不代表 14 条知识都通过了独立语义验证。23 次维护请求产生 21 个提交结果（其中有空操作或全部候选被拒绝），2 次取消。拒绝原因包括 7 项遗漏适用条件、1 项缺少较新用户纠正、1 项暂态内容、1 项缺少修复验证；没有立即为同批拒绝追加请求。

具体案例：

- [报表时区](results/sleep/01_timezone/learn-1.json)：前台只确认约定、没有调用记忆工具，后台写入 Asia/Shanghai 和格式约定；新会话完成三项检查。
- [CSV 分批补充](results/sleep/03_csv/maintenance.json)：两次交互的编码、分隔符与列规范被整理为同一条有效约定，后续导出通过三项检查。
- [支付修复](results/sleep/07_repair_transfer/learn-1.json)：真实失败及测试通过后保存字段优先级和十进制舍入方法；[退款任务](results/sleep/07_repair_transfer/reuse.json)召回该条目并通过 3/3 检查。旧支付代码仍可读，不能据此声称记忆独立导致成功。
- [适用范围](results/sleep/09_scope/maintenance.json)：学习阶段整理超时取消，下一任务处理中继续提炼旧材料；后续按 analytics/public_api 的不同约定完成。全批两次取消的 usage 未知，未算作免费。

## 成本与延迟

| 指标 | 基线 | 后台整理版 | 变化 |
|---|---:|---:|---:|
| 学习会话已报告 token | 352,437 | 323,682 | −8.2% |
| 后续会话已报告 token | 986,703 | 1,183,578 | +20.0% |
| 全部会话已报告 token | 1,339,140 | 1,507,260 | +12.6% |
| 其中后台维护 token | 0 | 117,263 | 已包含在总数中 |
| 后续工具次数 | 169 | 183 | +8.3% |
| 后续文档读取 | 5 | 5 | 持平 |
| 后续测试断言失败次数 | 1 | 0 | 少 1 次 |
| 会话前台耗时之和 | 2,277.6 秒 | 1,572.2 秒 | −31.0% |
| 会话总耗时之和（含维护收尾） | 2,277.7 秒 | 1,758.6 秒 | −22.8% |

这些是全部尝试之和，包含失败；耗时相加不是两组并行执行的墙钟时间。基线服务失败和重试更多，不能把耗时差写成异步整理带来的加速。供应商用量覆盖为 **141/151 次尝试 → 174/179 次尝试**，其余未知；不把部分已报告总量称为完整实际费用，也不提供美元估价。

维护成本按发起调用的会话入账，因此后续阶段也可能承担上次未完成的提炼。后台记录的用量属于总 usage 的子集，不能再加一遍。按 14 次成功写入操作计算，平均为 **8,376 个已报告维护 token/次写入**，包括空操作、拒绝等开销，缺失部分另列；这不是每条“正确知识”的价格。

输入 4,096 是本地完整请求的估算门槛，输出上限设为 768。实际供应商报告可能更高。例如第一次时区维护本地预留 1,709 tokens（含输出），实际报告 5,136；最终账本采用实际报告。程序能限制调度和事前预留，无法把估算误差说成绝对计费上限。

## 只补查一个具体缺陷

金额题中，模型提炼出了规则，但冻结版 schema 允许省略 `when`，入库时以 `memory_scope_required` 拒绝；新会话没得到金额约定，写成了不符要求的规则。最终版将适用条件设为结构化输出的必填字段，并在提示中明确要求。

[唯一一次金额补查](supplement/scope-required/result.json)只验证学习与保存：前台未调用存储工具，后台成功保存 Decimal、ROUND_DOWN、负数向零截断和固定两位输出，适用范围非空。维护 1 次、5,299 个报告 token；含前台的补查共 11,847 tokens。没有再跑后续编码，不能把主表 7/10 改成 8/10。

## 工程检查与交付边界

完整工程检查为 **1,170 passed、4 skipped**，见 [test-results.txt](test-results.txt)；4 项跳过来自环境缺少 Go。之后补齐历史预览与新分支的后台费用归属，[36 项相关回归](history-accounting-tests.txt)通过；网站生成与传输的 [25 项检查](site-test-results.txt)通过。这些回归存在重叠，不相加当作独立任务数。`test_memory_maintenance.py` 覆盖自动学习、来源变更、合并、更正优先、取消恢复、跨会话单请求、无操作、API/格式失败、原子提交失败、账本和预算收尾。TUI 检查确认真实保存状态会展示出来。这里使用受控模型输出，不混入十题成功率。

本次交付保留本地 JSON、最多 64 条记录、现有模型与三个默认开关，不增加运行依赖、独立服务、图数据库、模型训练或自动生成 skills。整理期间正文变化会使整批候选作废，可能损失一次提炼机会；词面召回和模型归纳仍有局限。固定十题的结果支持保留自动补存能力，尚未证明整体降耗或普遍任务质量提升。
