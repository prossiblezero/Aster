# 显式 any / all 等待对照（2026-10-02）

本协议、源码、评分修订、运行顺序和驱动在模型任务回合前冻结。目标是判断父方只剩最终整合时，等待全部子任务能否减少协调消耗；同时测量首份交付的延迟，不预设速度收益。

## 同版三组 × 六题 × 两次

- `solo`：父任务独立完成。
- `any`：同时启动两个只读子任务，父方首次调用 `worker_status(ids, wait_seconds=300, wait_for="any")`。
- `all`：相同两个工作包，父方首次调用中仅将 `wait_for` 改为 `all`。

三组均使用同一个冻结候选版本；双子任务的分工、预算、父方任务和模型配置相同。首次等待由驱动通过真实 Runtime 工具路径执行，计入父历史和额度；随后模型自主运行，可以按新提示自行选择等待方式。因此这是首次等待策略的对照，不是把整段运行强制锁定在一种模式，也不验证模型自主选择模式的能力。

复用此前六道已见只读调查/受限审查题，不更改题目、工作包或输出契约。每组每题两次，共 36 个首次回合、每组 96 个事实。每次重复按六种三组排列轮换，第二次反转各题顺序；每组在每个位置出现四次。回合串行，回合内子任务真实并发。全部首次结果保存，不择优重跑、不修补答案、不丢弃失败。

模型、端点来自现有配置；任务回合限制沿用 36 次全队模型请求、60 次工具、300,000 已报告 token、600 秒。只读、Memory 关闭、网络工具关闭、严格完成门槛、读取并行度 1、64k 上下文、8,192 输出上限。冻结配置身份、端点哈希、Python 与依赖版本哈希。`.env` 和密钥不进入公开文件。健康请求单独记账；若服务拒绝健康请求，不启动整批。若任务回合的全部 HTTP 尝试均被拒绝，停止后续回合并保留该次失败。

## 评分修订先于模型调用

行为 oracle 和 grade 逻辑沿用旧驱动；本次预检递归遍历完整 AST，补齐函数体中的嵌套函数和条件分支内的定义。逐项断言保留旧索引的全部合法范围，并检查新增嵌套符号的正例、错误行号/越界/不存在符号/拼接符号、错误行为、缺项和重复项的负例。

评分仍要求对应候选文件中的真实符号与符号内行号；索引校验不证明引文在语义上足以支持该结论。历史报告的冻结评分不变；不能把本次分数与旧索引分数直接当作策略收益。

## 指标

主指标为严格整题通过、事实正确、全队已报告 token 和端到端耗时。通过还要求父运行正常完成、工作区和候选源码未变、驱动无异常。补充独立列出纯行为答案通过，避免把引用定位错误等同推理错误。

记录首个子任务终止时间、首个子任务正常完成时间、父方首次收到交付时间、父方首次模型请求/响应时间、最后子任务完成时间，以及初次等待持续时间。交付收到以父方 `worker_status` 返回带交付的快照或自动 handoff 事件为准，不能将孩子内部完成时间当成父方已可使用结果。端到端用单调时钟；跨运行轨迹相对时间用同机 UTC 事件时间。Solo 无子交付指标。

统计父方模型调用、协调工具、提前唤醒、重复读取行段、worker_finish 失败及已报告用量；保留 HTTP 重试和缺失 usage，不将未知费用记为零。对耗时、token 报告每题每次配对比值及中位数，另列总量。两次重复仍不足以推断统计显著性或普遍收益。

本实验仅覆盖显式分工且父方只剩整合的任务，不覆盖依赖首份交付才能开工的下游工作、写入合并、动态拆分或自主委派。默认 any 的响应优势通过事件控制测试保留，不能由此批纯整合样本推广为全局改用 all。
