# 会话改造后的真实编码质量与消耗

**这组真实编码任务没有观察到通过率下降，也没有逐题从通过变失败。** 默认核心工具集两版均为 **5/5（100%）**，完整工具集两版均为 **4/5（80%）**。结合此前固定工作流操作数减少 47.8% 的独立结果，可以说操作更方便、这组编码回归质量持平；不需要声称会话管理提高了模型能力。

此前 [会话操作评测](../session-ux-20260920/REPORT.md) 使用离线模型，18/18 是操作工作流完成数，没有测真实编码通过率或 API 费用。本次补充这项缺口，保留原报告与其冻结清单。

## 版本与判分

基线 `a3f338b`，候选 `edec1aa`（包含会话树、鼠标入口与测试分层）。两版使用独立干净 worktree，Conda aster Python 3.12.14，显式指定各自 `src` 并核对实际导入路径。任务、fixture、评分器和现有驱动在两版间完全相同。详见运行前 [协议](PROTOCOL.md) 与 [配置身份](environment.json)。

固定模型 `gpt-5.6-luna`、Responses、非流式，同一服务配置与默认采样参数；有效上下文预算 908,668、输出预算 32,768，每次 32 步／24 轮。两版进程同时启动，各自任务并发为 1。每题每工具集一次，**5 道既有仓库题 × 2 种工具集 × 2 个版本 = 20 次真实尝试**，无选择性重试或评分器改动。参考动作仅用于预检，不交给真实模型。

“完整任务通过”要求 Runtime 正常完成、满足任务合同且独立代码测试通过。代码测试在执行结束后加入隔离评分副本，核对 JUnit 名称、数量与结果；模型自述完成不算验收。

| 工具集 | 旧版完整完成 | 新版完整完成 | 旧版独立代码验收 | 新版独立代码验收 | 逐题退步 |
|---|---:|---:|---:|---:|---:|
| core（默认） | 5/5，100% | 5/5，100% | 5/5 | 5/5 | 0 |
| all | 4/5，80% | 4/5，80% | 5/5 | 5/5 | 0 |

每版共 9/10 次完整完成、10/10 次代码验收通过。core/all 是两个配置条件，不能合并成“每题两次重试”，本批不报告 Pass@2 或 Pass@3。

## 消耗与耗时

以下包含失败尝试，token 均为服务端**已报告用量**，不是本地估算，也不是账单金额。

| 工具集 | 版本 | 模型调用 | 工具调用 | 已报告总 token | 每次平均 token | 每次平均秒数 |
|---|---|---:|---:|---:|---:|---:|
| core | 旧版 | 34 | 83 | 283,567 | 56,713.4 | 60.12 |
| core | 新版 | 35 | 84 | 291,525 | 58,305.0 | 58.82 |
| all | 旧版 | 39 | 102 | 367,677 | 73,535.4 | 75.93 |
| all | 新版 | 31 | 90 | 270,354 | 54,070.8 | 72.21 |

core 已报告总 token **增加 2.8%**，all **减少 26.5%**。只看两版共同成功的任务，core 仍为上述 5 题；all 排除两版都未正常完成的重构题，4 题总 token 为 **278,594→204,313（减少 26.7%）**。完整配对与逐项覆盖见 [comparison.json](comparison.json)，不因失败更早结束而单独宣称节省。

| 工具集 | 版本 | 输入 token | 输出 token | 缓存读取 token（输入的子集） |
|---|---|---:|---:|---:|
| core | 旧版 | 277,541 | 6,026 | 176,640 |
| core | 新版 | 285,442 | 6,083 | 220,672 |
| all | 旧版 | 360,055 | 7,622 | 247,296 |
| all | 新版 | 264,108 | 6,246 | 200,704 |

**实际货币费用未测。** 没有该网关的计价信息与账单，不用模型名称推算价格。缓存读取包含在输入中，不能再次相加；未报告的缓存写入等字段保留为未知。

逐条 trace 核对发现：两版在 `dependency-upgrade/core` 都发生 **1 次 transport 自动重试且未返回 usage**。旧版 73 次逻辑模型调用对应 74 次 HTTP 尝试，新版 66 次对应 67 次；有总 token 的 HTTP 尝试分别为 **73/74、66/67**。缺失重试的消耗未知，不按 0 计。原驱动的 `usage_summary.complete` 以逻辑模型调用为分母（73/73 与 66/66），所以不能单凭这个字段断言覆盖所有 HTTP 消耗；新增 [请求核对记录](provider-audit.json) 和比较文件单独列出 HTTP 覆盖。all 条件没有缺失 usage 的 HTTP 尝试。

模型行动存在采样波动，网关缓存与服务延迟也未受控；耗时包括模型与工具运行、不含事后独立评分。因此本批用量和耗时差异是观测结果，不足以把 all 条件的下降归因于会话改造，更不能承诺稳定降低费用。

## 结论范围与简历表述

本批是 **5 道已用于开发的仓库小题**，每题每条件一次；它支持“这组回归未观察到质量下降”，不能证明统计非劣或所有真实任务都不退步。任务从新会话开始，未测真实模型在分支切换、摘要交接或多会话并行后的任务质量；这些仍需另外设计专项。

操作收益沿用此前候选 `1fee848` 的命令流程结果，本批候选 `edec1aa` 还包含后续鼠标入口。操作数减少 47.8% 不是鼠标操作的人效，也不是成本下降。可以按不同测量范围如实写：

> 实现会话树与多会话终端交互，在六类固定工作流中将规定操作数由 69 降至 36（减少 47.8%）；补充 5 道仓库题、两种工具集的新旧版本真实模型回归，任务完成率分别保持 100%／80%，独立代码验收均通过，未观察到逐题退步。

若简历篇幅有限，保留操作数这一主要收益，将质量与消耗对照放到项目报告；不把未确定的费用收益写入简历。
