# 优化后 Aster：固定二十题完整复测

2026-10-11。在模型调用前冻结本协议、源码 diff、运行时、运行器与数据哈希。

本轮对原二十题各执行一次全新 Aster 尝试，不与旧答案合并择优。pi 和 Codex
沿用原始 15/20、14/20；Aster 原始 12/20 与五次补测后 15/20 均保留。
已经分析旧轮失败，因此本轮是开发集上的复测，不能称为未见测试集或稳定排名。

模型仍为 gpt-5.6-luna / medium，Responses 接口，上下文 64000、输出上限 8192，
每题 900 秒、4 CPU / 8 GiB、空会话、单 Agent。两题并发；不额外扩大单题预算。
任务、题面、原生镜像、独立评分断言和评分器沿用原轮。隐藏测试只在 Agent 结束后
注入，参考解和旧答案不提供给 Agent。全部尝试均计入用量与失败，不静默重试。

生产改动：沙箱为每个命令分配独立于项目树的 TMPDIR，防止临时项目继承仓库配置；
明确执行副本中的相对路径约束；提示实际接口的复现、邻近回归、类型/顺序/空输入
和生命周期验收，优先交付实现与测试。没有任务 ID、参考补丁或隐藏测试断言进入提示。

评测环境改动：Landlock 启动器使用 Aster 自身 Python，任务命令使用镜像解释器，
只读开放其运行库路径，兼容 Python 3.6。两个 pytest 任务均采用先前重跑的当前目录
src 导入和已有生成版本文件适配。gRPC 沿用前次重跑的专用容器后台进程适配；
这部分仍属于评测适配，并非生产 Aster 支持持久服务。其他命令保留生产沙箱限制。

先执行无模型的环境预检及生产测试，再冻结正式版本运行完整二十题。正式运行开始后
不修改源码或本轮适配器。不因独立评分失败改题或追加单题尝试。

主指标为独立测试整题通过数；另列正常最终交付、内部完成但独立失败、超时、供应商

与生产优化的因果收益混为一谈。
