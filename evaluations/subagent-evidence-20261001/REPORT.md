# 子 Agent 证据交付：实现与三组对照（2026-10-01）

**完成轻量机制修复，尚未证明应默认启用委派。** 本轮生产净增 **80 行（0.68%）**，仍为 55 个 Python 文件，零新增运行依赖。真实模型对照中，新并行严格通过 4/6，旧并行 3/6；新并行全队已报告 token 少 16.3%、耗时合计少 37.0%。但新 Solo 也通过 4/6，新并行仍消耗其 2.80 倍 token、1.62 倍时间；父方重复读取没有下降。忽略引用的完整行为通过，旧并行反而是 5/6、新并行为 4/6，不能只用严格通过数宣称理解能力提高。

## 版本、任务与控制

- 六道已见的只读调查/受限审查题，来自 Django、OpenLibrary、终端会话三个源快照；调查与审查复用来源，不能当作六个独立代码项目或原 benchmark 官方成绩。
- **6 题 × 3 组 × 1 次 pass@1 = 18 次**，全部完成。保留全部首次结果，没有挑选成功重跑、修改评分或修补输出。六种组内顺序各用一次，回合顺序执行，Parallel 内两个真实子 Runtime 并发。
- 旧并行生产源码来自 `ef471322d2291fe253e152a6efa5bb389bcf0ca0`，包含此前快照隔离修复。新 Solo 和新 Parallel 使用同一份 candidate 源码。两个版本逐文件 SHA-256、驱动、评分器、数据及配置在调用前冻结，见 [FREEZE.json](FREEZE.json)、[candidate.patch](candidate.patch) 和 [PROTOCOL.md](PROTOCOL.md)。
- 同模型及 Responses 配置；144 次模型响应报告的名称均为 `gpt-5.6-luna`。各回合团队上限相同：36 次模型请求、60 次工具、300,000 已报告 token、600 秒。Memory 关闭，只读工具并行度 1，父方严格完成检查开启。
- 两组 Parallel 都由驱动显式分派相同两个工作包，再让真实父 Runtime 整合。本轮**没有评测模型自主拆分、写入任务或默认开启委派的效果**。新版 Solo 用于区分读取行号改进与委派本身的表现。

## 事后诊断：引用改善，格式和行为问题仍在

下表是冻结评分字段的事后解释，不修改主成绩，不自动修复 JSON；行为完整通过仍要求正常运行、ID 完整且唯一、工作区/源码未改变。

| 组别 | 行为完整通过 | 已确认行为/分类正确事实 | 仅引用失败 | 实际值错误 | JSON 不可解析回合 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 旧 Parallel | 5/6 | 47/48 | 3 | 1 | 0 |
| 新 Solo | 4/6 | 38/48 | 0 | 2 | 1 |
| 新 Parallel | 4/6 | 39/48 | 0 | 1 | 1 |

两个新版的不可解析回合各有八条无法逐项计分，**不能当作八条行为理解错误**。所有组的可解析审查分类错误均为零。

具体失败保留在 results.json：

- 新 Solo 和新 Parallel 的 Django 调查均生成了括号不匹配的最终 JSON；没有用评测器修复后补分。
- 新 Parallel 的 OpenLibrary 审查把实际键名 `subject:b` 写成 `subject:B`。子任务已作出这个错误推断，父方重读后仍保留它。这是行为值错误，不能靠交付状态、文件哈希或正确行号担保。
- 旧 Parallel 的终端会话调查/审查行为正确，分别有 1/2 条引用位置失败；新版并行两题均严格通过。新 Solo 的终端调查有两条行为值错误。

## 效率变化来自哪里，仍缺少什么

新旧 Parallel 的模型请求为 **56 对 69**，工具调用为 **95 对 143**。子任务 search 调用从 **40 降到 4**，子任务 read_file 从 41 降到 36。这与直接提供行号后减少定位搜索的方向一致；同时改了交付和提示，没有单独消融，不能把全部变化都归因于行号。

父方 read_file 仍是 **31 对 31**，其中路径均被子任务读过。主代理累计输入相对旧并行仅减少 **1.6%**。**本轮没有实现真实模型层面的父子读取去重。** 路径重叠也不意味着每次都读取同一行段；某些复核有必要，不能为了降低指标禁止父方读取。

源码摘录现在可以满足观察门槛，离线测试确认父方可不重复调用 read_file 完成纯调查；真实模型仍选择了读取。当前摘录受限为每路径最后一次读取的开头，可能没覆盖关键引用。它提供了可核验交付的基础，不等同于完善的证据选择策略，更不等同于结论自动正确。

相对新 Solo，新 Parallel 主代理累计输入减少 **10.7%**，但全队 token 增至 **2.80 倍**。这些任务都是给定探针的小型代码片段，单代理已很适合处理。默认继续采用 Solo，按用户需要使用独立调查/审查；自主派工保持默认关闭。此次没有加入路由模型、固定多角色流程或更大并发。

## 运行、记账与复现

两组 Parallel 共 **24/24** 个子任务正常完成。18 个父任务均正常结束；没有 runner 异常、源码/工作区变化或已知 usage 对账不一致。正常结束不是答对，所有错误仍计入主表。

144 次请求共报告 **1,588,391 token**；HTTP 重试和缺少 total usage 的尝试均为 **0**。没有冻结供应商价格表，不把 token 变化换算为金额；缓存输入和服务时延也影响实际成本与耗时。

全量回归 **1,087 passed、4 skipped**；独立 wheel 安装路径下 **55 passed**，55 个生产源码文件与 wheel/安装结果逐字节一致。取消、迟到交付、token 不足续问、权限及快照边界由离线回归验证，不将其归功于这批只读模型分数。
