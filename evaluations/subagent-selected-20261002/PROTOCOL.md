## 四组，24 个首次运行

1. baseline_parallel：本轮修改前的 2026-10-01 代码，两个子任务同时调查，均交付后父任务整合。
2. candidate_solo：本轮代码，父任务独自完成。
3. candidate_parallel：本轮代码，沿用 baseline 的两个工作包和等待顺序，隔离证据交付改动。
4. candidate_overlap：本轮代码，第一工作包交给一个子任务，父任务同时处理第二工作包并整合。用于探索父方也有独立工作的调度方式，不与前三组混算。

每题每组仅一次 pass@1，保留全部首次结果，不择优重跑、不修补模型答案、不改变评分。六题使用 evaluate.py 中固定的六种组内顺序；每组在各位置出现一到两次。回合串行执行，回合内部使用真实 Runtime 并发。

模型、服务配置、源快照、完整问题、工具权限及团队上限相同：36 次模型调用、60 次工具、300,000 已报告 token、600 秒。Memory 关闭，严格完成检查开启，只读工具并行度 1。评测驱动显式分工，**不评测自主任务拆分、写入任务或默认开启委派的效果**。

## 冻结与记账

修改前已将 checkout 的 55 个生产文件复制到 private/baseline，并逐文件记录 SHA-256；它包含上一轮尚未提交的改动，不能以 Git HEAD 代替。调用前冻结 candidate、驱动、协议、数据、原评分器、配置身份与端点哈希；密钥不进入公开输出。实际子进程导入指定冻结源码，运行前后重新核对。

主指标：严格整题通过、严格事实正确、全队已报告 token、总耗时。严格通过还要求正常结束、源码与任务工作区未改动。无法解析的 JSON 仍失败，不将八个无法计分项解释为八个语义错误。

诊断指标：父方读取次数；成功读取行数；其中被子任务更早读取过的相同行段（路径、文件哈希均相同，按每次父读取累加）；worker_finish 的尝试/接受次数和已选源码字数；父方在最后一个子任务完成前收到的模型响应数。行段重叠说明重复观察，不自动证明该次复核没有必要；早于子任务完成的父响应也不等同于有用工作已完成。

所有调用及有界 HTTP 重试计入原 ledger；未知 total usage 单列。时间包含执行与交付，token 为全队账本值，不换算未冻结价格的金额。六个配对、每组一次不能据此作显著性或普遍能力结论。
