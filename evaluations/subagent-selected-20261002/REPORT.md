# 精选源码交付与父子分工（2026-10-02）

**实现与离线验证完成；真实模型效果未验证。** 本轮解决“交付片段只取读取开头，可能漏掉支撑结论的代码”的接口问题。模型服务鉴权失败使 24 个计划回合均未得到答案，因此不能声称父方重读减少、通过率提高或成本下降。

## 本轮改动

子任务可以通过 `worker_finish(answer, sources)` 一次提交答案和支持行段。每段给出已有证据 ID、起止行与结论标识；运行时从真实读取事件提取原文，验证范围、文件版本和子分支归属。可以选择同一文件的多个位置及更早的读取，避免只收到文件开头。最多四段，正文合计 4,000 字符；超量返回反馈，不静默截掉论据。

交付工具只对子任务可见。它消耗一个正常工具额度，复用原有 Final 检查，无须额外模型轮次重述答案。任务要求 JSON 对象时，子任务可直接传对象，由程序序列化；这不保证父任务最终 JSON 或答案内容正确。

父方收到有效源码可以满足观察门槛，仍须亲自读取编辑目标、验证集成结果。来源标签是模型主张，哈希只证明版本；内容正确不意味着推理正确。提示改为对照所选行段审查结论，并针对缺口补查。

旧文本交付和预算耗尽的部分交付继续回退既有短摘录。新选择与读取证据索引随原子快照保存，旧分支不能引用未来或兄弟分支证据；即使复用某个工具调用 ID，也不能越过历史边界。续问清除旧的交付选择，但允许重新选择仍有效的历史读取。

生产源码 **55 个 Python 文件，11,907 → 11,993 行，净增 86 行（0.72%）**；改动八个既有文件，零新增运行依赖、配置项或服务。父任务和 Solo 的工具目录不增加新工具。相对上轮的增量见 [candidate.patch](candidate.patch)，计数见 [code-metrics.json](code-metrics.json)。

## 验证结果

- 完整回归：**1,098 passed，4 skipped**，151.21 秒。
- wheel 独立安装路径下，Worker、精选来源和工具契约检查：**163 passed**，38.70 秒。
- checkout、wheel、安装目录的 55 个生产文件逐字节一致。
- 新增 11 个参数化回归案例，覆盖中间行与早先读取的交付、无额外模型轮次、未读/反向/过期/超量/兄弟来源拒绝、脱敏、快照恢复、调用 ID 复用、父方权限以及编辑和测试完成门槛。
- 第 13 章运行示例通过；教学网站重新生成，全套 **25 passed**。Ruff 和差异空白检查通过。

这证明接口和生命周期可以按设计运行，不证明真实模型会选择正确证据或减少父方读取。安装验证复用同一 Conda 环境的依赖，不宣称跨操作系统或完整隔离环境的兼容性。详细记录见 [VERIFICATION.md](VERIFICATION.md)。

## 真实模型对照：因 HTTP 401 无有效样本

按[事前协议](PROTOCOL.md)，复用六道已见只读题，固定四组：上轮并行、新 Solo、新双子任务、新“父方＋一个子任务同时工作”。前两种并行组使用相同的两个工作包并等待子任务后整合；最后一组让父方同时完成另一工作包。仍是脚本显式分工，不评测模型自主拆分。

修改前源码已单独保存，并与 2026-10-01 的已评测 candidate 逐字节核对；没有用 Git HEAD 代替未提交基线。新旧源码、驱动、协议、评分器和配置在首次请求前冻结，见 [FREEZE.json](FREEZE.json)。模型和端点配置与上轮一致；已确认凭据来自项目 `.env`，不是被环境变量覆盖。

24 个首次回合在约半分钟内全部因服务鉴权失败而结束，未择优重跑或替换。账本记录 **54 个 HTTP 尝试：51 个 request_rejected（运行轨迹中均为 401），3 个随父任务失败而取消**。没有成功模型响应或可评分答案，所有尝试均未报告 total usage。统计中已报告 token 合计为 0，仅表示没有 usage 数据，不能解释成零成本。

原始评分中的四组 0/6 是服务失败造成的，**不属于模型能力比较**。失败请求耗时不能当作执行加速，零工具调用不能当作消除了重读。所有任务工作区及冻结源码均保持不变，没有 runner 异常。机器可读诊断见 [diagnostics.json](diagnostics.json)，首次结果和机械汇总仍完整保留在 results.json、summary.json。

恢复有效凭据后，应另建运行批次、原样运行全部四组，保留本次失败记录。本轮继续保持 Solo 默认、自主委派默认关闭；精选交付的真实收益及“父方＋一个子任务”的调度收益仍待验证。
