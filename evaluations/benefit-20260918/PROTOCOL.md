# Campus Planner 实战与机制收益验证

日期：2026-09-18。状态：运行前协议。用户授权真实模型测试、整理实验目录及按职责拆分长模块。

## 目录与责任

- `exam_project/campus_planner/` 只发布 Aster 编写、通过验收的可运行产品与使用文档。所有开发副本、驱动、评分器、轨迹和对照报告留在本实验目录。
- 操作员编写需求、公开规则、技能工作流和独立验收；候选 HTML/CSS/JS、产品 README、自测以及返修由真实 Aster Runtime 完成。操作员不手工补候选实现。
- 使用 aster 环境；required 沙箱，项目代码禁网，模型连接使用已有凭证但不记录凭证/端点。产品无需第三方运行依赖，以 Python 静态服务启动、浏览器交互、Node 内置测试运行器自测。
- Runtime 解耦通过回归后冻结源码提交与文件摘要。本目录协议、需求、规则及验收文件在首次产品请求前保存摘要；运行后的调整单独记录，不能覆盖失败。

## 实用场景

大学生需要集中管理不同课程的作业和截止日期，勾选完成、查找临近任务、备份数据，并导出到手机日历。基线从只有需求/规则文档、没有实现代码的目录起步，实现可用的本地网页。

## 基线开发与交付

固定 gpt-5.6-sol / Responses，128000 总上下文，32768 单响应输出，单请求超时180秒；最多80工具步、50模型轮、1800秒。stream关闭、只读并行1、Worker关闭；启用Memory但关闭evolution/Dream，观察自然保存，不在需求中提示保存操作。技能未配置。

独立浏览器验收在候选范围外运行，覆盖首次空状态、添加/编辑/完成/删除、搜索与筛选、刷新持久化、排序和过期标识、移动端布局、损坏存储与存储写入失败；检查实际可点击交互，不以模型自测代替。基线有缺陷时允许最多两轮具体返修，分别记录人工反馈与原失败，不算首次自主成功。

## Skills 对照

从相同且通过基线验收的候选快照派生两类维护任务：JSON备份导入、日历ICS导出。每类两个条件，仅技能包的发现入口不同：普通文档组与Skill组都能读取相同公开领域规则和工作流，Skill不包含隐藏答案或专属验收条件。

固定顺序为：备份普通文档→备份Skill；日历Skill→日历普通文档。每条件一次，共4次；每次最多55工具步、35模型轮、1200秒，其余模型配置与基线一致，Memory关闭。不根据结果追加抽样。两个任务只是小样本试点，不作统计显著性或普遍收益结论。

记录所有独立验收项、实际技能发现/正文/资源调用、错误、模型轮、工具步、真实usage及覆盖率、端到端时延。每个任务的候选都须回归基线功能。选合格候选作为功能合入来源，由Aster继续完成另一项功能并验收；合入成本单列，不混入对照。

## Memory 验证

分开报告三个问题，不把保存0解释成检索无效：

1. 基线开发中的自然发现/保存漏斗，允许保存0，不追加诱导提示来改分。
2. 操作员通过真实read_file→memory_store建立有来源的规则摘录，保持源文件可读且字节不变；无模型的检索诊断覆盖中文改写、无关查询、来源变化后失效。这是机制诊断，不算自主学习。
3. 相同项目快照、有效记忆与规则文件下，两个新的只读项目答疑任务分别开启/关闭Memory。固定顺序交错，每次最多8工具步、6模型轮、360秒，输出上限4096。两组都有同样源文件访问权；比较答案正确性、来源引用、首请求召回和重复查找成本。此项是项目资料检索收益，不冒充代码开发收益。

禁止通过删除来源文件或阻止无记忆组读文件制造优势。纯问答与机制材料留在evaluations，不发布为exam_project产品。

## 缓存

独立小预算校准和固定轨迹布局对照见 `cache/README.md`；最多18个HTTP请求，短标记使用256输出上限，与真实编码32768上限分开。校准若始终没有明确命中，停止收益归因并记录未建立缓存阳性。真实项目usage只作观察，不与不同轨迹硬作布局因果比较。

## 指标与边界

冻结预算是上限，不要求用满。真实模型失败、未知usage、人工返修、未启动/超时分别报告；不覆盖失败目录，不为得到正收益重复试跑。已用于本次开发验收的场景不再充当未见后训练测试集。最终结论允许机制可用但本样本没有收益。
