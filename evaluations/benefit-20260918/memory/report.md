# Memory：机制可用，本轮没有资料检索成本收益

2026-09-18。四个只读问答任务按事前顺序各执行一次，全部完成，双方答案和来源均正确；没有追加尝试。开启Memory后确实在首请求召回已有摘录，但没有减少关键来源文档读取，累计输入与总token反而增加。这里只检验操作员种入的项目资料检索，不证明自主学习，也不属于编码收益。

## 实验身份与公平性

- 基线快照：`workspaces/delivery-base-finish`。其基础浏览器验收12/12，Aster正式Node测试6项通过；本问答讨论的是该产品的公开约定，备份/日历功能是否已经实现不是问题答案。
- 两组产品和公开docs起点摘要一致，复制同一个有来源Memory及种入trace；只切`memory_enabled`。launch记录的其余配置一致，产品文件前后摘要均一致。源文件始终存在可读。
- 实际统一配置为Responses流式、请求模型`gpt-5.6-sol`，128000上下文、4096单响应输出、每任务8工具步/6模型轮/360秒；流式取代原计划nonstream见[事前修订](../AMENDMENTS.md)。12个模型响应都报告`gpt-5.6-sol`，不是仅据请求别名假定实际模型。
- 协议、问题、公开规则、驱动、评分脚本及seed逐文件摘要保存在[manifest](manifest.json)。对本轮新read_file证据引用的评分修复发生于任何Memory请求之前，说明见[memory-protocol](../memory-protocol.md)。

## 自然保存与种入诊断必须分开

原基线`base`、`base-recovery-1`均0工具步失败，没有形成保存机会；后续`base-recovery-2-stream`执行28步、`delivery-base-finish`执行16步，两者也都是0次memory_store尝试、0次成功、0条自然Memory。不能把后面的手动种入写成这一开发过程自主学会了经验。

操作员以真实Runtime.step顺序执行四组read_file→tool_load(memory_store)→memory_store，分别保存存储、时区、日历身份和备份原子性的一条稳定原文；没有调用模型、没有直接伪造Memory JSON，tags为空。manifest保存原文、read_file证据ID、源文件摘要和实际工具结果。全部4条准入成功。

## 工程含义

自然保存入口未触发、持久化与召回机制成功、实际资料问答无成本收益，是三个不同结论。当前优先问题仍是保存指引/触发时机以及摘录覆盖与检索选择，而非简单启用Dream或换向量库。Memory能力说明目前与召回材料一起标为不可信观察，后续可把宿主能力策略与不可信内容分开；经验总结仍需要独立的证据准入方案，不能通过放松原文校验直接宣称实现。
