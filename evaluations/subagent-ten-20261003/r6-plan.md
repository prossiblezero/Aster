# r6：在 token 预算拒绝前交付已有发现

r5 已完成并达到原严格整题通过率分支。用户继续要求优化。本轮从 r5 的真实失败出发：Boltons 第一遍孩子花费 6 次调用、87,111 已报告 token 后被团队 token 门禁拒绝，没有模型总结；父方接管后全队消耗 276,588 token，下一请求估计 53,134，超过 300,000 上限，最终答案为空。原子任务会为轮数和工具额度预留总结，却没有为 token 额度做提前收尾。

## 取舍与实现

只给受管理的孩子增加一次提前部分交付判定，复用现有无工具 PARTIAL 路径。每次实际请求构建后，用本次输入估算加输出上限作为请求成本；若已记账 token（含在途预留）加父方原有保留量、再加两次当前请求的估计，超过团队上限，则立即改为无工具总结并重建请求。触发收尾时，重建后的请求重新估算并归档，第一份试算不额外保存请求归档或 context_built 事件；最终仍须通过硬预算准入，未知 usage 保守记账原样保留。

两次当前请求只是为“继续一次调查，再总结”留余量的启发式，不是未来上下文成本的准确预测。父方并发消费、上下文突增或供应商失败仍可能阻止总结；不保证每次都能交付。它也可能过早中断有价值调查，因此结果仍标为 partial，不视作完成或父方验收。没有 token 上限、额度充足及 Solo 路径不触发本分支。

提示抽取为 Runtime 内部 helper，复用原局部轮数/工具额度收尾。Runtime 只在已发送无工具请求后结束拒绝工具的模型响应；普通调查中刚达到工具额度时仍保留下一次总结机会。不会追加长全局提示，不增加依赖、工具、设置、持久状态、路由器或 critic，也不提高预算。暂不强制父方提交答案，先测这个最小改动。

## 研究依据

复读 [OpenHands 固定源码](https://github.com/OpenHands/software-agent-sdk/blob/84d4470acd85688b52c510532ffc83b234ebf453/openhands-tools/openhands/tools/task/manager.py#L416)：非 FINISHED 状态保留停止原因和已有 partial，finally 仍合计用量。借鉴的是部分交付不能冒充完成，Aster 的既有部分交付机制保持这一点。

[ProgRouter](https://arxiv.org/html/2608.25992v2) 方法中接近任务预算时增加成本惩罚，保留后续预算余量。这里只借鉴余量意识；没有移植其异构模型路由、在线训练或能耗目标，也不声称上述两次请求启发式复现了论文。作者标注 EMNLP 2026 Findings；本次沿用已归档预印本，未独立核实会议正式收录。2026-10-03 的来源、源码提交与内容摘要见 [SOURCES.json](SOURCES.json) 和 [RESEARCH.md](RESEARCH.md)，本轮没有把历史源码当作最新内部实现。

## 实验与保留条件

仍为同一十题、80 事实、相同 oracle、模型、执行权限和全队上限：36 模型调用、60 工具、300,000 token、600 秒，64k 上下文、8,192 输出上限。采用 r5 相同 adaptive 驱动和中性任务提示，Solo max_workers=0、team=1。预定两遍完整对照共 40 回合，第二遍反序，保留全部首次失败，不根据中间结果停测或换题。同版 Solo 重新运行，冻结配置身份；若模型或服务配置变动，明确披露比较边界。

沿用原质量和成本指标。额外检查实际委派次数、提前部分交付是否发生、其事实是否进入父方答案、预算停止与空答案数。零委派回合的分数波动不能归因于新收尾机制；自主选择的子集只作描述性分析。若没有触发新路径，本轮只能说明候选在该样本的表现，不能声称机制收益。

保留 r5 已完成结果作为现有方案。候选必须通过工程回归；若真实对照质量/成本不支持改进，保留负结果及可复现候选，继续采用 r5，不为新一轮另调评分或抬高成本门槛。若质量达标却缺乏新路径贡献证据，也不将随机得分上涨写成该改动的改善。

## 实验后的决定（2026-10-04）

40/40 回合完成。严格通过 Solo 11/20、team 13/20，用量完整且总 token 减少 2.5%；但 20 个 team 回合均没有调用 worker_start，没有子运行或提前收尾。未满足新路径贡献证据要求，候选不采用，主区继续保留 r5。原冻结结果、工程回归和全部补丁均留档；具体分遍、格式失败和可解析配对见 [REPORT.md](REPORT.md) 的 r6 部分。
