# Aster 第二版优化：固定二十题完整复测

在本轮模型调用前冻结源码、适配器、任务与测试哈希。二十道题仍各执行一次全新尝试，
不选旧轮最好答案替换。第一版二十题、此前三方原始结果和故障补测均完整保留。
pi 固定为历史 15/20，Codex 固定为历史 14/20。

这二十题已用于调试，结果是开发集复测，不是未见测试集或稳定排名。对任何待解题
模型均不提供旧答案、参考补丁或隐藏断言；独立评分仍在解题结束后注入原始测试。

模型 gpt-5.6-luna / medium，Responses，64000 上下文、8192 输出上限、900 秒/题、
4 CPU / 8 GiB、单 Agent、空会话，两题并发。题面、原始镜像、原始评分器不变。
生产源码保留第一版的临时目录隔离，并增加通用的共享根因修复/直接 API 检查指引。
供应商重试仍最多三次，默认等待改为 5/10 秒，数字 Retry-After 的等待上限为 60 秒，
取消仍立即传播；不在评测控制端额外重试任务。

评测适配沿用第一版的解释器、pytest 源码导入与 gRPC 服务生命周期修正；准备工作区
时先保留原始 Git 跟踪列表，再重建无历史基线，恢复其中被 ignore 命中的文件。
这使测试资源随项目进入 Aster 的执行副本，未扩大敏感文件或未跟踪忽略文件的权限。
Sphinx 的原生 egg 夹具测试必须在正式调用前通过预检。

评测容器各自拥有独立 PID namespace，允许其中进程相互发送信号，并只读开放其
`/proc`，使真正的子进程终止测试和 Valgrind 可执行。宿主生产沙箱仍保留原进程
限制；容器适配要求运行器显式标记与 Docker 环境标记同时存在。每个命令退出后的
进程组清理不变。这是容器评测环境适配，不声称宿主本地模式具有同样权限。

因短暂供应商故障可以暂停提交新题并记录间隔，不延长已启动任务的 900 秒上限。
必要的连接探测单列用量。全部成功、失败、超时及缺失用量保留，独立评分与内部
completed 状态分别报告。生产修正、评测环境修正和供应商波动不能混作单一因果收益。
